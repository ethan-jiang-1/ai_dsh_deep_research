# AGENTS.md — 文档标准（本仓 `docs/` 子树）

本文件拥有 `docs/` 的**文档标准**：层级归属、写作规则、预算处置序与 slop 清单。
它只约束**人读文档**；Agent Note 的格式由 [notes/AGENTS.md](../notes/AGENTS.md) 拥有。
上游对应物 = DSH `docs/AGENTS.md`（`vendor/dsh/docs/AGENTS.md`，机制权威）。

## 层级归属（一个事实一个家）

| 层 | 拥有 | 不放什么 |
|---|---|---|
| 根 [AGENTS.md](../AGENTS.md) | 每轮都要在场的常驻指令（每条 1–3 行，链到 home） | 教程、历史故事、情境化长流程 |
| 子树 `AGENTS.md`（本文件、`scripts/`、`packages/*`、`notes/`、`tests/`、`_backlog`） | 只属于该子树的指令 | 根已承载的仓级规则 |
| `docs/00-index.md`（+ `terms.md` / `decisions.md` / `external-materials.md`） | 文档地图；术语对照、D 号台账与外部材料正文分页（按需查） | 教程正文、决策理由 |
| `docs/design/` | 系统**现在**怎么组成、为什么这样组成（架构/角色/方法论映射/机制依据） | 当前 API 的唯一说明（→ 源码/README） |
| `docs/guides/` | 按任务怎么操作（60 开发环 / 61 run / 62 插件作者） | 设计理由（→ notes/implemented） |
| `docs/discipline-map.md` · [evaluation.md](evaluation.md) | 纪律三态表 · 验收合同与门禁台账 | 变更史 |
| `notes/` | 为什么这样决定、放弃了什么、跑了什么验证 | 当前合同（→ `docs/`） |
| 运行区（`research-workspace/`、`dev/`） | 这次实际发生了什么 | 可复现的回归证据（→ `tests/`） |

高层文档只描述自己的主题与**直接子项**的职责；更低层的细节链接到拥有它的下层文档。

## 写作规则

- **写当前状态，不写变更史**：说"现在是什么"，不说"之前是 / 现在改成 / 不再用"；历史归
  commit 与 notes/。
- **链接只用相对 Markdown 路径**（`md-links` 门禁）且**锚点必须真实存在**（`md-anchors`
  门禁）——不用裸文件名或编号。
- **编号词汇引入前先消歧**：同一前缀被两套词汇使用时，每处使用须能分辨所指，或改前缀根除
  撞车（先例处置 = [D27](decisions.md)：参与阶梯改 S0–S3，与评估五面 L0–L4 前缀分离）；新编号
  词汇进 [terms.md](terms.md) 登记所指。
- **每段只承载一条规则**：一段里塞多条规则或长括号旁白 → 拆开或把细节降到它的 home。
- **强调要省着用**：粗体/大写满篇 = 没有重点；只强调改变行为的那一句。
- **已知限制与延后工作**用固定节名 `## 已知限制与延后工作`（上游
  `## Known Limitations and Deferred Work` 同构）——普通待办留在 TODO 或 Note，不进这里。
- **状态注记（"已实现！/未来：…"）不写进文档**：状态会腐烂，布局与门禁台账承载它。

## 预算与处置序

常驻文档的行数上限由 [scripts/doc-budgets.json](../scripts/doc-budgets.json) 拥有，
门禁 `doc-budgets` 强制（超限或缺登记即红）。红了按序处置：

1. **下放**（把内容移到拥有它的层，原地留一行链接）；
2. **压缩**（留在这里但可以更短）；
3. **升顶**（确实需要空间时改 manifest，并在同一变更登记理由——**上限过低是预算 bug**）。

预算只防常驻入口膨胀；`docs/` 正文档与 guides 是生长面，不设顶。

## slop 清单（写或审任何文档时逐条扫）

- 同一条规则出现在两个 home（grep 一个特征短语，保留一个，其余改链接）；
- 历史叙事：`之前/现在/不再/曾经/改名/移动`、PR 号、commit 号；
- 实现状态注记（"已实现！"、"未来：…"）；
- 手抄的清单/目录（源或生成物才是权威时）；
- 推理过程转述（实现步骤叙事、显然分支的证明、测试走读、被否掉的局部备选）；
- 段落墙（一段多条规则 + 括号旁白）；
- 强调通胀（满篇粗体 = 没有重点）；
- implemented Note 里的规格腔（"应该"、迁移计划、验收清单）——已交付的 Note 只写"是什么"。

**单页自足性终检**（逐条扫完后对整页问一遍；DSH `dsh-trim-cot-leakage` 同构）：一个**只有
HEAD**、拿不到会话记录/PR 讨论/未提交草稿/变更史的读者，能否解析本页的**每一个引用**并
**核实每一条主张**？答不上来即 CoT 泄漏（把"当时的思路/情境"当成文档内容）——处置 = 补足
页内事实或改指 HEAD 内真实载体；**不允许**指向"当时说过的话"。

## 本仓与上游文档标准的差异（登记）

逐条三态登记（物理行未采纳 / 预算行数等价 / 双语与站点投影不适用）= [discipline-map 源 3](discipline-map.md)，此处不复制防漂移。

## 分类与写作顺序（vendor docs/AGENTS.md 吸纳）

每份在范围内的文档先**分类**，再动笔：

- **tutorial**：沿一条有序路径到某个结果，只引入该步需要的东西；
- **reference**：定义一个查询范围与当前行为，不按教学顺序展开。

两类内容分量都大时分开写；某一类很小时在页内标注该节属于哪类。写 tutorial 前先私下判定
读者起点与每个概念的层级（初/中/高），**前置先于依赖概念、难度渐进**，把非必要的进阶材料
移到后续 tutorial 或 reference。

作者顺序固定：**定位文档在树中的位置 → 定它允许的详略 → 选 tutorial/reference →（tutorial）
按前置与难度排序概念 → 把下级拥有的细节下放 → 用链接替换低层解释**。

**配方页的新鲜度契约**：guides/ 里以范本（preset 目录、模板、脚本）为准的清单必须与真实范本
对齐；范本漂移了先回改本页，而不是让清单烂在文档里。
