# _backlog/ · 问题与证据区门牌

> 本目录的子树指令：区的形状与把门规则，一页速览。制度正本 = [README.md](README.md)（有出入以它为准）；
> 两轨卡片格式 = [issues/README.md](issues/README.md) 与 [bugs/README.md](bugs/README.md)；
> 走卡方法 = [methods/](methods/README.md)。

## 想法落哪

| 目录 | 放什么 |
|---|---|
| `issues/` | 值得推敲的问题、任务或特性——卡是判断记录 |
| `bugs/` | 确认暂不修的缺陷——卡是工作项 |
| `research/` | 推敲中攒的证据，服务活跃卡，随卡归档 |
| `methods/` | 走卡的方法（澄清 / 查证 / 验收 / 结论去向） |
| `triggers.md` | 工作中可直接观察到的重议条件索引 |
| `_archived/` | 已结、已修、叫停的卡与随卡研究 |

当场修掉的缺陷不建档（轮次维护行记它，含类扫）；开新卡前先搜已有卡——不重复推敲。

## 入口两张票

缺一不入加工，随格式承载：

1. **问题清楚**——问题、范围、排除项、当前情况，与假设建议分开；
2. **验收手段**——issue 结论倾向「现在做」→ `## 验收标准`；缺陷卡 → `## 修复判据`。

缺陷卡的**修复就绪**翻转（根因有证据 + 修法选定 + 修复判据写就）= 两票合一，也是修复授权（用户裁定
2026-10-12）：P1/P2 修理型修复凭卡自授权；P0 或触及入口链、门禁与验收合同、文档合同、pack 公共行为、
已记录决定的修复不自授权，走 `等人拍板`。

## 状态（frontmatter `status` = 当前阶段唯一家）

- issues：`推敲中 ⟷ 等人拍板 → 已结 | 叫停`
- bugs：`排查中 → 修复就绪 → 修复落地 → 已修`，另有 `等人拍板` 与用户叫停的 `待修`

状态行镜像 frontmatter 并拥有历史；沉默不翻转；每次翻转 = 带守卫的动作 + 记录；退出值只在归档的
同次变更翻转；已结/已修 永不重开（复发 = 引用旧卡的新卡）。翻转表住两轨 README。

## 铁提醒

完成 = 离开活跃区（`git mv`，文件名不改，正文不重写）——位置只表达粗段（活跃/归档），阶段正本 =
frontmatter status；卡是判断记录不是任务，结论去向按 [结论去向](methods/issue-to-note.md)，Note 记决定。
质量责任不随去向转移：业务验收归用户，技术证据归 agent。推敲卡不授予实施权限——唯一范围例外 = 修复就绪缺陷卡的 P1/P2 有界修复。
severity 是通道边界：P0 永不自授权。状态行带 🔒 的触发只有用户能判。
