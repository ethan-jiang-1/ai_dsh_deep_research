## 背景 / 触发

trial run（drt_cn-us-open-source，2026-09-28）中用户提出：rerun 启动后，lead 实际需要与用户敲定补研究细节（补什么/多深/什么预算），现行合同没有这个交互的家。合同缺口三处实证：

- synthesis skill §5 的 HITL2 卡 = 判决最小摘要 + 三选项（定稿/补研究/修订表述），**不带范围问项**；
- rerun-loop-live（implemented Note）全场跑通靠的是**特例路径**——范围恰好写在 v1 final 末节"v2 优先项四条"，lead 只对账不发明；
- 一般情形下 lead 只有两个坏选择：猜范围（跑飞风险）或临场加问（违反"两点之间静默自主"明文合同，且交互无锚点户口——诚实线数不到、question.md §Decisions 无行可落）。

## 已知与未决

已核实：

- HITL2 本身是**循环的**——每个版本交付重过一次（[m2-run-mechanics](../../../notes/implemented/2026-09-24-m2-run-mechanics.md) §109：ReopenResearchPass = 同 bundle 版本演进）；候选后续①（rerun 交付同样过 HITL2 锚进 skill）待做，与本卡相邻。
- 一次多问 + 推荐置首的卡片机制现成（HITL1 三问同卡）——范围轮可直接复用形态。
- HITL2 卡 ≤200 字纪律刚立（[synthesis §5](../../../packages/deep-research-pack/presets/lead/skills/synthesis/SKILL.md)，实测 6 张超长卡最长 1280 字把选项挤出视口）——范围细节塞进决策卡会重新破戒。
- 重入点合同：补研究回挖掘（最深重入点）、修订表述原位改（不回节点）、结构性另起新 bundle（D17）；HITL1 永不重开（rerun-loop-live 记账实证）。
- 用户初步裁决（2026-09-28 会话）：倾向**所有交互集中在 HITL2**——认知依据：HITL2 是用户信息最全的时刻（刚看完交付稿），HITL1 是最不全的时刻；问范围细节问在实料上。
- **2026-09-29 两场 HITL2 试点复盘**（model-ecosystem 与 cn-us-open-source 均定稿；run 通道 web 3081 已死，操作侧按"文件即真相"代驱——结构化卡转呈、用户本人作答）：① **A 形态交互成本实测 ≈ 0**——范围轮试点题（多选 over final §9 缺口清单）两场均被认真作答（3 方向 / 1 方向），零摩擦零"过烦"；② **D 形态 de facto 在场**——用户勾选全部落在 final §9 缺口清单内（两场 final 的 §9 即数据源），只是未合同化；③ **严格门实证未发生**：两场都拍定稿、零 rerun → "lead 补的方向非我所要"无从出现——门要求的恰是 A 会预防的痛（**门悖论如实登记**：等实证 = 等一次本可避免的跑偏）；④ **相邻发现**：cn-us-open-source lead 的 present 从未声明 + HITL2 从未被问（通道死在门前，**G8 双缺席第二实例**，会话日志全库取证）——HITL2 码头对通道死亡脆弱，候选后续①②〔rerun-loop-live〕的相关性因此超出 rerun 场景。

- **何时**：这场 run 交付后就立 RFC，还是再攒一场 run 体感？
- **次序**：与候选后续①（rerun 交付过 HITL2 锚定 skill）谁先——①是不是本卡的前置？（2026-09-29 更新：G8 双缺席第二实例表明 HITL2 码头脆弱性**不限于 rerun**——首交付同样会死在门前；①与本卡同触 synthesis skill §5 邻域，天然同窗做）
- **放弃**：B（真 HITL3 第三颗◆）是否正式记否决（用户意向已反对，待毕业门正式判）。

## 候选与取舍

- **A. HITL2 两轮卡（用户意向）**：决策轮瘦卡（守 ≤200 字）+ **条件范围轮**（lead 按 findings gap 清单 + review 残留 + final 末节优先项拟提案，逐 topic 推荐置首；用户裁决 → 范围锁定）。代价：HITL2 变厚、范围轮卡数需上限；收益：两点合同字面保持、轨道拓扑不动（两◆ + 一回边）、对齐发生在用户信息最全处、随循环制每版本自然重复。
- **B. 真 HITL3（第三颗◆"补研究对齐"）**：范围对齐有独立户口、诚实线可数到；代价：轨道拓扑 +1、用户负担 +1、静默自主进一步收窄。输掉倾向：用户意向反对额外停靠（待毕业门正式判）。
- **C. 计划呈现不拍板**：journal/活动流发补研计划，可打断不强制答。最轻；输掉：用户"敲打"诉求不满足。
- **D. 范围住文件**：final 每版末节必须写"下一版优先项/不充分清单"，HITL2 卡引用之。有实证（rerun-loop-live 零额外交互跑通）；单独用输在"用户批注与文件对账"仍是隐式交互、无裁决点。**A/D 合流 = 当前倾向**：D 降级为范围轮的数据源（lead 提案对着文件拟，不拍脑袋），A 承载交互。

边界（随形态锁定）：critic 审查步内 FAIL→修复循环仍**静默**（质量拦截非方向问题）；HITL2 承载方向与范围的全部交互，这条线不破。

有界风险：方向性跑偏要等 v1 交付才被用户看见——缓解 = HITL1 锁大方向 + v1 报告自带证据缺口节 + 循环 HITL2 每版本可修；v1 永不白做（就是基线版本）。
