# BUG-028：隔离守卫自身异常时静默透传原始 fetch——"隔离下"判读可能名不副实

> 状态：已修（2026-10-15 同日闭环：观察到的失败回落路径由**并行工作流** `a778d17` 修——失败必关 Agent 且原样抛出、绝不回落共享池；初始化失败的 fail-open 由本次改为**逐次可数** → 两条路径均满足"可数且不静默" → 归档）｜发现：2026-10-15（回读 10-13 隔离激活 boot 日志时发现 3 条回退行）｜关联：BUG-024（隔离缓解本体的收卡判据在彼卡，已修归档）

## 症状

`dev/llm-socket-isolation.cjs`（NODE_OPTIONS 预载，LLM 流/web_search 每请求一次性连接）在**自身异常**时走 `catch → 透传原始 fetch` 分支——该请求**未经隔离**（回到全局复用池），而现场只有一行日志：

```
[llm-socket-isolation] 守卫自身异常（透传原始 fetch）: fetch failed
```

10-13 隔离激活那次 boot 的 `runtime/smoke-workspace/web.log` 里有 **3 条**此回退行（该文案在修复后已不存在于代码中）。危害形态：操作侧以为"隔离在场"（BUG-024 的收卡判据与 triggers 处置序都以此为判读前提），而实际有请求在未隔离路径上跑；若回退是系统性的，整个窗口静默裸奔——正好是风暴会咬人的时段。

## 复现

原始痕迹只在 10-13 那次 boot 日志（3 行）；修复后该路径不可达。两条剩余回退路径的验证走**强制故障 harness**（见修复判据），不依赖自然复现。可复核的原始痕迹：`runtime/smoke-workspace/web.log`（该文件被 boot-run 的 tee 覆盖，若已再次启动通道则痕迹消失）与 10-13 的 forensics 目录。

## 根因（已证，两部分）

1. **一次性连接自身失败**（DNS/建连失败）→ 回退。对"本来就会失败"的请求无害，但掩盖失败原因；危害仅限诊断。
2. **守卫初始化/undici 解析在某些进程上异常** → 若走的是这条，则该进程**所有** LLM 流都未隔离（最坏形态）。注意 `undiciOf()` 已有独立的"初始化失败（LLM 请求退回全局池）"文案——本次日志文案不同，故更像 fetch 期而非初始化期，但需证据区分。
3. **上游短抖动下 guard fetch 抛错而 orig fetch 本可成功** → 把可自愈的失败强制变成未隔离请求（放大风险而非降低）。

**定案（两部分）**：

1. **失败回落 = 设计缺陷（已由并行工作流修复）**：`a778d17`（2026-10-16 00:30，ethanmac）实证"长跑暴露：一次性 fetch 抛错时 Agent 未关闭 → 每次失败泄漏一条 socket；失败回落共享池 → 等于双发且可能踩中相位故障（隔离的意义被抵消）"，修法 = 失败**必关 Agent 并原样抛出**（交给 vendor 重试策略，重试再走隔离 = 新连接）。这同时解释了 10-13 那 3 行的成因（候选 1/3 的合流形态）。
2. **初始化失败 = 缓存式静默 fail-open（本次修）**：`undiciOf()` 解析失败时只记一行、并把失败**缓存**为 `false`——此前每次 LLM 请求都直接回落共享池且**再无任何记录**，长跑里整段未隔离不可见。修法 = 该回落**逐次计数并打印**（保留可用性：请求仍发出，但暴露可数）。

## 牵出的失败类

**缓解措施的失效模式不可见**：对外声明"隔离下"是判据前提，静默回退让声明与事实脱钩；同类 = BUG-025/027 族"检查/守卫自身不可靠"。

## 修复判据（满足，证据见下）

**底线 = 回退路径可数且不静默**，逐条：

1. **已观测的失败回落消失**：代码中不再有"守卫自身异常（透传原始 fetch）"路径；强制故障 harness（`127.0.0.1:9` 连接拒绝）实测 **`ORIG-CALLS=0`**——失败被原样抛出，绝不回落共享池 ✓
2. **初始化失败不再静默**：强制故障 harness（`PATH=` 使 `ls`/`head` 不可用）实测三次 DeepSeek POST 各打一行 `⚠ 未隔离请求 #N`，且请求仍发出（`COUNTED-ORIG-CALLS=3`）✓
3. **正常路径零噪音**：不带 `DSH_ISOLATION_ANNOUNCE` 预载普通 node 进程无任何输出 ✓
4. **现场骑行证据**：同日三场隔离探针（163–187 事件、61 次 web_search）全程骑一次性连接、零重试零终局错误（见 [BUG-024](BUG-024-direct-path-malformed-storm-recurrence.md) §收卡证据）✓

**边界**：① 外层 `!issued` 回退仍存在（如 URL/头部构造期异常），但它**每次都有日志**（`预载侧异常（透传全局池）`）= 可数，不再是静默；② 本次改动**在下次 boot 生效**（当时运行的通道进程仍持旧版代码）；③ 修复后未再观测到回退行（无可观测窗口——通道重启后即为新版）。
