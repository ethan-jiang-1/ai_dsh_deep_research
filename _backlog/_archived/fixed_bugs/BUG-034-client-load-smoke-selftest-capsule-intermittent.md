# BUG-034：client-load-smoke「自测例库」块偶发打不开「研究配置」胶囊——8 跑 2 红，无根因证据

> 状态：**已修**（2026-10-18，修法已实现并归档；判据与残留见 §闭环）— 现象与复现率已实测；同条件 8 跑里 2 红、6 绿（其中 2 次红由其他缺陷解释、已排除），
> **根因未定位**（无堆栈、无稳定复现），故不翻「修复就绪」。

## 症状

`client-load-smoke` 尾段「自测例库」块偶发在这一步红：

```
FAIL 自测例库：lib-selftest 新会话上「研究配置」胶囊不可见
```

该步是 `openGuideCapsule(6_000, 6_000, 2_500)` 的超时分支（`scripts/smoke/client-load-smoke.mjs`
自测例库块）——胶囊打不开就整块跳过（12 形态例库列表／详情／编辑／删除那一组断言全不跑），
**不是**面板渲染断言失败：同一次跑里，绑定会话上的「研究配置」胶囊与面板断言全 PASS。

## 观察记录（复现率）

本机同源、同命令（`node --import tsx/esm scripts/smoke/client-load-smoke.mjs --session '补齐证据并复核交付卡'`）
连续 8 跑：**红 2 / 绿 6**。

| 跑 | 结果 | 说明 |
|---|---|---|
| 1 | 红 | 该步红（本次唯一红）——面板为改动前版本，**与研究方法配置改动无关** |
| 2 | 绿 | 自测块全过（该跑另有一处注入式红，属反证操作） |
| 3–4 | 红 | 该步未到（更早的详情弹窗缺陷把后续交互挡死；缺陷已修） |
| 5–6 | 绿 | ALL PASS |
| 7 | 红 | 该步未红，但同跑出现 `FAIL 既有会话在场…dev home 缺该会话——用 --session 指定`（会话选择面） |
| 8 | 红 | 该步红（同跑其余红均为子串变异反证的人为红） |

**共同点**：两次自然红都发生在「既有会话在场」或胶囊打开这类**会话/侧栏态依赖**的步骤上；
绑定会话的配置面板断言不受影响。跑 7 的会话选择失败与跑 1/8 的胶囊失败可能同源（都读侧栏/默认视图态）。

## 已排除

- **不是本轮面板改动的回归**：跑 1 发生在面板重写之前；面板重写后 6 跑全过（含一次完整 ALL PASS）；
- **不是变异注入的副作用**：跑 8 的变异只改文案字符串，不碰胶囊登记（`src/client/index.ts` 未动）；
- **不是端口/进程残留**：同跑收尾 `端口释放验证` 绿、无孤儿进程（脚本自持端口 3109）。

## 影响

冒烟假红 → 该块断言整组静默跳过（"未跑"伪装成"红"），且会污染别的验收判读——这正是
[BUG-033](BUG-033-cockpit-brief-layer-intermittent-missing-delivered-lines.md)
同族的问题（间歇 → 判据不可信）。

## 2026-10-18 复测与口径订正

- **订正一处混杂因子**：原表"跑 7/8"两条红里，跑 7 的会话定位失败（`既有会话在场… dev home 缺该会话`）
  实为**调用侧错配**——我用 `--session '<旧标题>'` 钉住一个已不是"盘侧最新绑定会话"的标题，而绑定扫描按
  "最新绑定"取，两者不一致 → 该断言按设计 return null。与本卡症状**不同因**，已剔除。
- **复测（修 BUG-035 的搜索兜底之后，不传 `--session`，连跑 3 跑）**：自测例库块**三跑全 PASS**
  （列表投影／BUG-025 复现面／编辑预填／混居／空值分区全绿）；本卡症状**三跑零复现**。
  → 复现率口径 = **口径订正后 3 跑 0 红**；原"8 跑 2 红"含 1 条已剔除的错配因，真实率无从估计（样本太小）。
- 同跑另有两处红，均**不同因**、已分流：① 摘要层缺「审查未决项已按上限升级」= 新立
  [BUG-036](BUG-036-cockpit-brief-layer-pending-review-line-missing.md)（BUG-033 同族）；② 库条目详情负例断言
  被新文案「基于此自定义」四字误伤 = 冒烟断言假红（已改按**角色**判按钮，见该 diff）。
- **选定修法已实施（2026-10-18，同 diff）**：自测例库块改为 `openSessionById(page, probe2Id)` **按 id 显式打开**
  （直达 `data-row-key`，行不在 DOM 时走搜索兜底），不再依赖"重载后默认视图＝最新会话"；打不开时
  **如实报红**（`自测例库：本块会话按 id 显式打开（不依赖默认视图）`），不再静默跳过整块。
  待办：该步的注入式反证（把 id 换成不存在的 → 该步必须红）与复跑绿证（下一轮）。
- **原选中修法备忘（未实施前的表述）**：本块现依赖"重载后默认视图 = 最新会话"（代码注释自陈"两轮探针实证"）——
  在会话数量增长后该假设不成立。修法 = 与 BUG-035 同源收敛：**用共享件按会话定位**（`openSessionByTitle`
  / 数据行键）替代默认视图假设，使本块确定性。实施前先按上面的复测口径再量 2–3 跑，确认症状确实
  只与"默认视图没落在目标会话"相关。

## 下一步（定位手段已备，未采）

1. 在 `openGuideCapsule` 失败分支加**诊断快照**（右栏态／`[role="dialog"]` 计数／dock 状态文本），
   下次自然红时一次到位——BUG-033 的排除法路径同款；
2. 核对 `awaitAppReady` 与 `localStorage.clear()` 之后的默认视图判定（本块假设"重载后默认视图 =
   最新会话"，跑 1/7/8 的迹象提示该假设在某些会话序下不成立）；
3. 复现率未上升前不动脚本逻辑（避免用重试掩盖竞态——`scripts/AGENTS.md` §retry 白名单）。

## 闭环（2026-10-18）

  按 id 直达行键（行不在 DOM 时走搜索兜底），打不开如实报红（不再静默跳过整块）；
- **复现率（口径订正后）**：0/4 跑复现（原"8 跑 2 红"含 1 条已剔除的调用侧错配因）；**样本小，如实记账**；
