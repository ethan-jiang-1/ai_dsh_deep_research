# 推敲：rerun 的不满转接——用户说法 ↔ 我们的手段

> 立卡：2026-10-23 ｜ 状态：已结 — 2026-10-23 落地（commit 77ae9fa / d961e33） ｜ 类型：设计 ｜ 结论倾向：现在做（先落词表与 HITL2 措辞，观察面出口随后） ｜ 实施授权：2026-10-23 15:58 用户「开始考虑…落地…静默自主推进」 ｜ 可关闭：是

## 0. 立项来历（用户原话）

2026-10-23 12:00 前后，用户在看到刚跑通的 v1→v2 rerun E2E 截图后提出：

> "就是这样，你设计一下啊，或者挖掘一下，就是我们要用到 rerun 的话，用户可能有哪里不满意的地方，
> 但是他的说法和我们技术落地怎么支持他的这个说法，中间应该有个转接还是干啥的，就是让他的知道
> 我们有什么手段来帮助他。这里我们以前有什么思考吗？有什么交互啊，什么东西的吗。"

三个要点：① 用户会**用生活语言说不满**；② 我们的技术落地只有**自己的三种词**；③ 中间缺一层
**转接**，让用户知道"我们有什么手段、各自代价是什么"。随后用户要求把上下文留足备 REVIEW。

**为什么现在做**：同日刚落地的 [rerun 版本面](./2026-10-23-rerun-versioned-graph.md)
把"有几版 / 交的是哪版 / HITL2 待审"说清了（`plan/vN` 快照、`final/vN` 版本账、`> rerun:` 声明、
图谱版本轨都在）。**版本面是"状态"，本卡补的是"手段"**——同一批文件、同一批用户时刻，现在补
转接层成本最低。

## 1. 问题

用户对一份研究交付不满意时，说的是**人话**：「太浅」「方向不对」「数据过时了」「太长/太绕」
「我不信这个来源」「结论跟我预期反了」。系统回的是**我们的话**：「定稿 / 补研究 / 修订表述」，
结构性重跑甚至不在交付审阅卡上；交付之后也没有任何地方告诉他"还能怎么改、各自要付什么代价"。

按现状会发生什么（推演，不是假想敌）：

- 用户说"太浅" → Lead 可能直接开一轮补研究（对），也可能反问"要不要补研究？"（把分类推回给
  用户），也可能改一遍措辞说"加了两段"（答错题）——三种都可能，**没有合同约束**；
- 用户说"方向不对" → HITL2 卡上没有对应选项，Lead 要么猜范围补研究（白跑），要么想不起
  "另起一个 bundle"，用户也不知道有这个手段；
- 用户三天后说"还是太长" → 没有任何入口提示"表述修订不重跑、版本不变"，用户不知道这一改
  相对重跑是"免费"的。

本卡要建的是中间那层**转接**：用户说法 → 诉求类别 → 可用手段（产出 / 代价 / 什么不变）→
一句可直接说的话。

### 2.1 一次交付之后，现在的完整路径（reviewer 对照用）

1. **HITL2 卡**：Lead 自拟一句判决摘要 + 三选项（定稿 / 补研究 / 修订表述），≤200 字；
2. 选**定稿** → `final/vN.md` + `final.md` + `present`，交付结束；此后没有任何"还能怎么改"的入口；
3. 选**补研究** → 重入挖掘，按 Lead 自拟的范围补证 → `final/v(n+1).md` → 再次 HITL2；
4. 选**修订表述** → 原位改 `final.md`，版本号不变、不回节点（是否再呈卡未写死）；
5. 想**结构性重跑** → 卡上没有；只能用户自己说出"方向不对"，Lead 记起 sibling 预检规则才会提；
6. **交付后隔天想改** → 新开 lead 会话说"继续 `archive/drt_<slug>` 这个 run"（手册路径），
   或直接在原会话说话；两者都没有"我们有哪些手段"的提示。

本卡要动的是第 1、3、6 步的**措辞与出口**；第 2/4 步的文件语义不动。

## 3. 缺口（四条）

1. **用户词没有落点**：七类常见不满没有一条写进任何合同；Lead 只能自由发挥。
2. **有手段没有代价**：补研究再跑一轮抓取、版本 +1；表述修订版本不变；结构性重跑是另一份
   bundle、旧报告原样保留——这三句现在只躺在图例里，没跟"不满"对齐。
3. **出口只在 HITL2 那一刻**：交付后隔天在新会话里想改，只能自己记住路径；观察面没有入口。
4. **最大的不满反而没有选项**：方向错了要走结构性重跑，而 HITL2 卡上只有定稿/补研究/修订表述。

## 4. 提议：一个转接层，三件

### 4.1 L1 分诊词表（单一正本，住 Lead 侧；本卡核心）

| 用户可能怎么说 | 诉求类别 | 手段 | 产出 / 代价 | 什么不变 |
|---|---|---|---|---|
| 太浅 / 只有二手 / 关键数字没有 / 我不信这条 | 证据不足 | **补研究**（同 bundle 证据扩张） | `final/vN+1`，重入挖掘；范围按报告末节，需再跑一轮抓取 | 问题定义、已有证据、旧版本 |
| 方向不对 / 我要的是 X 不是 Y / 范围错了 | 方向变了 | **结构性重跑**（另起 bundle，sibling 预检 + 用户同意） | 新 `drt_<slug>`；成本≈一场新 run，旧报告不改 | 旧报告与其版本账原样保留 |
| 结论跟我知道的不一样 | 反证缺失 / 口径错 | 先定位"哪条结论 vs 哪条证据"（critic 升级或定向反例），再决定是否补研究 | 可能只补一条证据，不重写全篇 | 其余结论 |
| 数据过时了 / 时间口径要改 | 时效 | **补研究**（时效刷新）+ 口径行更新 | `vN+1` | 结构 |
| 太长 / 太绕 / 要一页纸 / 要表 | 表达形态 | **表述修订**（原位改） | `final.md` 改，版本不变 | 证据与结论 |
| 来源不合规 / 只要官方 | 来源约束 | 运行中 = **steer**；已交付 = **结构性重跑**（约束变了） | 视时点 | — |
| 过程我不放心 / 为什么停在这 | 不是 rerun | 走状态页 / §Decisions / 审计，不重跑 | — | 全部 |

**纪律（写进同一 skill，作为 Lead 的对话程序）**

1. **先复述再分类**：用一句人话回述"我听到的是证据不够，不是方向错"，让用户能当场纠正；
2. **至多两个手段 + 一句"这个不用重跑"**：超过两个选择等于让用户自己做分类；
3. **范围只从报告来**：补研究补哪块，引报告末节与缺口清单（范围轮卡洞见），不现场发明；
4. **不动手**：分诊只给方案，用户点头才落（D17 三形态照旧）；
5. **不自动分类**：不做关键词/正则路由；分类住模型，机械面只保证三种手段的后果与版本记账可见。

### 4.2 L2 交付卡与报告末节（模型可见文本）

- **HITL2 三选项**改写成"用户语言 + 后果"（草案，待审）：
  - `补研究（补哪块看报告末节；会出新版本 v2）`
  - `改说法（只改措辞，版本不变）`
  - `定稿`
  题干补一句"不满意属于哪类？可以直接说：太浅 / 方向不对 / 太长"（**不新增问题**，只给词）。
- **`final.md` 末节强制「下一版优先项 + 什么会改变建议」**（当前六段没有；rerun-loop-live 的
  §9 是自发生成，不是合同）。它同时是 4.1 里"补研究"的范围数据源，也是用户与 Lead 之间唯一
  共享的词汇表。quick_factual 缩略为一行"若要加深，可补哪一处"。

### 4.3 L3 交付后出口（只读观察面）

状态页 ⑤（版本面旁）与终稿页脚各一个折叠块「还不满意？三种改法」：三行用户语言 + 后果 +
**可复制的一句话**（如"这份太浅，按报告末节的第 1 条补一轮，出新版本"）。观察面仍只读——
不按钮化 rerun（cockpit-flow-face 已否决），只给话术。

## 6. 输掉的方案

- **观察面加 rerun 按钮**：D18 只读；rerun 是发起人向 Lead 的对话动作（flow-face 已否决）。
- **自然语言分类器 / 关键词路由**：抱怨说法长尾，机械分类必然误判；分诊住模型。
- **新 HITL3 或 HITL2 加"不满类型"第一问**：+1 停靠、破 ≤200 字与"一次问全"；先用 4.2 的
  措辞观察真实体感，再议（§9 未决 2）。
- **把结构性重跑塞进 HITL2 第四个选项**：四项 + 每项后果会超字数并冲淡"审阅报告"这个时刻；
  建议由 Lead 在用户说"方向不对"时提出（§9 未决 3）。
- **把"补研究"做成图谱按钮**：同上。
- **重开 HITL1**：方向变化走结构性重跑，不重开立项。
- **另建"不满意工单"或第二套状态**：报告末节 + §Decisions 已是事实源。
