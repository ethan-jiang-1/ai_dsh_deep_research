# 实施：让研究报告首屏支持业务决策与证据核查

> 立卡：2026-10-11 ｜ 状态：已结（2026-10-11）｜ 类型：Feature ｜ 可关闭：是

**关闭结论（2026-10-11）**：实现已落（`3269d4c`）；真实 run 交付版首屏六段核验通过（`drt_deepseek-default-upgrade`，含「前提被改写」的诚实修正样例）；三道机械门对真实 bundle exit 0（`evidence-audit` CRITICAL 0 / MAJOR 0、`node-gate` 全门 PASS、`schema-scan` 全齐）；人工判据通过——业务读者 2026-10-11 走查 [四组样例与四类反例](../../../research-workspace/drafts/2026-10-11-decision-report-samples.md)，**整表确认通过**。**口径更正随卡**：「首屏与正文、findings/review 不矛盾」已按用户拍板**降格为人工判据**（门R/门A 仅作代理信号），原「确定性」主张撤回。**随卡结转**：走查的具体卡住点如需补记，回填上述样例集的三张记录表。

**问题与期望结果：** 当前报告模板有 TL;DR、主体、反例、缺口和来源清单，但没有明确要求把结论与业务选择、适用条件和行动联系起来。交付一套决策摘要报告模板及生成/审查规则，让读者先读懂答案和边界，再沿关键依据核查证据。

**交付物：** 更新当前版报告模板、Lead 生成报告的 skill 和 Critic 审查要求，以及部署种子镜像；提供覆盖快速事实、市场比较、断言核验、趋势预测的四组脱敏或虚构样例及验收记录。样例仅用于检验表达与证据导航，不作为真实业务结论。

**研究依据：** [高管研究 UX 调研](../../_archived/research/2026-10-11-executive-research-ux/index.md) 的报告首屏建议与证据核查要求。用户研究效果仍为假设；技术通过不能宣称已提高决策质量。

## 要做的东西

1. 在 [报告模板](../../../research-workspace/templates/run/final.md) 的首屏给出：答案/建议及适用条件、备选与取舍、关键依据、最强反证、目前不能判断的事项、下一步。快速事实题可缩成答案、口径、依据和限制，不强行填满业务选项表。
2. 建议必须有证据和条件。没有充分依据时明确“目前不能判断”，探索题可以提供选择框架，不能被格式逼成唯一推荐。期限、负责人、预算等未获用户指定时标“待定/未知”，不能编造。
3. 关键依据直接链接到对应 evidence 文件及其摘录/解读，读者可继续打开原始 source_url；保留主体、反例、缺口与完整来源清单。抓取日期与来源发布日期分别表达；单源、争议和过时口径不能被简短摘要抹掉。
4. 更新 Lead 实际负责综合/报告生成的 skill 与 Critic 实际负责 adversarial-review 的 skill：开工时定位现有 owner，不另造平行生成或审查流程。Critic 核查首屏建议是否被证据支撑、是否遗漏改变建议的反证、是否把未知写成确定。
5. 同步必要手册与 pack workspace 种子。保持 run 根 final.md 唯一当前版权威、present 交付、HITL2 选项、证据扩张版本与表述修订语义。

## 实施顺序与依赖

三卡次序 = ①立项简报 `2026-10-11-executive-research-intake-brief.md` → ②本卡 → ③驾驶舱 `2026-10-11-executive-research-ux-delivery.md`。本卡实施内序：先改模板和生成/审查规则，再制作四组样例检查首屏与详情一致性，最后做真实组合冒烟。立项简报未落地不阻塞本卡：仍从现有 question.md 取已知目标，缺失字段明确未知，不要求回填历史 run；①落地后报告的建议段锚定其业务字段。

### 在办行（2026-10-11 按 `methods/validation-design` 补全字段）

> 上表保留为可读判据；下列行是**紧接着要执行的面**，每行字段 = 行为 · 类 · 输入/状态 · 判定与失败信号 · 负例/互补 · 证据 owner（能证什么 / **不能证什么**） · 人工判据。

**②-a 四组样例 + 四类反例首屏走查（人工判据批次）**
- 行为：业务读者读四组样例（快速事实/市场比较/断言核验/趋势预测）首屏，能直接说出答案、边界与「目前不能判断」；读四类反例（单源/冲突口径/缺成本输入/过时资料）首屏，能看到限制被显性说明。
- 类：模型行为 + 人工判据。
- 输入/状态：材料齐备于 `research-workspace/drafts/2026-10-11-decision-report-samples.md`（四组 + 三处刻意植入缺陷，该文件自述 human judgment pending）；互补态 = 快速事实样例**不被格式逼成商业建议**。
- 判定与失败信号：逐份记录「判断与卡住点」；**失败信号 = 预测样例把假设写成事实、或反例的限制未被显性说明**。
- 负例/互补：三处刻意植入缺陷（含无依据建议）必须被读者指出——指不出即负例命中。
- 证据 owner：人工走查记录（**不能证**：真实 run 的首屏行为——那已由 `drt_deepseek-default-upgrade` 交付版核验覆盖，见下「真实 run 交付核验」段）。
- 人工判据：**是**——唯一 owner 是业务读者（你）。

**②-b 「首屏与正文、findings/review 不矛盾」判据修正（现为代理充数）**
- 行为：首屏结论与正文/审查结论不矛盾，且**改变建议的反证**没有被首屏抹掉。
- 类：模型行为 + 人工判据（**原表此行标「确定性」，是与实际 owner 不符的假牙**）。
- 输入/状态：现状 = 无直接断言，`node-gate`/`schema-scan` 源码零「首屏/决策摘要」字样，**仅由门R（标题重复）与门A（交付完整性）代理**（2026-10-11 实测）。
- 判定与失败信号：修正后 = 人工读交付稿首屏与 §最强反证/§目前不能判断 是否互斥；**失败信号 = 首屏给了推荐而正文列出推翻它的反证，或反证段缺席**。
- 负例/互补：反向核验已有实证——`drt_deepseek-default-upgrade` 交付版首屏把「决策前提被改写」列为第一条残留风险，属正例；负例需人工构造（首屏删掉反证引用）。
- 证据 owner：门R/门A 只作**代理信号**（能证：标题不重复、交付件齐；**不能证**：语义不矛盾）；语义判据归人工。
- 人工判据：**是**（与 ②-a 同批）。**已定（2026-10-11 用户拍板）= 降格为人工判据**：不给「不矛盾」造机械断言，原表该行不再以「确定性」呈现，门R/门A 只作代理信号（能证形式面、不证语义）。
