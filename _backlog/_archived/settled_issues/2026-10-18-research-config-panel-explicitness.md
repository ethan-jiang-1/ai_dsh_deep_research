> 「本次研究」区要读 question.md 的**研究方法节**——这是本卡新增的一个工作区文件读面（现在只读 `method-library.md`）。三态文案必须区分：**无 run**（本会话还没研究，给入口）／**文件缺**（bundle 在但 question.md 不在）／**未记录**（有 question.md 但方法节空——旧 run 的合法形态，不回填）。
>
> **机制指认（三轮复核补——复用现成通道，不新造发现机制）**：面板现注入面只有 `readFile`/`sendInstruction`，不知道 run bundle 在哪。「本次研究」区的定位 = 研究状态页签同款——`index.ts` 装配面已有的 `follow` 闭包注入 ＋ `src/lib/bundle-bind.ts` 的 `sessionBindingOf`（journal 工具调用路径识别 `drt_<slug>/`）＋ 三位置查找（根／archive／_abandoned）；三态判定折算进 `src/lib/` 纯函数（keyless 单测）。**读限教训（BUG-026 同族）**：question.md 的研究方法节在模板第 32–40 行——`readFile` 默认 limit 40 恰好卡在边界，question.md 实际还有更后的 §Decisions；读方法节须显式传足额 limit，勿吃默认值静默截断。
>
> **回执三态的信号源**：「已发送」= `session/prompt` 返回 ok；「Lead 已回话」= follow 流里发送之后出现的 assistant 事件（只订阅自己发的那条指令，≠ 列表实时化，见 §方案与取舍 边界注）；「已落盘」= 回读 `method-library.md` 对账 diff（改了哪一句从两侧文本折算，纯函数）。
>
> **按钮在位 ≠ 功能可用**：本卡只保证两个入口按钮在场（含空态与失败态），功能可用性由子卡② 的 ②-3 负责。

## 方案与取舍

卡内特有的备选（跨卡共用的"输掉的方案"住[总卡](2026-10-18-research-method-config-ux.md) §方案与取舍）：

- **「本次研究」区只读展示、不给一键换**：否——用户的第一诉求就是"这次用的是哪条、能不能换"；只读会把问题推回对话；
- **无 run 时不给入口、只显示空态**：否——会与 R8 的"选保留在无 run 时"冲突（本卡初稿即如此，已在 §交付物规格 修正）；
- **回执只加"Lead 已回话"一态、不做落盘对账**：否——"生效没有"的唯一证据是回读对账，成本只是多读一次文件；
- **把「刷新」改成 follow 流实时**：缓——成本明显更大；先保留手动刷新 + 发送成功后自动重载，等"反复手点刷新"成为可观察痛点再升级（发现 12 只记现象，不预设解法）。**边界注（三轮复核）**：缓的是**列表**实时化；回执三态的事件订阅（§交付物规格 信号源）不在此列——它只盯自己发出的那条指令，不做整面板 follow 化；
- **详情页内联编辑直接改库文件**：否——越 D25 边界（总卡 §方案与取舍 已记）。
