> 问题：`_backlog/research` 作为「多方向研究」的货架是否合格——一题一目录、题名页、材料点名、结论转卡、归档与留痕；当前门禁查了什么、没查什么。
> 消费者：本轮研究自身的组织（用户 2026-11-10 直派）。
> 产出的卡：—（元方向：结论直接改本目录与索引，不转卡；见 [shelf-criteria §7](2026-11-10-shelf-criteria.md) 「应用，不转卡」）
> 结论：现行结构（一题一目录 + 题名页 + 材料点名 + 归档）够用，不缺门禁；真问题是「结论如何被消费」无判据——补 `产出的卡：—` 必带理由的人工核对即可，v1 **不落新门**（不加语义门禁、不要求材料被引用、不要求结论必须转卡）。一方向一 fresh context 的共享底座协议已应用，冷读通过。
> 归档：2026-11-10（元方向，结论已落在本目录与索引；无下游卡）

## 研究问题

1. 一个研究方向独立成题的判据是什么（问题、消费者、产出卡、材料）？什么该合并、什么该拆？
2. 题名页与材料的分工：哪些内容进题名页（名头 / 边界 / 索引），哪些进材料（证据 / 推演 / 结论）？
3. 结论如何不烂在 research 里：什么算「已定性」、什么必须转 issue / note、什么只进 commit？
4. 材料性判据（借 company 的 materiality）：哪些研究结论必须留 Note，哪些 commit 即可？
5. 当前门禁（`backlog-liveness`）只查结构；缺的「材料被引用 / 结论被消费」的证据该怎么补，还是不该补？
6. 本仓现状评估：六个方向开出来后，索引、题名页、材料三层是否可导航；哪些是过度工程。

## 边界

- 不把「研究货架」做成第二套 docs 体系。
