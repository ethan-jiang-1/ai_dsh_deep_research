# 实施：让研究报告首屏支持业务决策与证据核查

> 立卡：2026-10-11 ｜ 状态：推敲中 ｜ 类型：Feature ｜ 可关闭：否

**问题与期望结果：** 当前报告模板有 TL;DR、主体、反例、缺口和来源清单，但没有明确要求把结论与业务选择、适用条件和行动联系起来。交付一套决策摘要报告模板及生成/审查规则，让读者先读懂答案和边界，再沿关键依据核查证据。

**交付物：** 更新当前版报告模板、Lead 生成报告的 skill 和 Critic 审查要求，以及部署种子镜像；提供覆盖快速事实、市场比较、断言核验、趋势预测的四组脱敏或虚构样例及验收记录。样例仅用于检验表达与证据导航，不作为真实业务结论。

**研究依据：** [高管研究 UX 调研](../research/2026-10-11-executive-research-ux/index.md) 的报告首屏建议与证据核查要求。用户研究效果仍为假设；技术通过不能宣称已提高决策质量。

## 要做的东西

1. 在 [报告模板](../../research-workspace/templates/run/final.md) 的首屏给出：答案/建议及适用条件、备选与取舍、关键依据、最强反证、目前不能判断的事项、下一步。快速事实题可缩成答案、口径、依据和限制，不强行填满业务选项表。
2. 建议必须有证据和条件。没有充分依据时明确“目前不能判断”，探索题可以提供选择框架，不能被格式逼成唯一推荐。期限、负责人、预算等未获用户指定时标“待定/未知”，不能编造。
3. 关键依据直接链接到对应 evidence 文件及其摘录/解读，读者可继续打开原始 source_url；保留主体、反例、缺口与完整来源清单。抓取日期与来源发布日期分别表达；单源、争议和过时口径不能被简短摘要抹掉。
4. 更新 Lead 实际负责综合/报告生成的 skill 与 Critic 实际负责 adversarial-review 的 skill：开工时定位现有 owner，不另造平行生成或审查流程。Critic 核查首屏建议是否被证据支撑、是否遗漏改变建议的反证、是否把未知写成确定。
5. 同步必要手册与 pack workspace 种子。保持 run 根 final.md 唯一当前版权威、present 交付、HITL2 选项、证据扩张版本与表述修订语义。

## 实施顺序与依赖

三卡次序 = ①立项简报 `2026-10-11-executive-research-intake-brief.md` → ②本卡 → ③驾驶舱 `2026-10-11-executive-research-ux-delivery.md`。本卡实施内序：先改模板和生成/审查规则，再制作四组样例检查首屏与详情一致性，最后做真实组合冒烟。立项简报未落地不阻塞本卡：仍从现有 question.md 取已知目标，缺失字段明确未知，不要求回填历史 run；①落地后报告的建议段锚定其业务字段。

## 验收标准

| 判据 | 行为类 | 检查方式与证据 owner | 负例 / 互补 |
|---|---|---|---|
| 模板首屏结构：建议与适用条件 / 备选取舍 / 关键依据 / 最强反证 / 不能判断的事项 / 下一步；快速事实缩略为答案+口径+依据+限制 | 确定性 | tests/ 契约测试断言模板节名在场（先红后绿）；`pack-workspace-fresh` 对账镜像 | 删任一节测试变红；快速事实样例不被格式逼成商业建议（互补态） |
| 四组样例（快速事实 / 市场比较 / 断言核验 / 趋势预测）首屏直接回答题目，证据不足允许不给推荐 | 模型行为 + 人工判据 | 人工走查样例集，逐份记录判断与卡住点 | 预测样例把假设写成事实 = 负例命中 |
| 任一首屏主张沿链接可到真实 evidence 摘录与原始来源 | 确定性 | `evidence-audit` 对合成夹具语料对账（须先 source dev/env.sh） | 植入伪造链接 / 无依据建议 → audit CRITICAL（红证） |
| 四种反例（单源 / 冲突口径 / 缺成本输入 / 过时资料）首屏显性说明限制 | 模型行为 + 人工判据 | 人工走查反例样例；critic/lead skill 合同行进契约测试 | Critic 放行刻意植入的无依据建议 = 负例命中 |
| 首屏与正文、findings/review 不矛盾；无未修复 CRITICAL 才进入交付 | 确定性 | `node-gate` + `schema-scan` 对合成 bundle 现行断言保持绿 | — |

必跑面（任务型路由）：L0 + `render-overlay` 先于 L1（skill 文本）+ `pack-workspace-fresh`（模板）+ `tests/evaluation-contract.test.mjs`（证据合同面）。真实报告行为证据按授权走 L4-lite 或真实 run，无凭据时如实标注「未运行项」；人工判据单独记录，不用技术绿或样本百分比替代产品判断。

## 关闭条件

报告模板与生成/审查要求已实现，四组样例和反例有验证记录，组合冒烟及文档对账通过。不得以样例写得流畅或机械结构通过代替证据支撑检查。
