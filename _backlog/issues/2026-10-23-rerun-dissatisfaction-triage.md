# 推敲：rerun 的不满转接——用户说法 ↔ 我们的手段

> 立卡：2026-10-23 ｜ 状态：推敲中 ｜ 类型：设计 ｜ 结论倾向：现在做（先落词表与 HITL2 措辞，观察面出口随后） ｜ 可关闭：否

## 1. 问题

用户对一份研究交付不满意时，说的是**人话**：「太浅」「方向不对」「数据过时了」「太长/太绕」「我不信这个来源」「结论跟我预期反了」。系统回的是**我们的话**：「定稿 / 补研究 / 修订表述」，结构性重跑甚至不在交付审阅卡上；交付之后也没有任何地方告诉他"还能怎么改、各自要付什么代价"。

结果：用户知道自己不满意，但不知道我们**有什么手段**能帮到他，只能把不满写成一句模糊指令，由 Lead 猜；猜错就白跑一轮，猜对了用户也不知道本该有更便宜的选项（只改措辞却被重跑了一轮）。

本卡要建的是中间那层**转接**：用户说法 → 诉求类别 → 可用手段（产出 / 代价 / 什么不变）→ 一句可直接说的话。

## 3. 缺口（四条）

1. **用户词没有落点**：七类常见不满没有一条写进任何合同；Lead 只能自由发挥。
2. **有手段没有代价**：「补研究」要再跑一轮抓取、版本 +1；「表述修订」版本不变；「结构性重跑」是另一份 bundle、旧报告原样保留——这三句现在只躺在图例里，没跟用户的"不满"对齐。
3. **出口只在 HITL2 那一刻**：交付后隔天在新会话里想改，只能自己记住"继续说 archive/drt_x"；观察面没有任何"还能怎么改"的入口。
4. **最大的不满反而没有选项**：方向错了要走结构性重跑，而 HITL2 卡上只有定稿/补研究/修订表述。

## 4. 提议：一个转接层，三件

### 4.1 L1 分诊词表（单一正本，住 Lead 侧）

| 用户可能怎么说 | 诉求类别 | 手段 | 产出 / 代价 | 什么不变 |
|---|---|---|---|---|
| 太浅 / 只有二手 / 关键数字没有 / 我不信这条 | 证据不足 | **补研究**（同 bundle 证据扩张） | `final/vN+1`，重入挖掘，范围按报告末节 | 问题定义、已有证据、旧版本 |
| 方向不对 / 我要的是 X 不是 Y / 范围错了 | 方向变了 | **结构性重跑**（另起 bundle，sibling 预检 + 用户同意） | 新 `drt_<slug>`，旧 bundle 原样保留 | 旧报告与其版本账 |
| 结论跟我知道的不一样 | 反证缺失 / 口径错 | 先定位"哪条结论 vs 哪条证据"（critic 升级或定向反例），再决定是否补研究 | 可能只补一条证据，不重写全篇 | 其余结论 |
| 数据过时了 / 时间口径要改 | 时效 | **补研究**（时效刷新）+ 口径行更新 | `vN+1` | 结构 |
| 太长 / 太绕 / 要一页纸 / 要表 | 表达形态 | **表述修订**（原位改） | `final.md` 改，版本不变 | 证据与结论 |
| 来源不合规 / 只要官方 | 来源约束 | 运行中 = **steer**；已交付 = **结构性重跑**（约束变了） | 视时点 | — |
| 过程我不放心 / 为什么停在这 | 不是 rerun | 走状态页 / §Decisions / 审计，不重跑 | — | 全部 |

纪律：先复述不满再给**至多两个**手段 + 一句"这个不需要重跑"的判断；补研究的范围只从报告末节与缺口清单取，不许 Lead 发明（范围轮卡洞见）。不说话术自动分类——分诊在模型侧，机械面只保证三种手段的后果与版本记账可见。

### 4.2 L2 交付卡与报告末节（模型可见文本）

- HITL2 三选项改写成"用户语言 + 后果"：`补研究（补哪块看报告末节；会出新版本 v2）` / `改说法（只改措辞，版本不变）` / `定稿`；卡上补一句"不满意属于哪类？可以直接说：太浅 / 方向不对 / 太长"。
- `final.md` 末节强制「下一版优先项 + 什么会改变建议」（当前六段没有；rerun-loop-live 的 §9 是自发生成，不是合同）。它同时是 4.1 里"补研究"的范围数据源。

### 4.3 L3 交付后出口（只读观察面）

状态页 ⑤（版本面旁）与终稿页脚各一个折叠块「还不满意？三种改法」：三行用户语言 + 后果 + **可复制的一句话**（粘回对话即发）。观察面仍只读——不按钮化 rerun（flow-face 已否决），只给话术。

## 5. 输掉的方案

- **观察面加 rerun 按钮**：D18 观察面只读；rerun 是发起人向 Lead 的对话动作（cockpit-flow-face 已否决）。
- **自然语言分类器 / 关键词路由**：抱怨说法长尾，机械分类必然误判；分诊住模型，机械面只保证后果与版本记账。
- **新 HITL3 或 HITL2 加"不满类型"第一问**：+1 停靠、破 ≤200 字与"一次问全"；先用 4.2 的措辞，观察真实体感再议。
- **把"补研究"做成图谱按钮**：同上，观察面不发指令。
- **重开 HITL1**：方向变化走结构性重跑，不重开立项（rerun-loop-live 记账）。
- **另建"不满意工单"或第二套状态**：报告末节 + §Decisions 已是事实源。

## 6. 验收标准

- 4.1 词表落成单一正本（Lead skill），七类说法各有落点、每行有产出/代价/不变项；
- HITL2 选项带后果，`final.md` 模板含「下一版优先项 + 什么会改变建议」，synthesis 判据引用；
- 状态页/终稿页折叠块渲染三种改法与可复制话术（client-load 断言）；
- 真模型探针：给一句"太浅"，Lead 能复述 + 给至多两案 + 说清代价与不重跑的选项，且**不擅自 rerun**；
- 不新增交互点、不在观察面加动作按钮、不改 D17 三形态。

## 7. 边界

- 不改 HITL1/HITL2 两个停靠点合同；不加第三颗 ◆；
- 不自动 rerun、不自动分类、不迁移旧 bundle；
- 报告末节是"下一版的候选"，不是承诺；写不进就标"未取得"。
