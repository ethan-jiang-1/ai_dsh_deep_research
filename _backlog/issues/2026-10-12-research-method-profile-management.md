# 推敲：研究方法配置——长期管理、默认与复用

> 立卡：2026-10-12 ｜ 状态：等人拍板 ｜ 类型：Feature ｜ 结论倾向：现在做（对话式保存已实施）；Settings 图形化管理 = 未定待裁定 ｜ 可关闭：否

**问题与期望结果：** 用户可能希望把当次调整保存为可复用方法、设定以后研究的默认，并能明确区分“改本次”和“改长期配置”。本卡判断长期管理是否纳入首版、应放哪里及作用于哪些研究；保存不能让旧 run 追随新配置变化。
**当前情况：** 用户明确要求深入推敲 UI 与管理体验，但尚未选择长期保存范围或 Settings 方案。[总卡](2026-10-12-research-preference-templates.md) 拥有总体意图和语义；[单次卡](2026-10-12-research-method-run-lifecycle.md) 拥有当次快照与执行。当前 pack 无方法管理库，代码例外限观察/调试，DSH Settings 能力见 [研究依据](../research/2026-10-12-research-preferences.md#dsh-可借用能力及限制)。
**未决问题：** 首版只做当次覆写还是包含保存/管理；工作区级或 DSH profile 级；配置式路径还是 Settings 页；默认与推荐谁优先；内置更新、自定义编辑、删除和失败怎样处理。
**下一步：** 比较三个完整用户任务——首次选用、当次微调后显式保存、以后开跑/旧 run 恢复；核对各方案的读取/写入 owner、D7/D18 代价与部署形态，再提交范围选择。必要实验按 [总卡授权边界](2026-10-12-research-preference-templates.md#已确认意图与授权) 隔离开展，正式实施前先提交详细方案供用户 review；本卡不是 CRUD 实施任务。

## 范围与依赖

本卡拥有长期定义的作用域、编辑/保存/复用语义、未来默认、管理入口、持久化与升级/删除影响。方法内容与可编辑字段依总卡；接入新 run 与旧 run 不受库变化影响依单次卡的快照边界。UX/技术候选查证可并行，不要求先实现运行功能。

当次选择与 HITL1 由单次卡拥有，本卡仅规定保存定义如何成为下一次的候选输入。Cockpit 不承担长期编辑或配置库正本。管理方案如延后，不阻断内置预设 + 本次覆写的单次闭环。

## 已知事实与待证能力

- [D7/D18](../../docs/00-index.md) 仅给观察/调试自写代码例外，host 半目前是空壳；完整 Settings 页或保存业务需要评估是否重议该边界，不自动复用例外。
- DSH settings〔V1〕 持久化在 active profile patch，表单只暴露活动、唯一可寻址 entry 的 volatile 字段；reset 恢复继承值，陈旧写入被拒。声明 Config 不会自动生成一张已可用的管理页。
- ui-settings〔V2〕 提供页面/行扩展与共享配置表单读取/写入；非 loopback Web 的持久设置受限。不能据此宣称远程、跨设备、账户级配置已可用。
- workspace instructions〔V3〕 发现文件，不等于自动知道用户预设库。模型可见约束〔V4〕 要求送达模型的内容可从日志复原；“Settings 保存成功”不等于“Lead 已读取”。
- [状态模型](../../docs/design/50-agent-loop-and-state.md) 要求旧 run 从 bundle 恢复；长期定义只是新 run 的初始值，不能成为执行期间或恢复时的新正本。

需要查证的不是“DSH 能不能画页”，而是采用路径能否同时完成持久保存、读取送达、作用域隔离、升级保护和部署；本轮不假定存在 method Service、slash command、保存工具或自动注入机制。

## 方案与取舍

| 候选 | 用户结果 | 收益 | 成本/未决 |
|---|---|---|---|
| 首版仅内置 + 本次覆写 | 用户每次选用并调整，旧 run 可回看；不长期保存 | 最薄，优先验证方法效用和低负担选择 | 经常重复输入的成本；需用户决定是否接受首版缺少复用 |
| 工作区独立用户预设库，配置式管理 | 同工作区的新 run 显式读取可复用定义，可通过对话/文件保存 | 与文件方法较接近，易携带 | 位置/格式/权限/显式读取、写入失败与 seed/scaffold 升级保护均需设计；不是放进只读 harness |
| DSH Settings 管理与持久化 | 独立管理页/行，未来默认和显式保存 | 入口一致，可借用已有修订写入与 schema 能力 | 新配置 owner、模型送达、代码边界、profile 范围、部署和浏览器失败处理；需判断 D7/D18 是否扩边 |

建议先确保单次闭环，再按重复保存需求裁定管理范围；这是建议，不是已经选轻量首版。若首版必须长期保存，则选择一个权威库，不做 profile patch 与工作区文件的双向同步。

## 需要走读的用户任务

1. **首次研究**：用户不先进入 Settings 即可得到方法候选和解释。若有长期默认，明确它只是起点；题面已指定的方法/约束不能被默认覆盖。问题不适合默认时如何推荐，应回到当次 HITL1，不能偷偷换方法。
2. **临时调整**：用户改本次来源/核验/呈现要求，只影响这次。取消编辑不修改 run 或库。是否提供“另存为”及入口位置待定，但长期保存必须是显式动作。
3. **保存与下次复用**：成功时能辨认保存的名称与范围，新 run 实际读取保存内容；失败/冲突时保留草稿并显示尚未保存，不能界面先显示成功再丢数据。
4. **编辑与升级**：内置查看、复制/另存、自定义编辑和 reset 应说明改哪层；建议不直接修改包内置文件。库变化只影响以后实例化的 run，已有快照不被重写。未选长期路径前不设计复杂版本历史。
5. **删除与默认失效**：删除被默认引用的方法时，不允许默默以其他方法继续冒充原默认；是在删除时要求选替代，还是新 run 说明默认不可用，要按所选路径裁定。旧 run 仍可恢复。
6. **不同作用域**：同时有多个工作区/profile 或已归档 run 时，UI 显示作用范围，读取不会串用。跨设备迁移、共享、导入导出另行决定，不把“我的预设”误称账户同步。

## 待裁定的精确问题

| 问题 | Agent 可先做的事 | 需要用户判断 |
|---|---|---|
| 首版必须长期保存吗 | 比较三条完整任务流与实现/维护成本 | 是否接受暂时每次覆写，以及首版价值取舍 |
| 默认服务哪类研究 | 比较同工作区、多项目/同 profile 使用场景 | profile 级或工作区级控制更符合使用习惯 |
| 管理入口与范围 | 读 pinned Settings/配置/部署能力，出低负担文案 | Settings 管理或配置式管理的可用性与投入 |
| 内置与用户编辑 | 设计查看/当次覆写/另存和升级负例 | 是否需要首版复制/重命名/删除/默认等具体操作 |
| 代码边界 | 列出选中路径的消费方、发布集与最小改动 | 若需扩 D7/D18，是否接受该有界演进 |

事实自主查证，未获判断时只暂停依赖它的定案；本轮不发散成一轮问所有细节。首版范围建议在单次用户路径示例清楚后裁定。

## 验收标准

当前本卡为候选评估，不预造未选方案的实现矩阵。推敲材料应可验证：

- 三条候选按相同用户任务比较，注明权威库、writer/reader、作用域、运行前解析、升级与部署代价；不只比较界面外观。
- 所选范围与默认语义不依赖聊天恢复，模型可见输入有明确日志/文件送达路径；工作区库或 Settings 是否真的被 Lead 读取是待证事实，不能用保存成功代替。
- 明确哪些是必要操作、哪些延后；若结论为延后或不做，记录理由及可观察重议条件。若定“现在做”，在本卡补齐如下负载行为的正式验收，再形成交接。

所选方案需覆盖的观察点（当前不是已承诺全部操作）：

| 行为与类别 | 输入与正/负结果 | 证据 owner 和限制 | 人判断 |
|---|---|---|---|
| 临时与长期修改分开（确定性/编排） | 只改本次、取消、显式保存：只有保存成功才改变库；原预设/旧快照不被临时操作污染 | 所选写入接口行为断言 + UI/文件独立读取；库路径定后绑定具体检查 | 入口与文案 |
| 下次读取与范围（编排/模型） | 新 Lead/新 run 读取保存内容；另一作用域无该设置；题面指定要求仍优先 | 真实组合 session + 新 run 实际内容；keyless 保存回放不能证模型使用 | 默认适用性 |
| 保存冲突/不可写（确定性/编排） | 陈旧 revision/权限拒绝/断连：草稿不丢、不虚报成功，可按明确流程重试 | 若 Settings 选中，依已有 revisioned mutation；若文件路径选中，按其失败机制设计，不能硬套 API | 恢复体验 |
| 内置升级与库删除（确定性） | 内置升级不改用户定义；默认引用不可用有解释；旧 run 内容保留 | 发布/seed/scaffold 检查与独立旧快照对照；无此断言不声称升级保护 | 默认失效处理 |
| 生命周期与部署（编排） | 正式安装、新/旧工作区、重载/卸载；写 UI 若采用需验证真实 slot 装配 | 按开发指南 L1/L2 和真实浏览器 owner；Settings 属新面，先声明具体 owner 再验收 | 是否值得扩代码边界 |

标准分类遵循 [验收设计](../methods/validation-design.md)。未选范围不把表中所有操作当首版义务；最终结论要明确保留、删去或延后哪些行为。

## 范围排除与关闭条件

不把长期配置库放进 run facts 或只读模板，不建第二个研究状态机，不改 DSH core，不在 Cockpit 中编辑配置。不承诺跨设备同步、团队共享、预设市场或高承诺学术协议。

当长期管理的做/延后/不做、作用域、入口、数据 owner、与单次快照的关系和架构影响已有依据且获必要判断，可按 [交接方法](../methods/issue-to-note.md) 申请处理；需显式评审的持久架构决定由 notes 判断是否形成 RFC。未定范围保持活跃，不将技术可行性写成产品许可。

## 结论与落地记录（2026-10-12 实施授权后）

- **已实施**：长期复用的最小可用形态 = 对话式显式保存——用户明确要求（"记住这种做法/以后都用"）→ Lead 把当次有效方法写成 `research-workspace/method-library.md` 命名条目；此后立项 Lead 显式读取该库作推荐参考，题面指定仍优先。协议正本 = Lead 的 research-brief skill「用户方法库」节（含看/存/改/删/设默认五动词）。作用域 = 本工作区；无版本史/跨设备/共享（README 已知限制同记）。
- **右栏「研究配置」管理面板（2026-10-12 用户拍板：做期 1）**：
  - **期 1（已拍板，本轮交付）**：右栏新增与「研究状态」并列的「研究配置」页签——显示 4 个内置偏好（只读）+ 「我的偏好库」实时投影（读工作区 `method-library.md`，与磁盘对账）；每条带操作按钮（用于本次 / 设为默认 / 编辑 / 删除）→ 生成对应自然语言指令**经 `session/prompt` 发给当前会话 Lead 执行并回执**（默认 steer、失败降级 queue）；面板不直写任何文件——写路径唯一 = Lead（模型可见、会话日志留痕、与 run 事实一致）。架构依据 = [00-index D25](../../docs/00-index.md)（D7/D18 有界扩展：client 面新增管理**中继**显示与指令生成，业务写入仍归 agent）。
  - **期 2（以后可选，未拍板）**：面板直接表单编辑/直写库文件或 Settings 持久化（写入绕过 Lead）——更大的架构改动（写路径移出 agent、修订冲突/并发、D7/D18 再扩边），动工前需独立方案评审 + 用户再次拍板；重议条件 = 期 1 实际使用后仍嫌指令中继慢/不直观。
- **延后（被取代）**：Settings 独立管理页路径——由用户选择的右栏面板路径取代为本期方向；期 2 启动时再一并评估。
- 状态翻转 推敲中→等人拍板：期 1 实施后仍待用户实测确认；Settings 路径已被右栏面板路径取代。
