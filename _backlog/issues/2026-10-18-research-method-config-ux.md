**当前情况：** 面板与折算实现已亲读；方法内容正本 = lead 的 [research-brief skill](../../packages/deep-research-pack/presets/lead/skills/research-brief/SKILL.md) 方法预设表；题面形态库 = [question-patterns.md](../../research-workspace/question-patterns.md)（8 条）；节点契约 = [NODES.md](../../research-workspace/NODES.md)。外部先例与验证边界 = [调研材料](../research/2026-10-18-method-config-ux-external.md)。**本卡已经过两轮无上下文审计（内容盲审＋拆卡结构审计）与一轮有上下文代码级复核**（回执见 §附录）。**2026-10-18 按用户拍板拆卡**：实施分派两张子卡，本卡只保留共用的边界、证据与共识。

**未决问题：** 交付工件合同的范围（盲审后缩小，见 U12）；领域包要不要升格为字段（U13）；方法库增长纪律（未决-3）；库规模（未决-4）；保存指令优先级。以上都**不属任何子卡**，见 §未决与重议条件。（"P→方法映射表住哪" = **U16，是子卡② 的前置**，不在此列。）

顺序建议：子卡①② 可并行（① = 客户端与测试；② = skill 表、内置名单与同钉内容面），但两卡同改一个面，故**分工铁律**（**正本在此**，两张子卡只留压缩版 + 指针）：

- **按断言块分工，不按文件分工**——两卡可能落在同一个测试文件里（如 `tests/library-fold.test.mjs`），断言块不重叠即合法；若同落一个 diff，先落子卡② 的同钉改动，再叠加子卡① 的标签断言；
- **内容与呈现分家**：内置打法文本、标本映射、推荐规则**内容** = 子卡②；它们在面板上的**呈现与在场**（卡片、详情位、按钮、空态）= 子卡①；
- **两个定制入口**：按钮在场与位置 = 子卡①；指令文本与 Lead 行为 = 子卡②；
- **显示标签**（`找什么资料`／`明确不承诺` 等）与其一致性断言 = 子卡①；内置内容面的**同钉同步**（实测四处＋发现 15 的模板与 README 枚举面）= 子卡②。

未决池各项等实证疼痛再升卡。

## 术语（给无上下文读者）

| 词 | 这里指什么 |
|---|---|

| **同钉** | 内置条目的同一份事实散在多处，任一侧改字即红。**实测四处** = 客户端常量 / skill 表 / `tests/library-fold.test.mjs` / `client-load-smoke` 的内置名单（发现 14）；**另有未钉面**：显示标签（发现 13）、模板 `采用:` 选项行＋pack README 枚举（发现 15，归子卡② 同步）。原有的"三处同钉"是旧称 |
| **折算层** | `src/lib/` 的纯函数：把文本折成条目与指令；有 keyless 单测、组件只负责画 |
| **派工五件⑤** | Lead 派活给队友时必须写全的五项，第⑤项 = 方法论装载（把本次方法的相关要求点名写进任务） |
| **node-gate / evidence-audit** | 操作侧的机械门：前者查 bundle 文件在场与判据，后者查来源可溯源；**都不检查方法承诺** |
| **readiness** | critic 在 `review.md` 给出的终局判定（PASS/FAIL），PASS 才进入交付审阅 |
| **底线六条** | 来源链 · 逐字摘录 · 独立信源 · 日期校准 · 缺口显式 · readiness——任何打法都改不掉 |
| **标本 run** | 给一条内置打法配一个本仓真实跑过的 run，让人看到"这条打法上次跑出来长什么样" |
| **厚内置条目** | 对照：现在内置条目 68–74 字（口号级）；厚条目 ≈ 用户自写的「格局调研」408 字（点名来源与字段）。成本 = 内容撰写 + 同钉同步 |

## 已核实发现（逐条有出处）

| # | 发现 | 证据 |
|---|---|---|
| 1 | **方法轴是题面轴的影子，且与自家判型库不对齐** | 判型库 8 条 vs 方法 4 条。**注意：映射是"按类型"而非"按 P 号"**——research-brief 给的是 quick_factual→事实核查、exploratory_map→领域地图、claim_verification→主张核查、选型/对比/方案指导（含兜底归 exploratory_map 的 P5/P6/P7）→方案比较。所谓"P8 无对应"是**按该规则链推导**的结论。**本仓没有任何 P→方法的表** |
| 2 | **HITL1 的第二个问题现在是零信息** | 第一段卡问研究类型，第二段计划卡再出现"方法：X"。问题不在"问两遍"（两轴真不同时各问一次合理），而在**方法＝类型的确定函数**，那一行不携带新信息 |
| 3 | **本次 run 用的方法在整个驾驶舱不可见** | 研究配置页签只读 `method-library.md`（**不读 question.md**）；研究状态页签虽读 question.md，但**只取首行**当"研究问题行"，不取研究方法节。副标题却承诺"每次研究自动推荐、可换" |
| 4 | **回执 ≠ 落地** | 发送成功 = 绿条 `已发给 Lead：<整条指令原文>` + 2.5s 后自动重载；Lead 未落地时用户看到的仍是"成功"。仓库自有词汇纪律（强正面词留给 hard gate）→ 应分"已发送 / Lead 已回话 / 已落盘"三态并显示改了哪一句 |
| 5 | **"它怎么干活"没被回答** | 卡面一行摘要 + 详情四段要求文本；缺检索路由、编制、工件骨架、以及**这条要求管不到什么** |
| 6 | **内置不成示范（量化 5.6 倍）** | 用户自沉淀的「格局调研」四字段 **408 字**；四条内置 **72／68／74／72 字**（按 事实核查／领域地图／主张核查／方案比较 序） |
| 7 | **可辨识度不足** | 事实核查 vs 主张核查 3 秒内分不清；卡上只有"做法"、没有"什么时候用它" |
| 8 | **新建 = 空白页** | 名称 + 4 个空 textarea；救生索「基于此自定义」藏在 ⋯ 菜单 |
| 9 | **库会腐化** | 无命中计数、无结果指标、无休眠；对照判型库的增长协议（留察 / 跨 run 复现 ≥2 或单次真实成本 / 连续 3 次零命中休眠）一条都没有 |
| 10 | **底线与作用域不可见** | 六条共同底线不在任何界面；库作用域（本工作区、同工作区共享、换工作区不带）只在副标题小字 |
| 11 | **渲染瑕疵（用户截图实证）** | `summaryOfEntry` 取 `sections.source` 原文、直接渲染进纯文本 div（不解析 markdown）→ 用户条目里的 `**只钻一遍**` 在卡面显示为**字面星号**；长条目不截断，一张卡 4 行拉爆列表 |
| 12 | **同一个右栏两种时间观** | 研究状态页签是 follow 流实时；研究配置要手点「刷新」（代码里只有发送成功后延时 2.5s 的一次自动重载） |
| 13 | **字段显示名与指令名不一致，且不在同钉范围内**（盲审发现） | 面板显示 `找什么资料` / `明确不承诺`（客户端 SECTIONS），而指令与库格式写 `找来源=` / `不承诺=`（library-fold 与 skill 表）。用户按 A 改、指令说 B。当前同钉只覆盖名称＋摘要＋四字段**内容**，**显示标签面未钉**（只有冒烟钉了面板措辞） |
| 14 | **冒烟硬编码内置名单**（盲审发现） | `client-load-smoke.mjs` 断言 `['事实核查','领域地图','主张核查','方案比较']` 四条全在场——内置改 6 条会直接把浏览器冒烟打红，而它不在任何"同钉"清单里 |
| 15 | **方法名清单还有两处未钉的枚举面**（三轮复核发现，归子卡②） | `research-workspace/templates/run/question.md` 的 `- 采用:` 选项行枚举四方法名（pack 种子副本由 `dev/sync-pack-workspace.mjs` 同步，`pack-workspace-fresh` 只证同步不证内容）；`packages/deep-research-pack/README.md` §研究怎么跑 亦列举四预设（README 合同 = 行为改变同 diff 更新）。新增方法不同步改 → 模板选项缺名、README 漂移 |

## 概念模型：四个轴 + 一条原则

| 轴 | 回答什么 | owner |
|---|---|---|
| A 题面形态 | 研究什么形态的问题 → topic 骨架/编制/类型卡 | [question-patterns.md](../../research-workspace/question-patterns.md)（8 条） |
| B 打法 | 怎样调查、核验、综合 | research-brief 方法预设表 + 工作区库 |
| **C 领域包** | **本行业的一手源 / 口径 / 工件 / 免责** | **今天没有这个轴**（以库条目形式隐约存在——「格局调研」就是一条） |
| D 本次旋钮 | 时间窗/语言/地域/排除/深度篇幅 | question.md §Constraints（已有，**不复制**） |

**原则：旋钮必须映射到既有执行面。** 凡执行不了的一律不做（域过滤这类真做不到的：外部先例 = Microsoft 明确拒绝做站点白名单）；**已经写在底线里、不可降级的不做成旋钮**（如手册已有的"final 关键结论 ≥2 独立信源，critic 判"）。

四字段的实际执行面（**现在完全看不见，但已实现在三个 skill 里**）：

| 字段 | 谁读它 | 在哪生效 | **管不到什么** |
|---|---|---|---|
| 找来源 | scout（检索器对账、query 三轮）、analyst（采信分级） | 派工五件⑤ + leads.md 的 `单检索器——待破` | **不是域名硬过滤**（web_search 无此能力）；不改手册 source_tier 判据表本体（harness 常量，D17） |
| 怎么核实 | analyst（摘录口径至少两项）、critic（独立重抓/反例） | evidence 卡口径契约 + review.md | 不新增机械门；node-gate / evidence-audit 不检查方法承诺；**≥2 独立信源是底线，不是本字段可调项** |
| 报告怎么写 | lead（synthesis） | final.md 首屏**两种已文档化形态之间**的选择与重点顺序（六段／快速缩略）；**正文组织**（分节、时间线串法、矩阵排法）可由打法影响 | **不能换第三种首屏形态**（表格／时间线／矩阵）。注意区分**首屏骨架**（合同，两种）与**正文组织**（打法可影响）——某打法把正文写成时间线是合法的，把首屏换成时间线不合法（见 U12） |
| 不承诺 | critic + 交付限制节 | review 检查点 + 「目前不能判断」 | 不被机械门把守 |

## 行业差异的落点：四处内容，不改拓扑

**结论：行业差异不落在角色/节点/门禁上，落在四处可写的内容上**——所以定制本质是**内容编辑**，可以做得简单。四处 = ① 一手源是谁（把 source_tier 判据具体化）② 口径必带什么（财年/币种/汇率日；适应症/剂量/终点；申请日 vs 公开日；计费单位）③ 冲突怎么裁（官方 vs 媒体；期刊 vs 预印本；厂商 vs 实测）④ 工件与免责（IC memo / 证据表 / 权利要求对比表 / 差距分析表 / 选型矩阵；不构成投资、法律、诊疗意见）。

**边界提醒**：领域包只能写进**库（run 变量）**，不能改研究手册（harness 常量，D17）；它靠 Lead 派工传递，机械审计不检查它——这一条必须在界面上如实说明，否则就是假旋钮。

逐行业的具体内容草案（8 个场景 × 一手源 / 口径陷阱 / 检验与冲突裁决 / 工件 / 不承诺，逐行标注依据等级）= [调研材料 §5](../research/2026-10-18-method-config-ux-external.md)。**该表是设计材料、非已核实事实**，逐行核实前不进任何模型面文件。

## 方案与取舍

**选中方案（定制阶梯）**：零配置（接受 HITL1 推荐）→ 轻改一次（计划卡修订 / 「用于本次研究」）→ **沉淀**（跑完满意的一场 →「把这次的做法存成偏好」，Lead 从 question.md 研究方法节 + evidence 的来源分级分布 + final 骨架归纳成四字段）→ **起草**（面板一键「让 Lead 帮我起草」：先问三个问题〔一手源？必带口径？给谁看/什么工件？〕再按四字段起草落库）→ 精细（分区编辑）。后两档是本次新增；两者都走 `session/prompt`，**不越 D25 边界**。外部印证：AlphaSense 自定义 Skill 五入口正是这个形状。

**输掉的方案**：

- **前端向导先行**：输入面一旦要选，等于把四字段换个说法再问一遍，草稿质量还不如 Lead 现写——缓做；
- **方法清单一次扩到 7 条**：P2 逐格口径与"事实核查"的差异不足以支撑独立条目——留在卡上，等真实 run 触发；
- **面板直写库文件**：写路径移出 agent → 变更不再模型可见、不留会话日志（D25 已裁决，本卡不重开）；
- **领域包改研究手册**：违反 D17（harness 只能读）；
- **域过滤 / 检索轮数上限等无执行面的旋钮**：外部先例 = Microsoft 拒绝做站点白名单；
- **把 ≥2 独立信源做成可调旋钮**：它已在底线里且不可降级（盲审订正）；
- **拆成 1 总 + 3 子（本卡拆卡时的落选方案）**：把"交付工件合同 + 领域包字段"也独立成卡——它会让一张长期无证据支撑的卡挂很久；改为留本卡未决池，按实证疼痛升卡；
- **不拆只分层（落选）**：把草案下放材料、卡瘦 1/4——只治长不治混，结论倾向仍会把"以后做"的未决项裹进"现在做"；
- **把方法写进每个角色 preset**：把每次研究的变量变成框架组合变更（[2026-10-12 研究依据](../_archived/research/2026-10-12-research-preferences.md)已否决）。
