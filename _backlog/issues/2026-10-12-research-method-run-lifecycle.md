# 推敲：研究方法配置——单次研究选择、执行与恢复

> 立卡：2026-10-12 ｜ 状态：等人拍板 ｜ 类型：Feature ｜ 结论倾向：现在做——闭环已实施并过真实 run 验证，待用户 review ｜ 可关闭：否

**问题与期望结果：** 用户选择或调整方法后，希望整次研究按该方法工作，并能在恢复、重派和交付回看时知道实际采用了什么。本卡推敲从 HITL1 输入到 run 快照、角色执行、恢复与只读展示的完整路径，避免只加一个选项却没有行为或恢复依据。
**当前情况：** [总卡](2026-10-12-research-preference-templates.md) 已记录用户意图；问卡有原始约束，Lead 派工已有自包含要求，run bundle 是研究事实正本。当前没有独立的方法快照及其传递约定。机制和节点映射见 [综合研究](../research/2026-10-12-research-preferences.md)。
**未决问题：** 如何融入 HITL1 两段卡与 quick 豁免；快照放问卡还是独立文件；默认/推荐和自定义怎样确认；坏配置、方法无法兑现与变更怎样处理；首版是否包含 Cockpit 摘要。
**下一步：** 依总卡的候选方法写出普通研究、quick_factual、用户已给方法三个交互走读，比较存储与恢复方案；先准备预期行为和负例，需要时按 [总卡授权边界](2026-10-12-research-preference-templates.md#已确认意图与授权) 做隔离可逆实验，正式落地前提交详细方案供用户 review。

## 范围与真实前置

- 本卡拥有当次选择、字段覆写/文字解释、冲突说明、快照身份与 owner、各派工渠道的送达、研究偏离、恢复和回边、报告及只读回看。
- 方法语义、首批预设与自定义可用内容依 [总卡](2026-10-12-research-preference-templates.md)；格式和交互可先查证，不能在内容未定时硬写 schema。
- 长期保存与默认来自 [管理卡](2026-10-12-research-method-profile-management.md)；本卡只规定接收一个候选定义并生成当次内容，不依赖管理器才能成立。
- 不改变角色数、Team 主通道或现行编制；不新增日常 HITL 停点、运行状态机或仓级任务队列。若新增硬输入/输出件，后续须评估 NODES 与相关同步面，不能偷偷只改模板。

## 现行边界

[research-brief](../../packages/deep-research-pack/presets/lead/skills/research-brief/SKILL.md) 的未知标 open、两段 HITL1、计划确认 ≤200 字及一轮修订是前置约束。skill 写已给信息不重复问，而 [Lead persona](../../packages/deep-research-pack/presets/lead.patch.yml) 要求已有答案仍发三问确认；这是待核对的现行表述张力，不能用新方法悄悄改写其中一处。quick_factual 不发第二段计划卡，不代表不记录当次方法；其单点 subagent 与轻量 Critic 也需得到适用内容。

[team-assembly](../../packages/deep-research-pack/presets/lead/skills/team-assembly/SKILL.md) 的编制矩阵和派发五件仍是底座。spawn、已有队员新 task/消息、重派以及一次性查证都需考虑方法送达；不能只验证初次 spawn 或假定队员历史已包含最新要求。

[状态模型](../../docs/design/50-agent-loop-and-state.md) 决定恢复仅依 run bundle；[NODES 回边](../../research-workspace/NODES.md#回边版本语义d17) 决定补研究回挖掘、表述修订原位、结构性另起 bundle、HITL1 不重开。[运行指南](../../docs/guides/61-run-playbook.md) 另有活跃 run 的 steer 方向修订，Lead 记 Decisions 后原地补搜，不算 rerun。冻结初始内容不能取消此能力；须区分明确修订与一般提问，记录变化并将新要求送给受影响队员。

呈现默认要兼容 [synthesis](../../packages/deep-research-pack/presets/lead/skills/synthesis/SKILL.md) 的报告要求与 quick 缩略；核查要求要保留 [Critic 轻量豁免](../../packages/deep-research-pack/presets/critic/skills/adversarial-review/SKILL.md)。方法增加的承诺如何判偏离、何时 UNVERIFIED/MAJOR/FAIL 仍需明确，原 readiness 不自动证明它们兑现。方法偏离由相关角色在其 owner 文件及 journal 记录，操作侧 audit 不由 Lead 或队员修改。

## 方案与取舍

### 用户选择与确认

候选 A：把推荐方法及关键影响融入现有立项/计划摘要，已明确的方法直接落格，仅重要冲突或缺失需问。负担较低，但必须处理没有第二段计划卡的 quick 路径，不能把推荐记录成用户显式选择。

候选 B：在 HITL1 第一段加一个明确的方法问题，预设附一句话说明并支持覆写。可发现性好，但与三问纪律、已有困惑问/业务简报同时出现时可能过载；不能直接认定第四问是已允许的常规配置入口。

需要比较实际卡片文案和状态，而非先做一个额外选择器。用户已给、未指定、选择自定义、要求互相冲突应有清楚结果；不以省问为由补全未确认的目的/口径。

### 单一快照与派工

候选 A：在 question 中新增专门方法节，复用已有 Scope/Constraints/Decisions。路径少、恢复直接；需防问卡过长、现有浅读截断和多处重复值。

候选 B：独立方法文件，question 仅关联身份/位置，Scope/Purpose/预算仍归问卡。结构清晰、方便读取；会增加节点输入、模板/种子/扫描/部署同步面。不能 question 和方法文件双写成两个权威版本。

共同建议：保存版本与实际内容，区分原预设、当次覆写和采用来源，初始确认内容不被库更新或改名重写。Lead 按节点节选必要动作写入自包含派工，并指向同一 run 正本；fresh 不依赖 Lead 历史，嵌套 AGENTS 不作首步唯一通道。稳定角色技能仍定义职责和质量底线。

### 失败、修正与交付

- 非法/损坏/未知格式：与用户未选择、旧 run 未记录分开；不自动按当前默认继续。问卡 timed pending、答案返回但快照未写入、写到一半的内容也必须区分；只读有用准备不能冒充已确认执行，恢复核对答复与文件事实，不把沉默当接受。
- 多 run/归档：归档续跑、路径迁移不改变本次内容身份；关联 bundle 不唯一时依 sibling/接续规则处理，不自动挑一个。并行 run 使用各自快照，未来默认与其他 run 不串用。
- 约束冲突/能力不足：说明不能兑现什么及影响；共同证据/权限底线不能被自定义关闭。用户硬性只允许/排除的来源不可因不可达而擅自扩围；来源优先是指导，不升级为白名单，可使用本来允许的其他来源并说明限制。
- 模型偏离：以 query、来源、证据、findings/review 为依据核对，不信“我遵循了配置”；补搜/修复沿既有回边，未能查明的要求如实记录，不把方法名当通过证明。
- 中途修正：初始确认保留；补证据默认沿用同一方法。哪些覆写属于合法范围补充、哪些是结构性换方法需另起 bundle，要具体列例，不预先造第二套版本状态机。
- 交付回看：报告说明实际方法与重要限制；Cockpit 若纳入，只从已绑定 run 的事实读取摘要，不显示当前库默认冒充运行配置，不新增编辑或停点。读取失败/未绑定/旧 run 未记录如实显示。

## 验收标准

以下是已知意图与现行边界对应的标准草案，条件项等方案确定后才定稿；本轮只交准备材料，不宣称已通过运行验收。证据命令的适用面归 [开发指南](../../docs/guides/60-dev-loop.md)，具体新增断言需后续设计。

| 行为与类别 | 输入/状态 | 通过信号与失败信号 | 负例/恢复 | 证据 owner 与限度 | 人判断 |
|---|---|---|---|---|---|
| 当次内容可解释（模型/编排） | 用户明确选方法、未指定、已给部分约束 | 采用来源与实际内容对应输入；方法问法无无效重复，不把 open 编成已确认；现行三问张力有明确处理依据 | 快答免第二段；冲突不能静默覆盖；pending/未落盘不当已确认 | HITL 会话事件 + question；回放可证渲染，不能证选项好懂 | 问法与负担 |
| 内容正本唯一（确定性） | 预设加覆写；多个既有 Scope/预算字段 | 从唯一 owner 能读到当次实际内容，引用不互相矛盾 | 模板改名/更新/删除后原内容仍在 | 模板/文件契约、未来解析接口的行为断言；pnpm verify 只证结构 | 无 |
| 全渠道送达（编排） | fresh spawn、已有队员新任务、重派、quick 查证 | 请求/读取中可追到同一快照与任务相关动作；派发五件保留 | 初次 prompt 有名称但无内容、嵌套 AGENTS 未加载时不得误判送达成功 | 真实组合的 session log 与 bundle；L1 只证挂载，keyless 回放仅证装配 | 无 |
| 恢复独立于库（确定性/模型） | 新 Lead 接续有快照的 run；库已变或不存在 | 只凭 bundle 复述方法并按相同内容派工 | 旧 run 未记录不伪填；损坏/未知版本不静默默认 | 恢复走读及推敲实验的真实新会话观察；文件在场不能证执行 | 旧 run 接续体验 |
| 行为确有差异（模型） | 同题、同预算，领域地图与主张核查候选对照 | 事先预期的 Scout 搜索/覆盖与 Analyst 或 Critic 动作出现对应差异，产物可核 | 只改报告标签/自述，或方法要求未执行，判不成立/证据不足 | 推敲实验中的真模型 session + query/证据/findings/review；静态 prompt 测试不能替代 | 方法效用 |
| 底线与能力诚实（模型） | 自定义只找赞同、免除适用核查、要求系统综述、指定不可达来源 | 保留适用质量/权限边界及 quick 轻量豁免；不预设结论、不伪称穷尽，说明冲突或缺口 | 模型误读/不能执行须修正或显式记录，不能扩大权限或绕过用户硬性来源限制；来源优先不升级为白名单；新增承诺不默认已由 readiness 验证 | 研究手册、Critic review、既有 evidence-audit；不发明质量评分，audit 由操作侧写 | 承诺是否可接受 |
| 修订与回边一致（编排/模型） | steer 方向补充、HITL2 补研究、表述修订、结构性换方法 | 与现行修订/回边及 Decisions 一致；初始内容保留，无隐式 HITL1 重开，新要求送达受影响执行者 | 不把更换整体方法误作原位 polish；旧产物/旧任务不能冒充按新要求完成 | NODES、运行指南、question Decisions、final 记账；node-gate 只证现有机械项 | 结构性变化边界 |
| 只读回看（确定性/编排，若首版纳入） | 绑定 run、未绑定、archive run、文件失败、库默认已变化 | 摘要与当前 run 磁盘事实一致；状态不虚构，未读到不等于未选 | 两 run 不串数据；无快照不显示默认；不依据名称宣称兑现 | Cockpit 折算测试 + client-load-smoke 磁盘对账；不能证明研究质量 | 信息量与位置 |

模型标准应先写独立预期和观察失败条件，再在授权范围内验证；单场展示不足以证明普遍效果。不能用工程测试代替真人 UX 判断，也不把所有方法要求新增为机械硬门。

## 落地执行记录（2026-10-12 实施授权后）

用户授权实施（见总卡授权演进）。以下为实施期拍板，均记录依据：

- **快照落点 = question.md 新增「研究方法（本次实际采用）」节**（原候选 A）。依据：不加新文件即零 NODES 六处同步面；scout/analyst/critic 派发五件①已要求先读 question.md，方法随既有读取路径自然送达；恢复只凭 bundle 的现行合同不变。Scope/Purpose/预算仍归原字段，方法节只写调查路径内容与采用来源，硬性输入约束不复制（引用 Constraints）。
- **选择入口 = 不加第四问**（回应审查发现的双菜单/重复选择风险）。推荐方法由 Lead 依判型与题面自动给出：普通 run 在既有计划确认卡的计划要点中加「方法行」（名称 + 一句人话说明 + 调整走既有「修订计划」选项，自然语言）；quick_factual 免第二卡 → 类型即方法（事实核查），question.md 记「自动采用」与理由，运行中用户 steer 可改。既有三问卡零例外纪律不动。
- **首批预设 4 个**：事实核查、领域地图、主张核查、方案比较；「研究证据综合」延后（高承诺，另证能力再议）。内容住 lead 的 research-brief skill（方法论文本），不是新增用户菜单。
- **长期复用 = 对话式显式保存**：用户明确要求（「记住这种做法/以后都用」类原话）→ Lead 在立项前把命名方法条目写入工作区 `research-workspace/method-library.md`（用户数据，非 harness 纪律文件，Lead 维护）；此后立项 Lead 显式读取该库作为推荐参考，题面指定仍优先。无版本史、无跨设备、无共享；Settings 管理页不做（需 D7/D18 显式重议，另行申请）。
- **Cockpit 只读方法摘要 = stretch**：核心闭环验收后再做，走 lib 折算纯函数 + 状态页一行展示，仅读 bundle。
- **实验修正**（回应审查发现的混杂变量）：真模型走查先跑现状基线（不启用方法节），再同题同预算同判型同编制启用方法节对照；「类型切换」观察单独标注为整体产品效果，不记作配方独立贡献。
- **验收**：`pnpm verify` + `pnpm test` 全绿为底线；preset-smoke（L1 真挂载）验证 persona/skills 装配；可行则走 run 通道真模型实验（hitl-answer 代答，不阻塞等人）；UX 以完整文案 + 任务走查记录代替真人测试，并如实标注未经真人验证。

执行顺序：research-brief/lead.patch/team-assembly/question 模板 → 种子再生成 → 门禁与测试 → 实验 → 文档合同（pack README）→ 三卡结论与交付说明。

**实施与验证结果（2026-10-12）**：六处实现 = research-brief skill（四预设内容/映射/确认落格/用户方法库协议）+ lead.patch persona（立项读库/计划卡方法行）+ question.md 模板（方法节 + Snapshot 行）+ NODES 立项行 + team-assembly 派发点名方法动作 + critic 方法承诺核查节（4 节新增，原 4/5 顺延）；种子与 overlay 再生成。机械证据：`pnpm verify` 全绿、`pnpm test` 405 过、preset-smoke 真挂载 ALL PASS（4 preset + skills 隔离）。真模型走查（quick_factual「DeepSeek chat 上下文长度」，HITL 代答 pick=recommended 并显式记账代理模拟）：方法节自动采用落格含判型理由/本题化调查要求/不承诺边界；派工五件含方法动作；critic 轻量独立重抓执行了方法检验策略，二轮 readiness PASS（零 CRITICAL）；HITL2 定稿 → final/v1.md → present → goal complete 全链走通；操作侧 evidence-audit：12 证据、URL 真抓 12、摘录回溯 70/71、final 链 50/50、CRITICAL 0（MAJOR 1 为操作侧审计记录，非交付门）。**未覆盖**：普通 run（非 quick）的计划卡方法行与修订调整、方法库保存路径（代理模拟未发起保存请求）、Cockpit 方法摘要（延后）——均为后续 run/授权项；UX 可理解性未做真人测试。
