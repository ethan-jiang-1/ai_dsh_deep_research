# 推敲：研究偏好的详情查看与分区编辑 UX（右栏「研究配置」期 1.5）

> 立卡：2026-10-12 ｜ 状态：等人拍板 ｜ 类型：Feature ｜ 结论倾向：现在做——方案已细化且前四项（格式/折算/组件/smoke）已实施，待人实测手感与收尾 ｜ 可关闭：否

**问题与期望结果：** 用户在右栏「研究配置」面板看到偏好清单后，下一个自然动作是：点开某一条，看**里面到底写了什么**（会怎么找资料、怎么核实、报告怎么写），然后**按自己的话调整**它。期 1 只有一行摘要 + 一个整段 textarea 盲编辑——看不见内容就改不了，也改不明白。本卡把"查看一条偏好"与"分区调整"的交互做完整。
**当前情况：** 期 1 已落地（列表投影 + 一键指令经 Lead + 对话管理五动词）；库格式与指令正本 = lead 的 research-brief skill；D25 边界（面板不直写、写入唯一路径 = Lead）见 [00-index](../../docs/00-index.md)；面板实现 = [ResearchConfigTab.tsx](../../packages/deep-research-pack/src/client/ResearchConfigTab.tsx)。用户明确要求"好好想 UX、别敷衍、立卡跟踪"。

## 用户任务走查（设计目标）

1. **看懂内置偏好**：点「领域地图」→ 原位展开详情：三个分区（找什么资料 / 怎么核实 / 报告怎么写）逐条人话渲染 + 不承诺 + 一句"改不了内置、但可以基于它自定义"。底部 [基于此自定义] [用于本次]。
2. **基于内置做一份自己的**：点 [基于此自定义] → 名称输入框（预填「基于领域地图的自定义」）+ 三分区预填内置内容 → 用户改自己关心的那节（如把"广度优先"改成"重点看免费产品"）→ [发送修改] → 指令交给 Lead 建新条目 → 面板刷新出现新偏好。**内置始终只读**（升级保护不变），用户改的是自己的副本。
3. **调整已保存的偏好**：点条目展开详情（当前内容分区可见）→ 每分区旁 [改这节] → 小输入框预填当前文字 → 用户改完发送 → 指令 = "把研究偏好「X」的「怎么核实」改为：<新文字>"（单节定向，改动小、Lead 好执行、用户好理解）→ 回执 + 自动刷新。
4. **删除不再裸奔**：期 1 的删除是点了就发——补二次确认（[删除] → 变为 [确认删除？] 再点才发），防手滑。

## 信息架构（详情卡内容，用户语言）

| 分区 | 承载 | 库字段 |
|---|---|---|
| 找什么资料 | 信息源策略（官方/原始优先、第三方只当线索…） | `找来源` |
| 怎么核实 | 检验策略（独立重抓、反例权重、口径对齐…） | `怎么核实` |
| 报告怎么写 | 综合与呈现（地图式/判定+反证/维度化对比…） | `报告怎么写` |
| 明确不承诺 | 边界一句话 | `不承诺` |
| 来源行 | 日期 + 源自哪个 run/对话 + 默认偏好 badge | 标题行 |

**库格式升级（本卡的实施前置）**：条目正文从自由 `调查要求` 升级为上面四字段（前缀行）。向后兼容：旧条目（`调查要求`/`适用说明`）详情按"自定义要求"单块渲染，Lead 下次编辑该条时顺手迁移到新格式；`library-fold` 同 diff 支持两代格式（keyless 测试钉）。格式正本 = research-brief skill「用户方法库」节，同 diff 更新。

| 默认偏好徽标 | `Tag`（八色只读胶囊） | ~~手写 span~~ |

| 删除确认 | 小 `Modal`（确认/取消两钮） | ~~期 1 的点了就发~~ |

交互流（重写后）：

1. **列表**：条目卡片（名称 + 一句话 + 默认 Tag）→ 点名称开 `Modal` 详情；卡片右缘 ⋯ `Menu` 放操作。
2. **详情（读）**：Modal 内四分区（找什么资料 / 怎么核实 / 报告怎么写 / 明确不承诺）+ 来源行；内置条目无编辑钮、有 [基于此自定义]；底部 [用于本次]（primary）/ [编辑内容]（outline）/ [关闭]（ghost）。
3. **详情（编辑）**：同一 Modal 切编辑态——名称（内置来源时为新名称输入 `Input`）+ 四分区预填文本域 + 底部 [把修改交给 Lead]（primary，单保存钮）/[放弃]。发送 = 整条指令（`把研究偏好「X」改为：找来源=…；怎么核实=…；报告怎么写=…；不承诺=…`），保存未落地保留草稿。
4. **基于内置自定义**：详情读态点 [基于此自定义] → 同 Modal 切新建态（名称 `Input` + 内置内容预填）→ 保存发 `新建研究偏好「<名>」…（基于内置「<源名>」调整）`。
5. **删除**：Menu 删除项 → 小 `Modal` 确认 → 发删除指令。

## 指令文本（生成正本，写进 skill 管理动词）

- 整条编辑：`把研究偏好「<名>」改为：找来源=<…>；怎么核实=<…>；报告怎么写=<…>；不承诺=<…>`
- 基于内置新建：`新建研究偏好「<名>」——找来源：<…>；怎么核实：<…>；报告怎么写：<…>；不承诺：<…>（基于内置「<源名>」调整）`

## 验收标准

- **keyless**：`library-fold` 解析新四字段格式 + 旧格式兼容（两代夹具）；详情内容折算纯函数（分区 → 渲染行）；指令生成逐字断言。
- **browser（client-load-smoke 增补）**：详情展开在场（内置一条 + 库条目各一）；内置无编辑入口、有[基于此自定义]；删除需二次确认；分区编辑发送后回执在场。
- **UX 真值**：选项文案、分区名、"改这节"粒度是否好懂——**由用户实测判断**，本卡验收只证渲染与指令正确。
- 机械：`pnpm verify` / `pnpm test` 全绿；`cockpit-doc-registry`（新折算文件登记 design/40）。

## 范围排除

不改 D25 边界（不直写文件）；不做拖拽排序、导入导出、跨设备；不动内置预设正本（skill 方法预设表仍是内容唯一家）；不做批量编辑。

## 关闭条件

详情/分区编辑/二次确认/基于内置自定义四条用户任务有实现与浏览器证据；格式升级与兼容有 keyless 证据；用户实测反馈记录在案。若用户实测后要求期 2 直写，转[长期管理卡](2026-10-12-research-method-profile-management.md)重议。
