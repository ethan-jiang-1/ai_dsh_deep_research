# 本仓现状盘点：两套启动、一个仓内工作区、随包文本仍指仓内

盘点范围：`packages/deep-research-pack/`、`dev/`、`scripts/`、`tests/`、`snapshots/`、`docs/`、`README.md`、`_dist/`。`vendor/` 与生成物 `lib/` 不在内。所有判断以盘上文件为准；标"实现"的是当前代码行为，不是合同。

## 1. 两套"启动"叙事，作用域没有声明

| 入口 | 出现位置 | 实际作用域 |
|---|---|---|
| `node dev/run-driver.mjs up` → `dev/boot-run.sh` | 根 `README.md`、`docs/00-index.md` §先分流第 1 行、`docs/project-map.md`、`docs/guides/61` | 仓内开发通道：`runtime/harness-home` + `research-workspace` + 漂移门 |
| `dsh --profile research`（手动建 profile + add + scaffold 之后） | `packages/deep-research-pack/README.md` §部署、`_dist/安装手册.md` §四 | 已装用户的手动启动 |
| `node dev/run-driver.mjs up --bootstrap` | `docs/guides/65` §4 | 冷启动/多实例 |

`docs/00-index.md:17` 写"**别**直接 `dsh --profile research`——那会绕过漂移检测"，但 `_dist/安装手册.md:104` 又把同一条命令写成用户第 ④ 步。两句话各自在自己的作用域里成立，但没有任何一页把作用域写清；fresh agent 与用户都会把它们读成互相矛盾。

## 3. 会话组发现是"工作区任意"的真正阻塞点

`scripts/lib/session-log.mjs:38-49` 的 `findGroup(root, substring)` 与 `researchWorkspaceGroup() = findGroup(root,'research-workspace')` 用**目录名 substring** 找会话组；`scripts/lib/web-ui-nav.mjs:27,210` 的侧栏候选也写死 `research-workspace`；四个 run-ops 工具的 `--group` 默认值同样是 `research-workspace`（`bundle-sessions.mjs:47-49`、`session-events.mjs:39`、`plan-card-stats.mjs:25`、`provider-error-stats.mjs:24`）。

后果：工作区叫 `~/Notes` 或 `/data/acme/research` 时，所有 run-ops / hitl-answer / client-load 工具报"无命中会话组"。产品本身不依赖这些 dev 工具，但仓库调试产品 run 时会直接卡住。

**正解（已核）**：会话组目录不是任意 substring，而是 vendor `packages/session/session-persistence-jsonl/src/format.ts:207-245` 的确定性 `projectKey(cwd)`——`/`/`\`/`:` → `-`，非 `[A-Za-z0-9._-]` 用 `~XXXX` 转义，去前导 `-`，`--<slug.slice(0,251)>--`。spike 实测 `/private/tmp/dsh-product-boot/ws` → `--private-tmp-dsh-product-boot-ws--`。修法 = 在 `scripts/lib/session-log.mjs` 实现同形 `projectKey`/`projectGroupDir`，保留 substring 作为 legacy；不要扫 header（慢且无必要）。测试要加"任意工作区名 + 非 ASCII + 长路径"用例。

## 4. Profile 是手动前置，启动器不存在

- pack 的 bin 只有 `dsh-deep-research-preflight` 与 `dsh-deep-research-scaffold`（`packages/deep-research-pack/package.json:147-150`）；没有创建 profile、安装 pack、起 Web、绑会话的入口。
- `scaffold.mjs:569-609` 只确保团队层（`dsh plugin --profile <p> add @…-agent-team-profile@<ver>`）；它不创建 profile、不装 pack。
- `preflight.mjs:174-201` 把"profile 含 web-app + pack + 团队层"当既成前提；缺 profile 时的补救是手动 `dsh --profile <p> --from-default-profile web`。
- profile 名 `research` 在五处各自写死：`dev/boot-run.sh:18`、`dev/run-driver.mjs:41`、`packages/deep-research-pack/scripts/scaffold.mjs:36`、`packages/deep-research-pack/scripts/preflight.mjs:63`、`scripts/dist/export-dist.mjs:161-244`（生成的手册）。
- `dev/boot-run.sh:45-69` 的 pack 发布集 ↔ profile 镜像漂移门只对"仓内源码 → 开发镜像"有意义；安装态 tarball 没有对应物。产品需要另一套读回：package 版本、profile roster、row 存在、effective config（FAQ 35 的四层状态）。

## 5. 随包文本仍在指仓内脚本

`packages/deep-research-pack` 一旦被用户安装，仓内 `dev/`、`scripts/` 不存在；但随包文本仍引用它们：

- `packages/deep-research-pack/scripts/scaffold.mjs:186` 与 `scripts/preflight.mjs:212` 在种子清单/审计失败时提示 `node dev/sync-pack-workspace.mjs`——安装态是死 remedy。
- pack README 的用户步骤引用 `scripts/dist/export-dist.mjs`、`scripts/run-gates/secret-scan.mjs`、`scripts/run-ops/run-inventory.mjs`、`scripts/run-gates/evidence-audit.mjs`（后者已注明"开发仓，不随包发布"）。
- 种子手册 `workspace/AGENTS.md` 与 `workspace/NODES.md` 提到 `schema-scan` / `node-gate` / `run-accept` / `drafts/`（开发仓专属），但没有明确"安装态没有这些工具、回执按 install-only 降级"的边界句。

这不是"内容不在插件内"的问题——内容在包内；问题是**安装态文本把开发仓的动作当成用户可执行的动作**。产品化需要逐条 de-repo：要么删、要么改成"开发仓才有，安装态用 `no machine audit (install-only)`"。

## 8. 分发与 `_dist`

- `_dist/安装手册.md` 是 tracked 生成物，生成器 = `scripts/dist/export-dist.mjs`；正文是脚本内模板字面量（`:109-269`）。门禁 `dist-manual-version` 只校验表头版本 = pack 版本 + 指名 tarball，不校验正文；因此正文改动必须改生成器并重导出。
- `export-dist` 的 inventory `must` 列表目前不含 launcher（`:69-104`）；新增 bin/文件必须同 diff 加入，否则 tarball 少文件而手册照发。
- pack README 的 10 列数据卡由 `tests/pack/data-plane-invariants.test.mjs:39-63` 形状守卫；新增启动器设置行必须保持 10 列、P2 行卸载后写"保留"、可移植列在闭集内。

## 9. 可复用接缝（不要重造）

| 接缝 | 现有载体 | 产品化怎么用 |
|---|---|---|
| 工作区根参数化 | `scaffold --workspace`、`preflight --workspace`、`run-inventory --workspace`、`bundleDirOf(wsRoot,…)`、`nodeRunSource(root)` | 启动器与 dev 工具都传根；不要新增第二套 run 路径 |
| 种子引擎 | `scaffold.mjs` + `seed-core.mjs` + `workspace-guard.mjs` + `workspace-audit.mjs` | 直接复用；只新增"启动时静默 ensure"的调用方式 |
| 团队层版本派生 | `scaffold.mjs:576-600` 从安装锚/profile app-boot 派生 | 启动器复用同一逻辑，不装未钉版最新层 |
| 工作区注册 | `dev/run-kickoff.mjs:128-138` 的 `workspace/create` → `session/create{workspaceId}` | Host 插件用 `workspaceRegistry.create`；会话交给 Web Client |

| 凭据状态 | `scripts/lib/credentials-status.mjs` | preflight 复用；启动器不硬拦无 key |
| 相对回执 | `src/lib/final-target.ts` + `run-accept` 的相对标签 | run bundle 在工作区，回执天然可移植 |
