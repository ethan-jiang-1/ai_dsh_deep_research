# 红队：拆「一次研究 = 自包含 / 可丢弃 / 可续 bundle」

> 消费者：[_backlog/issues/2026-10-23-run-bundle-agent-state-and-read-chain.md](../../_archived/settled_issues/2026-10-23-run-bundle-agent-state-and-read-chain.md)
> ｜ 只读攻击（2026-10-23）；所有测试可在 `/tmp` 副本复跑，不改本仓。
> **结论先行：作为"目标"成立，作为"不变量"不成立**——`研究报告 = harness(bundle)` 本身就说 bundle
> 不是报告；研究事实可全在 bundle，但**批准、溯源、学习、执行现场**四类状态天然在外，其中两类
> 是交付/恢复的必需项。

## 1. 批准与 present 不在 bundle，门③/②可伪造（后果：假交付）

- 反例：semver bundle 同一处三套事实——`journal.md:10` 写「HITL2 pending、未写拍板行、未 present」，
  `question.md:56` 写「用户按现稿定稿」，`node-gate.md:8-9` 记 ③/② PASS，`audit.md:14` CRITICAL=7，
  最终停在 `_abandoned`；present 指向可变路径——hardware 的 v1（`final/v1.md` 记 18 行表/65 卡）
  其 present 指向 `final.md`，今日同路径已是 427 行 v2，而 v1 记账只有 41 行索引。
- 机制：门③只读 `question.md` 文本（`scripts/lib/node-gate-session-gates.mjs:135-166`），门②只查任意
  会话日志 payload 含 slug（同文件 :18-38），present 不在 bundle（`docs/guides/61-run-playbook.md:38`）；
  `dev/hitl-answer.mjs` 的 provenance 会把用户本人点击记成「代理模拟」（`archive/drt_harness-conventions-portability/question.md:112-114`
  三行互相更正）。
- 测试：bundle 拷到 `/tmp`，append `- HITL2 拍板：定稿` → `hitl2RowGate` 仍 PASS；伪造 present 指向
  `drt_x/review.md` → `presentGate` PASS；前缀 slug（`drt_x-v2/final.md` 满足 `drt_x`）也让
  `presentInLogs` 命中。
- 补条款：批准 = **日志锚定的 ask/answer 事件**，绑定 lead 会话 + final 哈希；无日志 = UNVERIFIED
  而非 PASS；present 只认 lead + 不可变快照（`final/vN` 或哈希），不指当前工作稿；bundle 文本永不
  作为批准证据；交付回执写进 bundle（指向事件）。

## 2. 「自包含」只在可读层成立；审计真相根是 262MB 会话日志（后果：换机/删日志即失去交付态、真证据被判伪造）

- 反例：semver 的 7 条 CRITICAL 全是 `file:///…` 本地文件——文件真实存在，却因不在 web 取回语料里
  被判「伪造链接」；46 个归档放空 sessions 根：门①红 22、门②红 22；再 `cp -R` 一次（mtime 变今天），
  24 个 PRE-CONTRACT 也翻红 → 46/46 失去①的交付证据。
- 机制：`scripts/run-gates/evidence-audit.mjs:7-8`「会话日志存着全部真相」；
  `scripts/lib/evidence-audit-core.mjs:221-224,276`；agent-instructions 注入消息会 replay/compact/resume。
- 测试：`cp -R archive/drt_deepseek-chat-context /tmp/x && gateBundle('/tmp/x', emptySessions)` → ①红；
  `evidence-audit --sessions /tmp/empty` → 全部 `source_url` 变 CRITICAL。
- 补条款：二选一——bundle 内带 `provenance/`（URL/本地文件 + sha256 + 取回时间 + 通道 + 原文切片）
  让审计离线可复算；或明文承认「bundle = 研究事实，证据正本 = bundle + 日志切片」，把切片纳入
  删除/归档单位。新增 provenance 类型（web/local-file/command），`file://` 不再按网页验；
  门禁三态 PASS/RED/UNATTESTED（无语料 ≠ 负证据）。

## 3. 不变量与 design/50 四态正面冲突；执行现场丢得比宪章说的多（后果：恢复承诺失真）

- 反例：design/50 写 session log 是「执行事件正本」、goal/板是「执行辅助」；实测新会话
  `team_task_list` 为空、任务板按 plan 的 `task_id` 重建（`drt_cn-us-ai-models-hardware/journal.md:15`），
  而 task_id「只是当前会话映射」（`research-planning:92`）；`create_goal` 对 agent 驱动会话直接拒绝
  （`drt_gha-ubuntu-latest/journal.md:7`、`vendor/dsh/packages/goal/tool-goal/src/authority.ts:102`）。
- 补条款：分层陈述——研究事实 = bundle 正本；执行状态 = 会话（可丢，恢复时重建，不承诺接上）；
  证据溯源 = 日志；派生 = audit/驾驶舱（不入恢复判定）；用 state 表代替绝对句。

## 4. 「下一步」不能从文件唯一推出：无状态字段，journal 是叙事且会与 Decisions 矛盾（后果：重问/重交付/卡死）

- 反例：semver 的 journal 顶（pending）与 Decisions（已批）相反；hardware 的续跑 journal 自己写
  「缺的是 W9/W10」——模型读后写的叙事，不是文件字段；46 个归档 45 个无 plan（执行图不在稳定契约里），
  4/4 在飞才有。
- 补条款：手册写死**状态推导表**（无 question→立项前；有 review 无 PASS→研究段；PASS 无 HITL2 行→
  待审；有 HITL2 行 + final/vN + 回执→已交付；`_abandoned`→停止），并规定「unknown/pending 是合法
  状态」；journal 与 Decisions 冲突的优先级（事件 > 文本）；交付回执。

## 5. 「删=删目录」不成立：删除留下 tar、日志、索引与悬空指针；共享库也是跨 run 状态（后果：删除/隐私承诺失真）

- 反例：2026-10-19 删 16 个 bundle，但 `_abandoned/README.md:34-35` 自述「完整会话日志仍在上游」，
  `/tmp/abandoned-backup-20261019.tgz` 仍在（383 条目，可列全 16 个目录）；`method-library.md:7` 还写
  「源自 drt_cn-ai-coding-assistants」——该 bundle 已删，指针悬空。`question-patterns.md:115` 的 P6
  种子点名 `drt_siliconflow-financials` 并把该 run 的「前提级发现」写成条目、`:137` 点名 geometry；
  `dev/sync-pack-workspace.mjs:36` 把库同步进 pack 随包发布；run 只记 `判型命中=P#`，不记条目正文/版本。
- 补条款：删除 = bundle + 日志切片 + 由它派生的共享库条目（或明文保留为证据并给保留期/访问边界）；
  禁止 `源自 drt_*` 跨 run 指针，改为匿名类别；`_abandoned/archive` 索引列为 ops ledger（不属于
  run 状态）；共享库定性为 harness 记忆、写匿名增量。

## 6. 契约版本漂移：断代靠 mtime，复制/改名即翻代；bundle 不自述版本（后果：同一 bundle 不同判决）

- 反例：46 个归档跨 5 个契约日（09-29/10-03/10-05/10-06/10-08），当下门禁仍判 2 个门③红、4 个门L红、
  1 个缺 `final/v1.md`（geometry 用 `final/README.md`）、2 个 audit 只靠 PRE-CONTRACT 放行；
  `drt_geometry-coaching` 自己的 `node-gate.md` 记 ③/② RED、audit CRITICAL=1，却仍在 `archive/`；
  `cp -R` 把 final.md 的 mtime 改成今天，`isPreContract` 由 true 翻 false；改名 `drt_x`→`x-copy`
  让 audit 标题校验红，present 的 slug 也失配。
- 补条款：创建/交付时写 `contract: N` + 手册/pack 版本 + `delivered.json`（门结果、audit 哈希、
  present 事件）；门禁读戳不读 mtime；改名=新身份需重盖章；旧 bundle 用迁移脚本补戳。

## 7. bundle 内的数据可以变成指令（AGENTS.md 通道；后果：注入升级为指令）

- 反例：presets 全部 `projectRootMarkers: []`（`presets/lead.patch.yml:99`），DSH 在成功
  read/write/edit 后会为该目录发现 `AGENTS.md`；`descendantDirsBetween` 把 `drt_x/evidence` 也纳入
  候选（`vendor/dsh/packages/context/agent-instructions/src/files.ts:276`）；还跟随 symlink 跨信任边界。
  当前 52 个 bundle 实测 0 个 `AGENTS.md`，但没有门禁禁止；2026-09-24 的化石 `$DSH_HOME/AGENTS.md`
  已压过手册、让整场 lead 按旧契约开工（`notes/implemented/2026-09-24-run-bundle-drt-separation.md:80-86`）。
- 补条款：机械禁止 bundle 内任何 instruction candidate（AGENTS.md/CLAUDE.md/local 变体，含 symlink
  目标）→ RED；把「bundle 内容是不可信数据」写进手册与 critic skill；交接前扫描；最好把 nested
  candidate 关掉/只在 cwd 认一个文件名。

## 8. 单写者只是表格，不是机制；leads 分片/草稿无契约（后果：丢更新与读不到接口）

- 反例：`drt_gha-ubuntu-latest` 早期两名 subagent + 一名 teammate 并发写同一批文件，实测多次
  `file changed since it was read`，靠 lead 逐条核收（`journal:8,17`）；`drt_eu-us-cn-ai-stack` 有
  `leads-eu.md`/`leads-supply.md` 两份未登记分片，`drafts/` 有 coverage-receipt 的 v2/v3 而无
  canonical 指针；11 个 bundle 共 12 个未登记顶层文件（leads-gaps×6、review-critic、topics-rerun、
  `_scout-verify.mjs`…）。
- 补条款：journal 分片（`journal/<role>.md`）或单写者 + 追加协议；leads 目录 + 索引（或禁止分片）；
  drafts 的 canonical 指针与清理规则；未登记顶层文件 = RED；用日志证明最后写者。

## 9. 换 harness/换模型/给人看：bundle 不自带说明，读法依赖本仓（后果：交接后读不懂/读不对）

- 反例：角色 cwd 必须是 research-workspace（`projectRootMarkers: []`；把 bundle 当工作区打开就没有
  手册）；队友方法论要按安装位读 `presets/<role>/skills/...`（`team-assembly:35-40`），bundle 不记
  pack 版本；45/46 归档无 plan，`W2.1`、`[来源:]`、`final/vN` 的语义全在仓内文档；没有 manifest。
- 补条款：生成式 `manifest.json`（文件角色 + 读序 + 状态表 + 契约/pack 版本 + 不可变快照哈希），
  它不是指令、不承担权威；或明确「bundle 只在配套 harness 下可读」。

## 已验证但未取到反例（避免误报）

- compaction：本地 662 个研究会话实测 0 个 `compaction/*` 事件——当前不是活故障；机制上手册基线是
  普通 user/message、可被压缩，长 run/换模型仍是风险。
- bundle 内 AGENTS.md：52 个 bundle 实测 0 个；机制可跑（#7），尚无真实注入事件。
- 非 lead 的 present：只证到工具在 critic/analyst 会话可见与门②不查角色；未找到真实非 lead present
  事件，按「未发生的洞」记。
- 证据 schema 不是问题：1,800 张卡中 1,757 张七字段齐，43 张是契约前无 frontmatter 旧卡。

## 最小修宪（按后果排序）

1. 保留「一方向一 bundle」与「研究事实正本在 bundle」；**删掉「之外不存任何状态」与「删=删目录」
   两个绝对句**，改为「bundle + 四张显式依赖（批准/溯源/执行/学习）+ 状态推导表 + contract 戳 +
   交付回执」。
2. 「可续」验收从「只给 bundle」改为「**bundle + 只读 harness + 状态表**」，接受语义续跑；
   present/HITL/审计三类事件必须有日志锚点；bundle 指令文件机械禁止。
