# 方案 A：滚动、对话智力体、切换对齐

调研日 2026-10-29。目标：不先写 UI，而先把**行为**定死——什么在滚、谁触发、切模式时保留什么。

图：`ux/R1-scroll-anatomy.png`（滚动解剖）、`ux/R2-state-machine.png`（模式状态机）。

## 0. 结论先行

1. **只有两个滚动容器**：草稿卡（展开时）、对话区。页面/工作台永不整滚。左库自滚。
2. **对话区遵循标准聊天**：默认贴底；用户上翻即暂停；有新消息出「N 条新消息」胶囊；点它或手动回底恢复。用户发消息永远强制贴底。
3. **草稿卡不自动滚**：卡片高度固定（收起态），字段多行内容截断；「展开表单」才进入全表单滚动。字段填上时**不抢对话的滚动**，只更新卡片。
4. **字段与对话可互查**：点字段的「来自对话」→ 对话滚到产出它的那条消息并高亮；点消息里的草稿回填 → 对应字段高亮。这是“信任”的关键。
5. **同一份 draft 是唯一真值**：卡、全表单、读态、probe、保存封套都读它；不存在“卡里有、表单里没有”。
6. **智力体不是聊天机器人**：它是一个有状态的四字段访谈器（问题选择、抽取、归一、冲突追问、完备性、保存/删除、检索、护栏、失败恢复），UI 只是它的投影。

## 1. 滚动解剖

| 容器 | 何时滚 | 默认位置 | 备注 |
|---|---|---|---|
| 页面 `[data-method-library]` | **永不** | — | `height:100%; overflow:hidden` |
| 左库 | 条目多时 | 顶部 | `overflow-y:auto` |
| 草稿卡（收起） | **不滚** | — | 固定高 268；字段值单行截断 + 省略号 |
| 草稿卡（展开/全表单） | 字段多/长时 | 当前 active 字段 | `overflow-y:auto`；「回到对话」回卡片 |
| 对话区 | 消息多时 | **底部**（最新） | 标准聊天；自动贴底；上翻暂停 |
| 输入框 | 不滚（多行时内部滚） | — | Enter 发送 / Shift+Enter 换行 |

## 2. 对话滚动的完整情形

1. **首次进入**：对话在底部；起手式可见；无“新消息”。
2. **发消息**：新气泡追加；**强制贴底**；输入框清空；出现“正在思考”行（钉在输入框上方）。
3. **流式回复**：内容增长；仅当用户在底部时跟随；否则不动，计数“新消息”。
4. **超长回复**：气泡内不滚（整段展开），由对话区滚；代码/表格同理。
5. **问卡出现**：问卡高；若在底部则滚入视口；否则只标记新消息。
6. **用户上翻**：立即暂停跟随；顶部/底部出现「回到最新」；不打断阅读。
7. **上翻时来新消息**：不位移；出现「1 条新消息 · 回到最新」胶囊；点击滚到底并恢复跟随。
8. **手动回底**：恢复跟随；胶囊消失。
9. **切换会话/刷新**：恢复历史；滚到底；草稿从库/草稿恢复；未保存提示。
10. **停止/失败**：显示 `Stopped` / 错误行；不自动滚（除非在底部）；可重试。
11. **字段回填**：卡片更新；对话**不滚**（避免打断）；若该字段是 active，卡片内高亮。
12. **点「来自对话」**：对话滚到那条回填消息、闪一下；再点字段回卡。
13. **展开表单**：卡片变全表单；对话收起；焦点到 active 字段；全表单滚到该字段。
14. **回到对话**：卡片恢复；对话恢复原滚动位置（记住 scrollTop）。
15. **读态**：对话收起；卡片只读；无滚动冲突。
16. **窗口变窄**：卡与对话各自保持最小高；不出现整页滚；输入框始终贴底。
17. **IME（中文输入）**：composition 期间 Enter 不发送；Esc 取消；候选框不遮挡输入。
18. **消息非常多**：虚拟滚动/分页；滚到顶可“加载更早”；不阻塞输入。

## 3. 草稿卡滚动的完整情形

1. 收起态：名称 + 2×2 四字段 + 进度 + 保存；长值截断；**不滚**。
2. 字段填上：值替换「（待定）」；标「来自对话」；进度 +1；**不改变卡片高度**（保持布局稳定）。
3. 手改：字段进入编辑（卡内允许直接改单行？→ 建议：卡内点击 → 切到全表单并聚焦该字段，避免卡内编辑态）。
4. 展开表单：全表单可滚；顶部保留「回到对话」；保存/取消/预览/默认都在。
5. 读态：卡只读；删除/设默认/和编辑聊聊。
6. 空态：卡显示「（待定）」，保存弱化，说明一行。

## 4. 对话智力体：它该是什么

### 4.1 状态（它自己维护的）

- **draft**：名称、四字段、provenance（来自对话/手改/待定）、active 字段、isDefault；
- **interview**：已问过的字段、当前字段、待补充项、用户说“不知道/跳过/你定”的记录；
- **library**：当前库条目名（防撞名）、默认条目；
- **context**：工作区、最近三条 run、内置参考、当前来源（从零/内置/run）；
- **session**：会话历史、标题、错误/停止/重试。

### 4.2 能力（缺一不可）

1. **选题**：下一个该问哪格（场景→来源→核实→报告→不承诺），为什么问它；可跳过、可“你替我定”；
2. **抽取**：把用户的话变成字段值；保留用户原话的可追溯引用；
3. **归一**：把口语整理成可执行规则（谁、何时、按什么口径、怎么裁）；
4. **冲突追问**：前后矛盾时指出并二选一，而不是默默覆盖；
5. **完备性**：四格 + 名称齐了才引导保存；缺的明确说缺什么；
6. **手改协同**：收到手改 diff → 确认、不覆盖、后续提问基于手改值；
7. **写库/删库**：只经窄工具；失败/超时/不可用有明确回执；
8. **检索**：内置参考只读对照；从 run 用 question.md/final.md 归纳；不重跑研究；
9. **撞名/默认**：保存前提示同名；设默认全库唯一；
10. **护栏**：一次一问；不用技术词；不研究、不读 fs/不 web；不承诺；
11. **失败恢复**：模型不可用、工具失败、DSH 重启、停止 → 明确的“现在能做什么”。

### 4.3 页面 ↔ 智力体的协议（现有 + 需补）

| 方向 | 内容 | 现有 | 需补 |
|---|---|---|---|
| 页面→智力体 | 首条上下文（库/草稿/内置/run） | 有 | run 选择结果 |
| 页面→智力体 | 保存封套（四字段+名称+默认） | 有 | — |
| 页面→智力体 | 删除封套 | 有 | — |
| 页面→智力体 | 手改 diff（900ms 防抖） | 有 | 失败重发 |
| 智力体→页面 | `method-draft` 全文（最后完整 fence） | 有 | 字段级 patch（可选） |
| 智力体→页面 | 「已写入/已删除」回执 | 有 | 错误码 |
| 智力体→页面 | 当前问题/active 字段 | 部分 | 显式事件，驱动卡片高亮 |
| 智力体→页面 | 停止/重试/不可用 | 部分 | 显式状态 |

**关键判断**：UI 的滚动/高亮/进度都应由**这些事件**驱动，而不是由“解析到一段文本”猜。现有 `method-draft` 是全文快照，足够驱动卡片；若要做到“点字段回看消息”，需要每条回填消息带一个稳定 id（消息 id 已有，记录“产出该字段的消息 id”即可）。

## 5. 模式/方案切换时的对齐

### 5.1 单一真值清单

| 状态 | 存在哪 | 切换时必须保留 |
|---|---|---|
| draft（名称/四字段/默认） | 页面 state（+ ref） | ✅ |
| 手改集合 / coach 字段集合 / active | 页面 state | ✅ |
| 库文本 / 加载态 / 错误 | 页面 state | ✅ |
| coach 会话 id / 历史 | session（DSH） | ✅（切模式不重建会话） |
| 对话滚动位置 | DOM | ✅（记 scrollTop） |
| 卡片滚动位置 | DOM | ✅ |
| 保存/删除待处理 | ref | ✅ |
| 模式（卡/全表单/读/内置/从run） | 页面 state | 切换即变，但 draft 不变 |
| 未保存脏标记 | 派生自 draft vs 基线 | ✅（切换/选库时提示） |

### 5.2 对齐矩阵（状态 × 模式）

| 模式 | 卡 | 全表单 | 对话 | 输入框 | 保存 | 可编辑 |
|---|---|---|---|---|---|---|
| 新建-卡 | 收起 | 隐藏 | 显示 | 显示 | 卡底部 | 卡只读，点字段→全表单 |
| 新建-全表单 | 隐藏 | 显示 | 收起 | 隐藏 | 表单底部 | 全字段 |
| 对话中 | 收起 | 隐藏 | 显示 | 显示 | 卡底部 | 卡只读 |
| 读态 | 只读卡 | 隐藏 | 收起 | 隐藏 | 隐藏 | 否 |
| 读态-和编辑聊聊 | 只读卡 | 隐藏 | 显示 | 显示 | 隐藏 | 否（只聊） |
| 内置参考 | 只读卡 | 隐藏 | 收起 | 隐藏 | 隐藏 | 否 |
| 从 run | 收起 | 隐藏 | 显示 | 显示 | 卡底部 | 卡只读 |

### 5.3 切换规则（避免状态打架）

- **卡→全表单**：焦点 = active 字段；全表单滚到它；对话保留 scrollTop；「回到对话」恢复。
- **全表单→卡**：草稿即时同步（同一 draft）；不重复保存。
- **新建→读态**：保存成功才切；失败留在新建并给回执。
- **读态→编辑**：把该条目装入 draft；手改集合清空；coach 会话沿用（带上下文）。
- **选另一条库**：有未保存修改 → 先确认；否则切换 draft，清空手改/coach 字段，重置 active。

## 6. 我建议的默认值（不用你逐条拍）

- 卡收起高 268；展开即全表单（不搞半展开）；
- 对话默认显示；读态默认收起；
- 「来自对话」可点，跳到产出消息；
- 新消息胶囊只在上翻时出现；
- 用户发消息强制贴底；
- 卡片内不提供编辑，点字段跳全表单（避免两套编辑态）；
- 从 run 取最近三条，默认最新；
- 内置参考只读，不直接复制。

## 7. 落地前必须补的三处

1. **字段↔消息的可追溯 id**（点「来自对话」回看）；
2. **显式事件**：active 字段、问题、停止/重试，而不是从文本猜；
3. **切换/选库的未保存守卫**。
