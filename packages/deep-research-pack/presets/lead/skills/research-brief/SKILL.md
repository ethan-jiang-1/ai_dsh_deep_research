# research-brief — 立项对齐（HITL1，两段卡）

一次 Deep Research run 的第一动作。目标：把用户的一句话变成**可验收的研究问题**，再拆成可分派的 topic 图；两文件定稿后先呈用户拍板再开工。

## 流程

1. **先查判型模式库**（`question-patterns.md`，会话 cwd 根）：通读各条目"识别特征"，对照
   题面找**命中条目**。命中 → 该条目就是本次立项的操作单：类型问卡选项与推荐、深度、
   topic 骨架、花名册按其"分派结论"填；动笔前过一遍其"陷阱"；其"困惑信号"命中几个，
   就把对应"澄清问法"作为**第四问叠加**。**无论命中与否**，都在 `drt_<slug>/journal.md`
   的立项行落判型痕：命中标 `判型命中=P<#>`；未命中标
   `判型未命中：<题面特征一句话>；兜底=<三分法哪类/怎么派>`（库的增长与效用计数原料，
   见库尾增长协议——不写库本体），未命中时下一步用三分法兜底 + 模型自身能力。
2. **判定研究类型与推荐方法**（给用户推荐，不让用户裸选；方法名取值 = 下节「判型 → 打法映射」，此处只记编制与 topic 形态）：
   - `quick_factual`：单一事实/数字/状态 → 通常 1 个 topic，跳过组队，subagent 直接查；
   - `exploratory_map`：领域全景/现状梳理 → scout+analyst 全流程，topic 按子领域拆；
   - `claim_verification`：验证一个说法/断言 → topic 按主张-反主张拆，反例搜索权重最高；
   - 题面是选型/对比/方案指导（含判型兜底归 exploratory_map 的 P5/P6/P7 类）；
   - 方法按映射表推，题面特征可校正（如选型题即使类型兜底归全景也推方案比较）；模式库命中条目的思考路径与陷阱仍然优先——**方法不替代判型操作单**。
3. **澄清三件事**（用 ask_user_question，每件带推荐）：
   - 研究类型（类型问卡按第 1 步命中条目或三分法拟定，附你判断的理由）；
   - 深度与篇幅（快答 / 标准报告 / 深度报告——推荐依据 = 预期检索往返：快答 = 1–2 次
     往返可答；标准 = 多源交叉的复杂学习；深度 = 长周期穷尽研究）；
   - 口径（时间范围、语言、地域、排除项）。

   澄清纪律：用户已提供的信息不再问；一次问全（结构化选项卡，不挤牙膏）；定稿进
   question.md 时未确认的维度显式标 open，**禁止脑补补全**。

   业务决策简报（信息充分性触发，不设固定第四问）：从题面与用户已给信息提取**决策对象**
   （为谁的什么决策）、**待决定事项**、**比较选项**、**期限**、**成功标准与约束**——
   用户已提供的信息直接落格不重复问；缺项先标「尚未确认」，仅当该缺项**会改变研究范围**
   （如预算上限改变盈亏比较、期限改变深度取舍）才随第四问追问；不影响范围的缺项不追问，
   研究按已确认口径推进。

   归档预检问可并入第一段卡（第四问位）：sibling 预检发现同名/前缀相关 bundle 已在
   （含 archive/）须问用户安置时，作为第四问并卡执行，不单独再打断一次——安置拍板与
   其余各问同批记入 Snapshot 澄清记录。
4. **建状态头**：新建 `drt_<slug>/run.md`（模板 `templates/run/run.md`）——`contract` = 当天日期、`phase: briefing`、`next: HITL1`、`delivered: none`、`parked: none`；阶段转换/交付/停放时更新（D28；状态是声明，事实与之冲突时以事实为准）。
5. **定稿 question.md**：模板 `templates/run/question.md`。
6. **拆 topics.md**：模板 `templates/run/topics.md`。每个 topic 必须有：
   - `must_answer`：一句话，验收时能判"答了/没答"；
   - `scope_role`：`primary`（报告主体）/ `synthesis`（跨 topic 综合）/ `comparison`（对比）/ `supporting`（背景）。
   - topic 数量 = 研究类型 × 篇幅：quick ≤1，standard 2–4，deep 4–8。
7. **计划确认卡**（HITL1 第二段；**quick_factual 免发**——类型为快速事实核查时跳过本步直接开工）：两文件 + `plan.md` 定稿后、组队/侦察开工前，把计划呈用户拍板——`ask_user_question` 瘦卡：
   - 问题正文 **≤200 字**——口径 = `ask_user_question` 的 `question` 字段**全部字符**（含业务简报行与「全文 = …」指针）：计划要点（问题定稿一句话 + 业务决策简报行〔决定 / 比较范围 / 输出形式 / 主要未知〕+ **方法行**〔推荐方法一句话 + 调整走修订〕+ topic 图骨干 + 执行图骨干（Wave / 并行数 / 最深层数 / 每 topic 深度 L0–L3）+ 深度/口径拍板）+「全文 = question.md / topics.md / plan.md」指针；
   - **呈卡前先数字数**：超限就删次要项再提交（例如逐条 topic 名压成「T1–T4」骨干、括号旁白删净），**不把超限卡递给用户**——交付门按同一口径记账超限（461 字实测 = 超限 2.3 倍，属违纪）；
   - options 三路：按计划开跑（Recommended）/ 修订计划（自由文本意见，**附加**进计划不替换）/ 放弃（不开跑，bundle 处置照 sibling 预检规矩）；
   - **一轮制**：修订意见由你逐字落 question.md §Decisions（用户原话 verbatim）后直接开工，不再二次呈卡；意见推翻类型/深度级 → 走放弃重开，不在卡上循环；
   - 拍板（含选择与修订意见）落 question.md §Decisions 第 1 条 + HITL1 Alignment Snapshot 的「计划确认」字段；
   - 用户不在场由代理模拟并显式标注"代理模拟"；跳卡直接开工 = 诚实降级不硬拦，但 journal 立项行记「计划确认卡缺席」。

## 方法预设（研究方法配置首版，2026-10-12）

方法回答"这次**怎样调查、核验、综合**"，与研究类型（研究什么形态的问题）、深度/篇幅（投入多少）互不替代。下表每个内置预设都是**调查路径默认**——用户可整档换，可用自己的话调整：

| 方法 | 给用户的一句话 | 信息源策略 | 检验策略 | 综合与呈现 | 明确不承诺 |
|---|---|---|---|---|---|
| 事实核查 | 核准具体事实/数字/状态的对象、时点与口径 | 官方/原始来源优先，第三方只作线索 | 逐字转写核对；关键来源独立重抓；单源结论显式标注 | 快答首屏：答案+口径+依据+限制 | 不做领域覆盖；"快"由深度决定 |
| 领域地图 | 摸清谁在做什么、到哪一步 | 广度优先铺方向，多类来源交叉定位阵营 | 覆盖对账：每个子域至少一条可核来源；盲点显式标注 | 地图式：分节定位+关系+时效边界 | 不把未覆盖说成不存在 |
| 主张核查 | 查证一个说法是真是假 | 对称检索：正反同权重；追原始出处 | 反例权重最高；判定四态（成立/部分/不成立/证据不足） | 判定+证据强度分级+最强反证单列 | 不预设真伪；不做只找赞同的检索 |
| 方案比较 | 把几个选项放在同一标准下比 | 各选项同维度查证；厂商资料与实际使用反馈并重 | 口径对齐才可比；价值权衡与事实分开 | 维度化对比+适用情境+取舍说明 | 不替用户决定偏好；无场景不推唯一答案 |
| 时间线与信号 | 按官方节点排时间线，用预列指标判断走到哪了 | 官方变更点（release notes／changelog／公告／生效日）为骨，媒体报道为肉；每个节点必须落在官方出处上 | 每节点带日期与出处；「现状」标注截至时刻；先列可观察指标与阈值，再下趋势判断；趋势与事实分句 | 首屏仍走既有骨架（六段或快速缩略）；正文按时间线组织（节点＋日期＋出处）→ 现状截点 → 指标读数表 → 趋势判断（显式标「判断」）→ 覆盖边界 | 不做无时间窗的预测；不把趋势判断写成事实 |

**判型 → 打法映射（推荐规则正本；面板的「推荐规则说明位」是它的投影，不另立一份）**：

| 判型模式 | 推荐打法 |
|---|---|
| P1 单点事实/状态核查 · P2 数据表/价目核查 | 事实核查 |
| P3 领域全景梳理 | 领域地图 |
| P4 断言验证 | 主张核查 |
| P5 多维对比/差距 · P6 尽调/评估 · P7 方法/方案指导 | 方案比较 |
| P8 事态跟踪/时间线 | 时间线与信号 |

未命中判型模式库时按研究类型兜底推：quick_factual→事实核查；exploratory_map→领域地图；claim_verification→主张核查；选型/对比/方案指导题→方案比较。共同底线（来源链、逐字摘录、独立信源、日期校准、缺口显式、readiness）不因方法降级；**方法只填未指定项，用户已明确的要求优先**；"研究证据综合/系统综述"类高承诺模式不在首版，用户提出时如实说明并按普通方法推进。

**确认与落格**：
- 普通 run：计划确认卡的计划要点含**方法行**——「方法：<名称>——<一句话>；要调整在修订里用自己的话说」；修订意见涉及方法 → 逐字落 §Decisions 并更新方法节，方法级调整直接开工，推翻研究形态/类型级 → 放弃重开；
- quick_factual（免第二卡）：方法 = 事实核查**自动采用**，方法节记「自动采用」+ 判型理由；运行中用户 steer 可改（记 §Decisions，不算 rerun）；
- 覆写冲突：用户要求与预设默认冲突 → 用户要求优先并显性说明取舍；不能兑现的要求如实说明，不静默忽略，不把用户立场当结论；
- 定稿落 question.md「研究方法（本次实际采用）」节（格式 = 模板）——恢复、重派、续跑只认该节，不认方法名。

**用户方法库（长期复用，显式才动）**：
- 立项先读会话 cwd 根的 `method-library.md`，**读的结果分三态，不要混成一个**（照抄观察面研究配置页签的 `libraryReadStateOf` 判据）：
  - **在场**（读回正文）→ 把其中命名方法作推荐参考（题面指定的方法/约束仍优先）；题面**点名**了某个偏好名 → 按该条目执行，并在 question.md §Decisions 记「采用库条目 X」；
  - **缺席**（文件不存在）→ 不是错误，但**不要静默**：在 HITL1 方法行或回复里说一句"偏好库还没建/还没存过偏好，本次用内置打法"，让用户知道有一个可以沉淀偏好的地方（模板随工作区种子自带，路径 = 会话 cwd 根）；
  - **读不回**（文件在但取不到：同名为目录、权限、编码等）→ **如实说"文件在但读不到"并给出原因**，绝不降级成"没有偏好"——两者对用户的含义完全不同（前者是故障，后者是空态）；
- 用户题面提到的偏好名**不在库里**时：不说"已按该偏好执行"，而是明说"库里没有这个名字，当前有这些条目：…；本次按 X 执行"，把差异摆在用户面前；
- **库条目格式（四字段，2026-10-12 detail-ux 升级）**：`## <名>（<日期>，源自 <run|对话>）〔默认偏好?〕` + 正文四行 `- 找来源: …` / `- 怎么核实: …` / `- 报告怎么写: …` / `- 不承诺: …`；旧格式（调查要求/适用说明）只读兼容，编辑该条时顺手迁移到四字段；
- **管理动词（全部显式触发，用户没说的不猜）**：**看**（"我存过哪些做法" → 列条目名 + 各一句话，不整篇倒出来）；**存**（"记住这种做法 / 以后都用 / 另存为…" → 把当次有效方法按四字段写成命名条目，文件不存在则创建；当次调整本身不自动入库）；**改**（"把 XX 改成…" 或面板发来的整条指令 `把研究偏好「X」改为：找来源=…；怎么核实=…；报告怎么写=…；不承诺=…` → 原条目原地更新为四字段并一句话回执改了什么；面板新建指令 `新建研究偏好「名」——找来源：…（基于内置「源名」调整）` → 按四字段新建条目）；**删**（"删掉 XX" → 移除条目；删的是默认偏好就照实说"下次不再有默认"）；**设默认**（"以后默认用 XX" → 该条目标注「默认偏好」——一个库至多一条，设新自动取消旧标注；默认只是推荐起点，题面指定仍优先）；
- **两个面板入口的指令形态（逐字正本；面板按此原文发送，客户端常量与本表同钉）**：
  - 起草：`我要新建一条研究打法。请先问我三个问题——① 我这一行的一手来源具体是哪些（点名到机构／数据库／官方页）② 必须带的口径字段是什么（时间／单位／币种／版本等）③ 这份报告给谁看、要什么形态与免责——拿到回答后，按四字段（找来源／怎么核实／报告怎么写／不承诺）起草一条命名条目写入我的偏好库，并一句话回执你写了什么。` → 行为：三问一次问全（结构化选项卡）→ 按四字段起草写库 → 一句话回执写了什么；
  - 沉淀：`把本次研究实际采用的做法存成研究偏好——从 question.md 研究方法节、evidence 的来源分级分布与 final.md 的结构归纳出四字段，写入我的偏好库；一句话回执，并说明它与最接近的内置打法的差异在哪。` → 行为：读三处（本次方法节／证据分级分布／报告结构）→ 归纳四字段写库 → 回执含「与最接近的内置打法的差异」；本会话没有绑定 run 时如实说明，不臆造来源。
- 库 = 本工作区用户数据（Lead 维护），无版本史、无跨设备同步；库内容只作推荐参考，不回写旧 run。

**领域示范：一条厚条目长什么样（只读示范，不给判型推荐）**——行业差异落在四处内容（一手源是谁／口径必带什么／冲突怎么裁／工件与免责），下面这条演示这四处**该写多细**：一手源点名到渠道、口径写到条款号、工件与免责写明边界。它是体例示范，**不是按判型推荐的方法**；抄体例，不抄内容（换成你自己行业的渠道与口径）。要点逐条有一手出处，核实记录 = `_backlog/research/2026-10-18-method-config-ux-external.md`。

`## 投研尽调（示范）（2026-10-18，源自外部核实）`
- 找来源: 一手件按渠道点名——A 股招股书看证监会《格式准则第57号》与交易所网站；港股看港交所《Guide for New Listing Applicants》（2023-11）与披露文件；美股看 SEC EDGAR 的 10-K／10-Q／8-K；主体与股东信息看国家企业信用信息公示系统（《企业信息公示暂行条例》第六条）。注意：工商年报里资产总额、营业收入等由企业选择是否公示，不能当财务底稿。

- 不承诺: 不构成投资建议；不给目标价与评级；不替代尽调程序（函证、访谈、现场核查）；工商公示信息不等于经审计的财务底稿。

## 判据

- question.md 写完时，一个不了解上下文的读者能复述"这次研究要回答什么"；
- 每个 topic 的 must_answer 无歧义（没有"大概/相关/等等"）；
- 澄清动作发生过且有记录（写进 question.md 的 HITL1 Alignment Snapshot 节）——没有澄清的立项是返工之源；
- 计划确认卡发生过且拍板落 §Decisions（quick_factual 除外）——开工前用户已见过具体计划；缺席 = journal 立项行记账。

## 反模式

- 不查模式库直接拍类型（库命中时弃用条目 = 丢掉沉淀的思考路径与陷阱清单）；
- 一次问超过三件事（用户疲劳，随便答；困惑问只叠命中信号的，有几问叠几问、没有就不加）；
- topic 拆成关键词而不是问题（"芯片制程" ❌ → "国产 AI 芯片当前制程能力与代差是多少" ✓）；
- 把 scope_role 全标 primary（没有主次的报告没有结构）；
- 定稿即开工、跳过计划确认卡（quick_factual 除外）——用户第一次见到具体方向就变成 v1 交付，跑偏成本在烧掉之后才暴露。
