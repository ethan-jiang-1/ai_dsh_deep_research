# synthesis — 综合

证据回来后的写作纪律。核心：**先纯综合，后定向补搜**——一次性把已有证据榨干，再决定值不值得再搜。

## 流程

1. **纯综合（禁止新搜索）**：通读本 run bundle（drt_<slug>/）的 evidence/ 全部文件与 topics.md，写 findings.md——每个 finding 一行：结论 + 支撑证据文件 + gap 状态（`supported` / `needs_search` / `contradicted`）。
2. **gap 定向补搜**：只对 `needs_search` 的 finding 派一次定向任务（给 analyst 或 subagent，说清找什么、什么算找到）。补完更新 findings.md，**只补一轮**——补了还缺就把该 finding 标 `insufficient` 并在报告里如实呈现。**未取得 ≠ 没有**：拿不到的项，报告里只能落「未取得/无法判定」（写明试过的渠道），**禁止转写成「没有/不提供」**——取证可达性不对称是常态（cn-dr-products 实证：洋厂商一手定价页全域 403，"查不到"进无法判定类），查不到 ≠ 官方没有。
3. **写 run 根 final.md 当前版**（首版另落 final/v1.md 记账）：**决策摘要首屏先行**——六段：
   答案/建议及适用条件（成立条件、口径、有效期；证据不足以支撑建议时如实写
   「目前不能判断」及原因，**不硬给唯一推荐**）→ 备选与取舍（比较依据不足不排序、
   不说服）→ 关键依据（2–4 条最强依据，每条附 `[来源: evidence/<file>.md]`，标来源
   等级 A–D 与关键口径）→ 最强反证（不抹平）→ 目前不能判断（insufficient 如实列出 +
   试过的渠道）→ 下一步（后续动作/待用户输入；未获用户指定的负责人/期限标**「待定」**，
   不编造）。之后按 topic 主体论述 → 来源清单（全部 evidence：路径 + 一句话说明 +
   retrieved_at；来源发布日期以摘录口径为准）。**快速事实型 run 首屏缩略**为
   答案 + 口径 + 依据 + 限制，不强行填满业务选项表。
4. **来源链格式**：每条关键结论后附 `[来源: evidence/<file>.md]`；来源清单节列出全部 evidence 文件（路径 + 一句话说明 + retrieved_at）。
5. **交 critic**：review.md 拿到 readiness: PASS 后，才向用户提交审阅建议（HITL2）。
   呈卡前核对 plan 的 `task_id` 列：每个 active 节点已有真实 `task-N` 或显式 `plan-only`——
   空行会让研究图谱只显示「状态未知（未映射 task_id）」，别留给用户看图才发现（BUG-043）。
   HITL2 卡片的**审阅摘要 ≤ 200 字**（约 4 行）——完整分析进 report 正文或 journal，卡片题干只留
   判决所需（结论一句话 + readiness 状态 + 最大残留）。实测依据（八场 77 张卡）：HITL1 卡全部
   ≤ 400 字无事故；6 张超长卡全是 HITL2（最长 1280 字），把选项挤出视口、人要滚动才能答题。
   **发出前自检**：摘要超 200 字 = 违纪，删到 4 行以内再发（执行方差实证：第八场 576 字部分遵守）。
   用户拍板后（无论定稿/补研究/修订哪支）**第一动作 = 回写记账**：把拍板行追加进 question.md 的
   Decisions 节（append-only、最新在上，写明拍板内容与版本走向）——这是交付门③的机械判据
   （G8 #③ 实证：缺席会被操作侧代补，救场计数因此下不去）。先记账，再落 run 根 final.md 与 present。
   **同 bundle 证据扩张 rerun**：拍「补研究」后在 question.md 标题下加一行
   `> rerun: v<N+1> · evidence-expansion · 日期 · 触发：<一句话>`，交付时落 `final/v<N+1>.md`
   版本账再写 run 根 `final.md` 当前版 + present；`final.md` 是工作稿，`final/vN` 才是版本账。
6. **交付前溯源自审（2026-09-27 定稿）**：出处链审查交给 critic 的**独立重抓**——对关键
   `source_url` 逐个 `web_fetch` 重新取回、逐格核对内容真实支撑（第六/八场实测这是比脚本更强的
   判据：验证的是内容，不只是"URL 出现过"；第八场 critic 重抓 23 URL、比对 340 格，0 误差）。
   **角色会话内没有任何命令执行能力**（无 bash/node，2026-09-27 实测：审计脚本在会话内跑不了，
   子代理也一样——别派"跑脚本"的任务）；机械审计 `scripts/run-gates/evidence-audit.mjs` 由**操作侧**在
   交付后运行，发现落 bundle 的 `audit.md`。

## 判据

- findings.md 里没有 `contradicted` 被静默忽略（矛盾证据必须呈现）；
- 每条关键结论的 [来源: …] 指向真实存在的 evidence 文件（critic 会逐条猎）；
- 报告呈现了"我们不知道什么"（insufficient 清单），不是假装全知；
- 首屏每条建议能沿 [来源: …] 追到真实证据文件——决策摘要不是独立于证据的评论；
- 「目前不能判断」出现在首屏时，是写明渠道的结论，不是被跳过的思考。

## 反模式

- 边写边搜（写作与搜索混流 = 证据碎片化，永远写不完）；
- 抹平分歧（两个来源打架时各打五十大板或取其一而不呈现冲突）；
- 把 C/D 级来源当关键支撑；
- 用首屏格式齐全冒充证据充分（六段写满 ≠ 建议成立——每段仍按 [来源:] 链判）；
- 把预测假设写成事实（预测必须标假设与口径；证据不足就写「目前不能判断」）。
