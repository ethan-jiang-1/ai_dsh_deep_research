# lead-mapping — 广度侦察

Scout 的核心方法论。目标：用最小的搜索成本，画出"答案可能在哪儿"的地图。你面对的信噪比极差——处置纪律就是你的生产率。

## 搜索纪律

1. **query 多样化**：同一概念至少三轮——同义词轮（中文措辞变体）、语言轮（英文/行话术语）、视角轮（支持方怎么说、反对方怎么说、中立观察者怎么说）。
2. **30 秒去留判**：每条结果限时判断——标题+摘要+出处三看，任一看不上就丢。丢要快，犹豫本身就是浪费。看上的才 web_fetch 抓全文。
3. **排除要显式**：搜过而排除的方向，在 leads.md 记一行"已排除 + 一句话原因"。静默放弃 = 下个人再搜一遍。
4. **URL 必须真实**：只记录你真实抓取过的 URL；凭记忆写 URL 是伪造来源，一票否决。

## 质量分级（每条 lead 必标）

| 级 | 定义（判**内容质量**，不判信源身份） | 用途 |
|---|---|---|
| A | 关键事实完整且口径明确 | 可支撑关键结论 |
| B | 内容可靠但覆盖/口径有缺 | 可支撑关键结论（需交叉） |
| C | 侧证、口径不明或转述二手 | 只做背景与线索 |
| D | 未验证 / 孤证 / 社区传闻 | 默认弃用；唯一来源时标"待验证" |

信源**身份**（一手官方/权威二手/行业/论坛）另记 `source_tier` 字段（primary/secondary/
tertiary/weak，判据表在研究手册）——quality 判内容、tier 判身份，两维独立评级。

## 检索器对账（每条 lead 必标）

实测依据（2026-09-26 三场 run）：**检索器选择、而非模型本身，是深度研究能力的主导变量**——仅换
检索器就能动 14–21 个百分点。所以"没找到"可能是"这个检索器看不见"，不是"不存在"。对账纪律：

- 每条 lead 标注它经由**哪个检索器/来源域**可达（官方域 / 主流搜索引擎 / 学术检索 / 代码托管站 / 行业垂直站）；
- 只有单一检索器路径可达的，标 `单检索器——待破`（与单源同构的显性缺口）；
- 同一现象跨检索器可达的方向**优先推荐**——主编据此判断覆盖面，而不是替主编猜。

## leads.md 格式

**交接不变量**（门 L 机械把守）：leads.md 必须含 ≥1 个**字段齐的方向单元**——任意层级
（##/### 皆可）的节，每节带字段行：状态（建议挖深 | 已排除（原因））、支持来源（带 A–D
分级）、检索器、关键线索、建议 owner（对应 topic: <topic>）；门 L 机械把守其中状态/支持
来源/关键线索/建议 owner 的最低在场集。0 个字段齐单元 = 门 L RED（防空语料）。

**组织轴按题型分形**（门不判轴，轴是你的专业判断）：方向轴（`## 方向: <一句话假设>`）适合
开放 landscape；实体轴（`### <实体名>` 每实体一节）适合实体边界题；题面前提校验段可放在
方向节之前——轴可以混用，**字段行是硬契约，节级标题措辞不是**。

```
## 方向: <一句话假设>        ← 或 ### <实体名>（实体轴同样合法）
- 状态: 建议挖深 | 已排除（原因）
- 支持来源: [URL]（A/B/C/D）×N
- 检索器: <官方域 / 主流搜索 / 学术 / 代码托管 / 垂直站>（单一可达则标：单检索器——待破）
- 关键线索: <来自哪个来源的哪句话>
- 建议 owner: analyst（对应 topic: <topic>）
```

## 定稿自检（交稿前三对账）

1. **计数对账**：写进 leads.md 的每个数字（条数/计数）必须是自己逐条点数过的，或有证据卡
   依据——不确定就不写数。实证（2026-09-29 mcp-server-ecosystem CRITICAL-2）：写了"14 条"，
   自己的证据卡与 findings 都是 13（14 是另一个仓库的数），critic 判词"这不是分歧，是同一
   文件的内部不一致"。
2. **口径差异回改**：点数发现来源间口径差异，必须当场回改 leads.md 对应行——差异记在证据
   卡里但没回改 leads.md 等于没改（同上实证：registry-06 已记差异、表格残留错数，而
   leads.md 是 analyst 抽数入口，错数直接传染下游）。
3. **覆盖对账**：对照 topics.md 数一遍——每个 primary/comparison topic 至少一条"建议挖深"
   lead 指向（标题或 owner 行标对应 topic）；node-gate 门 L 按同一判据机械把守，先自检省
   一轮门红。

## 覆盖记录（每次交稿必附）

leads.md 末尾加一段，回答“这次宽搜覆盖到哪”：

- **query 家族**：同义 / 语言 / 视角各跑了什么；没跑的说没跑。
- **检索器**：官方域 / 主流搜索 / 学术 / 代码托管 / 垂直站，各自覆盖了什么。
- **tier 分布**：primary / secondary / tertiary / weak 各多少条（自己点数）。
- **已排除**：方向 + 原因（与单元行一致）。
- **未覆盖 / 已搜未得**：子域 + 渠道 + 结论；“没找到”不是“不存在”。
- **待破标记**：`单检索器——待破` / `单源——待破` 逐条可见。

## 反模式

- 在一个方向上深挖（你是广度职能，深度是 analyst 的事）；
- 收集而不分级（没有分级的 leads.md 是垃圾场）；
- 只搜支持性关键词（反对方的措辞往往才是金矿）。
