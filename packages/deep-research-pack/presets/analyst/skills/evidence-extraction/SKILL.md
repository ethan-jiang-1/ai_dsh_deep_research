# evidence-extraction — 深度挖掘

Analyst 的核心方法论。目标：把方向变成**可核查的证据文件**——每条证据独立成档，身份链完整，主编综合时不需要重新读原始网页。

## 工作节奏（question-list 驱动）

每个 topic 开工时列问题清单（Question List）：把 must_answer 拆成具体可搜的问题。逐问题找证据；新发现催生的新问题**追加进清单**，答完的划掉。清单落在 evidence 文件的问题区，演进过程保留（划掉的留痕）。

## 证据文件格式（每条证据一个文件，`drt_<slug>/evidence/<topic>-<slug>.md`）

```
---
source_url: <被你 web_fetch 成功取回的 URL——搜索结果里看到≠抓取过，要引用就先 fetch>
source_tier: <primary/secondary/tertiary/weak——信源分级，判据表在研究手册>
publisher: <注册域>
retrieved_at: <YYYY-MM-DD>
quality: A|B|C|D
found_by: analyst
supports: <topic id>
---

## 原文摘录
> <原句，逐字，可多段；数字/日期/单位必须逐字保真；数字/规格类摘录须带口径（测量条件：版本/配置/时间/原文限定语至少两项，口径不明写"口径不明"）>

## 解读
<你的推理与初步判断；结论性的写"初步判断（待主编综合）">

## Question List（本 topic 的清单，随演进更新）
- [x] <已答的问题>（答案一句话 + 指向哪段摘录）
- [ ] <待答的问题>
```

**摘录与解读必须分开**——把解读写成引文是伪造证据，critic 一票否决。

**摘录硬规则**（研究手册 §证据文件契约 · 摘录最小契约；evidence-audit 机检，违反 = MAJOR 单列）：

- **引文行只放原文**——你自己的标注（标签、URL、`（同上，Table N）`、`旁证｜…`、`说明：…`）
  不进 `>` 行，写在引文块外面或解读节；
- **多段摘录逐段逐字**：每段独立一行 `>`，段间省略写 `[…]`；不把来源里不连续的句子拼成一段；
- **表格按单元格摘录**：每格一行 `>`，不整行/跨行合并；
- **`source_url` 必须真实抓取过**：是你 `web_fetch` 取回的 URL——搜索结果里看到 ≠ 抓取过，
  要引用就先 fetch 它（40 卡规模实测滑过 3 张，规模越大越要盯）；
- **`retrieved_at` 不得凭时间感直写**：按研究手册日期最小契约取校准信号（web 响应/页面自带日期优先，其次 `web_search` 结果行括号里的发布日期、用户消息与既有 run 文件已落笔日期），无法校准如实标「日期不确定（依据：…）」；
- **表格逐格一行**：不整行/跨行合并抄写（规模上来后最容易滑的一条）。

## 交叉验证与反例

- **关键 claim**（直接支撑 must_answer 的）：≥2 个**独立**来源；同一机构的转载不算独立。验证结果写进解读节（"与 <文件> 交叉一致/不一致"）。
- **单源关键数字**：第二源破不了时，解读节显式标 `单源——待破（试过的第二源渠道：<渠道>）`——不标就是隐匿缺口，critic 按此打回。
- **反例搜索**：每个关键结论专搜一轮"它不成立的证据"（反例词 / 争议 / 批评 / 更新更正）。找不到也要记："已搜反例（<query>），未见"——这本身是证据。
- **定向补搜用算子**（query 逐字进 DeepSeek Search API）：`"<claim 原句>"` 锁原文、`site:` 锁一手域或对手域、`after:` 锁版本更新、`-site:` 排掉自家域名与转载站；`已搜未得` / `已搜反例` 记**完整 query（含算子）**——只记关键词复现不了，也审不出是不是真搜过。
- **已搜未得**：按问题清单搜不到的，如实记 `已搜未得（渠道：<query/渠道>）`——与"已搜反例，未见"同构，如实缺口本身就是证据；挖不到不是失败，假装挖到了才是。

## 深度记录（每条证据卡的解读节）

“解读”节除推理外，必须留一段可核的深度记录——不是勾选框，是审阅者能复核的事实：

- **一手链**：claim → 二手/转述 → 原始出处（官方 spec/论文/财报/原始数据；版本/文号）；
  追不到就写“未取得，渠道：…”，不静默。
- **独立来源**：与哪张卡/哪个注册域交叉；同一通稿/转载链不算独立。
- **反例**：反例 query + 结果；“已搜反例，未见”也算记录。
- **口径**：测量条件（版本/配置/时间/原文限定语 ≥2；不明写“口径不明”）。
- **清单**：question-list 的 `[x]` / `[ ]` 与未答原因；新问题追加，不覆盖旧问题。

## 反模式

- 一个文件塞多条来源（身份链断裂，主编没法引用）；
- 摘录改写原文措辞（保真失败 = 证据失效）；
- 只记支持性证据（反例缺失的报告会被 critic 打回）。
