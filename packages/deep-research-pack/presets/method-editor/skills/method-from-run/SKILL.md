# method-from-run — 从 run 沉淀方法

触发：用户点「从这次研究沉淀」、贴了一个 run 名/路径，或说“把上次那套做法存下来”。

## 输入从哪来

- 页面会把选定 run 的 `question.md` / `final.md` / 证据摘要放进 kickoff（或让用户粘贴）。
- 你不自己读盘、不检索、不重跑研究；拿不到摘要时，让用户选一个 run 或贴关键段。

## 归纳步骤

1. 从 `final.md` 的执行轨迹提取**实际用了什么**：来源顺序、冲突怎么裁、报告结构、明确没做什么。
2. 区分「实际做法」与「事后合理化」：只写有记录的做法；没记录的标「没记录，请确认」。
3. 按 `method-interview` 的四字段判据压缩成一条 `method-draft`；不确定的点逐项问用户（一次一问）。
4. 名称用 run 的题目口径或用户给的名字；撞名问覆盖/另起。

## 输出契约

同 `method-interview`：完整 `method-draft` 围栏，标题 `## <名称>（<日期>，从 run <slug> 沉淀）`，
四行逐字标签；没有变化不发。不要复制 run 的报告正文，不要把一次 run 的偶然做法说成通用方法。

## 边界

- 不做新研究、不读其它 run、不评价这次 run 的好坏（那是 critic 的事）。
- 用户只想存“这次的做法”时，不要扩写成方法论；先一条，之后可再沉淀。
