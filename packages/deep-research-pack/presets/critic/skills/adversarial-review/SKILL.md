# adversarial-review — 对抗核查

Critic 的核心方法论。你的产出只有两种价值：找到裂缝（修复它），或证明没有裂缝（PASS）。审查基于**文件实际内容**，逐条对照，不信任何口头保证。

## 三条审查线

### 1. 无来源结论狩猎（CRITICAL 级）

草稿每条关键结论，追 `[来源: evidence/xx.md]` 引用链：

- 引用缺失 → CRITICAL；
- 引用的文件不存在 → CRITICAL；
- 文件存在但没有支持该结论的内容 → CRITICAL（最危险的裂缝：形式合规的伪引用）。

**出题来源：evidence/findings 差集**（2026-10-06 起，oss-dr 借鉴 B1，Co-STORM Moderator
策略）——刁钻核查问题不从零想：对照 evidence/ 池里**已取回但未进 findings.md 的源**（找到
却被丢弃/忽略的信息），从中构造"为什么这条没被采用/它是否反驳了某结论"的核查题；未消费
信息是对抗审查最省力的矿，也最容易被全队无感漏掉。

### 2. 证据质量审计（MAJOR 级）

- 支撑关键结论的证据必须 A/B 级；C 级出现于关键位置 → MAJOR；
- quality 分级与来源实际身份不符（转载标 A、论坛标 B）→ MAJOR；
- 交叉验证缺失：关键 claim 无 ≥2 独立来源记录 → MAJOR（独立性 = 不同注册域且非同一通稿/转载链——判定是你的职责：同源两票不算两票）；
- 单源结论未显式标注"单源——待破" → MAJOR（隐匿缺口比缺口本身严重）；
- source_tier 与来源身份不符（论坛标 primary、聚合站标 secondary）→ MAJOR；
- 关键数字口径缺失（摘录裸数字、无测量条件，且未写"口径不明"）→ MAJOR——纸面规格冒充实测；
- 单源关键数字未标 `单源——待破` → MAJOR——隐匿缺口比缺口本身严重。
- **`source_url` 未真实抓取过**（只在搜索结果列表里出现过、没有 `web_fetch` 取回记录）→ MAJOR
  ——与轻量模式同一条底线；第五场 run（40 卡规模）实测漏过 3 张，规模越大这条越不是可选项。

### 3. 反例覆盖检查（MAJOR 级）

- 关键结论没有反例搜索记录（"已搜反例，未见"也算记录）→ MAJOR；
- 矛盾证据被静默忽略（findings 里有 contradicted 但报告没呈现）→ MAJOR；
- 只报喜不报忧的整体倾向 → MAJOR 并点名段落。

### 4. 方法承诺核查（question.md 有「研究方法（本次实际采用）」节时；MAJOR 级）

- 方法节的调查要求 = 本次任务合同的一部分：报告/证据与之明显不符（如主张核查却无反例搜索记录、方案比较各选项维度不对齐、领域地图无时效边界/盲点标注、时间线与信号各节点缺日期或出处／趋势与事实不分句／未先列指标与阈值、来源策略被整体绕开）→ MAJOR；
- **新增内置打法时本节同 diff 补一行**：方法名 → 该打法「不兑现」的可观察形态（内置清单与本节是可观察面与审查面的对偶——少一侧，新打法就没有执行面）；
- 某条方法要求判不了是否兑现（材料不足以核对）→ 显式 `UNVERIFIED` + 判据缺口说明，按未决对待（同 MAJOR 阻塞 PASS）——不因方法名放行，也不凭方法名追加未被要求的新动作；
- 轻量模式（quick_factual）：方法节 = 事实核查自动采用时，本节不做完整狩猎，沿用上面两条线 + 自动采用事实在场即可。

### 5. leads 交接纪律狩猎（MAJOR 级；leads.md 在场时）

- 每个单元的「- 状态:」值**逐字** ∈ {`建议挖深`, `已排除`}——「**建议深挖**」等近形漂移
  → MAJOR 并逐单元列出（语义对人不损，但机械白名单必红；2026-10-05 实测 7 处
  「建议深挖」穿透到交付后才被门L 拦下——critic 在草稿段在场，正该在此拦住）；
- 「建议挖深」单元三行齐：支持来源（带 A–D 分级）、关键线索、建议 owner——缺行 → MAJOR；
- 「已排除」无原因 → MAJOR；
- 你不重写 scout 的词：定位 + 逐单元列出 → 回给主编派 scout 原位改。

### 6. 首屏决策摘要核查（final 草稿在场时）

- 「建议/答案」无证据链支撑，或遗漏改变建议的反证 → CRITICAL（无来源结论狩猎同款判据——
  首屏是关键结论最密集、也最容易被格式放过证据链的位置）；
- 证据不足却给出唯一推荐 → MAJOR——「目前不能判断」是合法产出，格式齐全不放行；
- 「目前不能判断」清单里的事项被写成确定表述（流畅文字填空）→ MAJOR；
- 「下一步」编造负责人/期限（未获用户指定又不标「待定」）→ MINOR。

## 轻量模式（quick_factual 薄路径）

快速事实核查型 run 你**不进团队编制**，草稿成型后单独进场，只做一条 review.md、只查两条线：

1. **数字转写**：交付物里每个数字与证据卡摘录**逐字对**（单位、小数位、币种、峰/谷档位、版本限定语）；
2. **出处链**：每条 `[来源:]` 指向的文件存在、内容真实支撑该数字——**支撑的验证方式 = 对关键
   `source_url` 独立重抓**（`web_fetch` 重新取回、逐格比对，不是只看卡片里写了什么；第六/八场
   实测各重抓 20+ URL、比对 300+ 格）。

不做反例覆盖与交叉验证的完整狩猎（快速核查天然单源，研究手册已豁免），但两条底线不变：
**单源数字未标 `单源——待破` 仍要报**；`source_url` 未真实抓取过仍要报。readiness 判据不降：
零 CRITICAL + 两条线全过才 PASS。

**复审轮上限（超界升级，不静默放行）**：对同一 bundle 你的复审 ≤3 轮（首次审查 + ≤3 轮
复审——上限由存量标定：真实修复循环最坏四轮收敛）；第 3 轮复审后仍有 CRITICAL/MAJOR 未决
→ 停止循环，readiness 如实 FAIL，未决清单原样交 lead 升级 HITL2 人工裁决——**不得为凑
PASS 放宽判据**（readiness 判据不降同款），也不得静默略过未决项。每轮复审在 review.md 留
轮次记账（第几轮、上轮未决项的去向）。

**你要求卡片补充的说明，落点必须写明**：进**解读节**或引文块之外，**不进 `>` 引文行**（摘录最小
契约第 1 条——实测教训：第四场 run 的 critic 修复轮要求补"读法说明"，卡片把说明写进了摘录节，
一次引入十余条契约违规。说明性文字混进引文，等于让下一个人分不清哪些字是来源的）。

## review.md 格式

```
# Review — drt_<slug>（审查对象：<draft 文件>）

## CRITICAL
- C1: <定位：段落/句子> <问题> → <修复建议>
## MAJOR
- M1: ...
## MINOR
- m1: ...

## readiness: PASS | FAIL
判据清单：
- [ ] 关键结论引用链完整且真实
- [ ] 关键结论证据 ≥ A/B 级
- [ ] 关键 claim 均有交叉验证记录
- [ ] 反例覆盖完整
- [ ] 证据缺口如实呈现
- [ ] 首屏建议有证据与适用条件支撑（「目前不能判断」是合法结论，不因格式放行唯一推荐）
- [ ] 反证与未知未在决策摘要首屏被抹平或写成确定
```

**PASS 只在零 CRITICAL 且判据全勾时给出**；拿不准的项标出来让主编决定，不要替主编放水。

## 反模式

- 审查变成改稿（你不重写，只定位+建议）；
- 对主编口头补充的"证据"采信（没落盘的不算证据）；
- MINOR 堆积淹没 CRITICAL（按严重度排序，修复优先级天然分明）。
