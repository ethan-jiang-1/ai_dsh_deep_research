# question-patterns — 判型模式库（HITL1 第一对照面）

> 用途：lead 立项时的**第一对照面**——接到研究请求，先在本库找命中模式；命中 → 走该条
> 目的思考路径与分派结论；未命中 → 三分法兜底（research-brief skill）+ 模型自身能力，
> 并在 journal.md 记标记行（见库尾"增长协议"）。本库**从不以穷举为验收**——验收是：
> 常用题有模板、陌生题有兜底、漏过的能长回来。
>
> 每条目六段固定骨架：**识别特征**（怎么看出来是这类）/ **思考路径**（拿到这类题先想
> 什么、再排除什么）/ **分派结论**（类型问卡话术 + 深度 + topic 骨架 + 花名册 + 通道）/
> **陷阱**（这个模式下的典型错误）/ **困惑信号**（什么情况说明题没谈清）/ **澄清问法**
> （对每个困惑信号，反逼用户的那一问，带推荐）。困惑问是**触发式加问**——命中信号才
> 加，叠在 HITL1 固定三问之上（三问保底，不替代）。

## P1 · 单点事实/状态核查

种子：drt_dsh-release-watch（版本状态 + 转正判定）。

- **识别特征**：一个事实、数字或状态的确认；题面常带"当前/最新/是否已经"；答案形态 =
  一个值或是否判断 + 可点开的官方出处。
- **思考路径**：①这个事实的**权威源是谁**（官方 release 页 / registry / 标准文档——先定
  源再动手）②时效要求多高 → 一切以**抓取当刻**为准 ③口径陷阱排查（"发布"含不含
  alpha/pre/rc？"最新"指稳定版还是任意 tag？）④单源合法性：quick 型天然可单源，但
  **状态类判定**（"是否转正"）要官方文档 + 公告双路。
- **分派结论**：类型问卡 = 快速事实核查（Recommended）；深度 = 快答；topic ≤1；**不组
  队**——one-shot subagent 直查 + 轻量 critic ×1（草稿后进场，只查数字转写与出处链）；
  篇幅 1–2 屏。
- **陷阱**：把多子问的状态题当纯快答（release-watch 其实两问——任务书要点名几个子问，
  每问都要有出处）；口径含糊不界定（"发布过"默认含 pre/rc，除非用户另说）；第三方转载
  页当官方源。
- **困惑信号**：「最新」的基准时刻不明；「是否 X」的判定标准不明（什么算数什么不算）。
- **澄清问法**：「最新」以什么时刻为准？（推荐：以抓取当刻为准）；判定标准含不含
  pre/rc/alpha？（推荐：含——宁可多报再筛）。

## P2 · 数据表/价目核查

种子：drt_deepseek-api-pricing / drt_kimi-api-pricing / drt_qwen-dashscope-pricing /
drt_zhipu-api-pricing（**跨 run 复现 4 次**——本库最早的自证模式）。

- **识别特征**：要的产出是一张**表**——多实体 × 多字段数字；题面常带"各/逐个/分别 +
  单价/费率/规格 + 官方"；下游用途多是成本估算、账单对账。
- **思考路径**：①先定**表的列定义**（要哪些字段——比价就要输入/输出/缓存三档单价 + 免费
  额度）②权威源 = 官方定价/规格页一锤定音，第三方比价站只当线索 ③口径纪律最重：每格
  标抓取时间，数字逐字保真，币种/单位/阶梯价抄全 ④多实体 = topic 按实体族拆，每格出处
  链独立。
- **分派结论**：类型问卡 = 快速事实核查（数据表档，Recommended）；深度 = 快答偏标准；
  topic 1–3（按实体族）；scout 极轻或省（官方域直达）；analyst ×1（逐格摘录）+ critic
  ×1 轻量（偏数字转写与出处链）。
- **陷阱**：第三方汇总页当源（口径旧、混币种）；阶梯价抄半截（首档价当全量价）；缓存
  计费字段漏列；免费额度漏问。
- **困惑信号**：字段范围不明（要不要免费额度/按次档？）；实体范围不明（全系列还是主力
  款？）。
- **澄清问法**：表格要哪些列？（推荐：输入/输出/缓存三类单价 + 免费额度，可增删）；
  覆盖全部模型还是主力款？（推荐：当前可调用的全部）。

## P3 · 领域全景梳理

种子：drt_cn-llm-deep-research / drt_cn-dr-products；三分法 exploratory_map 升级。

- **识别特征**："现状/全景/格局/主流方案有哪些"；开放面大；产出 = 一张**地图**（谁在
  哪、做什么、到哪一步），不是判断。
- **思考路径**：①先定**地图的分节轴**（按技术层切 / 按玩家切 / 按阶段切——用途决定切
  法）②每个子领域 = 1 topic，must_answer 锚"谁在做什么、到了哪一步"（可判答）③广度
  优先：scout 铺完方向再挖，不逐条深挖 ④地图要**边界标注**：覆盖到哪、明确排除什么、
  时效截至。
- **分派结论**：类型问卡 = 探索性全景（Recommended）；深度 = 标准/深度；scout ×1 +
  analyst ×1–2（按 primary topic 数）+ critic ×1；topic 2–5 按子领域拆，scope_role 有
  主次（禁全 primary）。
- **陷阱**：全景变罗列（只有清单没有定位与关系）；无主次的平铺；地图无时效标注（读者
  不知道画的是哪个时点）。
- **困惑信号**：地图的**用途**不明（支撑什么决策——决定分节轴）；范围边界不明。
- **澄清问法**：这张地图主要支撑什么决策？（按题给推荐）；边界上要不要含 X？（X = 题面
  提到但可排除的子域）。

## P4 · 断言验证

三分法 claim_verification 升级。

- **识别特征**："听说/据说/有文章说 X，真的吗"；产出 = 判定 + 证据强度分级。
- **思考路径**：①把断言**还原成可判定的精确命题**——先追原始出处（二手转述的断言常
  变形）②主张-反主张双线找证据，**反例权重最高**——ACH 纪律：列全竞争假设，优先找
  **区分性**证据（能排除某个假设的一条证据，比再多支持性证据更有价值）③判定四态：
  成立 / 部分成立 / 不成立 / 证据不足——"证据不足"是合法结论，不是失败 ④断言里的数字
  做口径核对（转述链上数字最易漂移）。
- **分派结论**：类型问卡 = 主张验证（Recommended）；深度 = 标准；scout ×1 + analyst ×1
  （首份任务书点名"反例权重最高"）+ critic ×1 **必配**（验证类最容易自嗨）；topic 按
  主张-反主张拆。
- **陷阱**：确认偏误（只找支持证据就收工）；断言原始出处不追；**伪快答**——争议口径的
  "数字题"（"X 是不是只花了 N 钱？"）表面像 P1，实为 P4：单源即错，必须双源破口径。
- **困惑信号**：断言的精确版本不明（哪个口径、哪个时间点、谁说的）；判定基准不明。
- **澄清问法**：这个说法你最初在哪看到的？（帮助锚定原始出处）；判定标准——部分成立
  算不算成立？（推荐：分维度判定，不整体二值）。

## P5 · 多维对比/差距

种子：drt_cn-us-cpu-gap / cn-agentic-parity / cn-us-open-model-ecosystem（复现 3 次）+
边界题 B1（CRDT vs OT）。

- **识别特征**："A 与 B（与 C…）比/差距多少/怎么选"；多实体 × 多维度；产出 = 维度化对比
  + 结论（选型或差距判断）。
- **思考路径**：①**维度框架先行**（比什么——性能/生态/成本/自主度…维度决定 topic 拆
  分）②每个维度内先对齐可比口径（版本/基准/时间点对齐才可比）③趋势问句（差距在收窄
  还是固化）是加分项，单列一问 ④"怎么选"必须回扣**使用场景**——没有场景的选型推荐是
  空话。
- **分派结论**：类型问卡 = 对比评估（Recommended；兜底归探索性全景）；深度 = 标准/深度；
  scout ×1 + analyst ×1–2（**按维度分派**，不按实体）+ critic ×1；topic = 维度数 + 1
  综合（synthesis）。
- **陷阱**：口径不对齐的对比（拿 A 的旧版比 B 的新版）；单一维度定全局；选型题不给场景
  就推答案。
- **困惑信号**：维度清单不明；使用场景不明（选型必答）；对比基准时刻不明。
- **澄清问法**：最关心哪几个对比维度？（推荐：题给维度收窄到 3–5）；选型的话用来做
  什么——什么场景？（选型必答，无推荐——用户才知道）。

## P6 · 尽调/评估

种子：drt_siliconflow-financials（含"前提级发现"教训：主体已递表，问题前提部分失效，
中途才挖出）。

- **识别特征**："这家公司/项目/产品靠不靠谱 / 是否值得投入 / 在上升吗"；产出 = **证据
  分级的方向性判断**（上升/停滞/下行 + 支撑面与削弱面），不是估值。
- **思考路径**：①**前提核查先行**——主体的官方状态（上市/递表/融资/歇业？）第一波就
  查：前提变了整个框架要重搭（siliconflow 教训：这事不能等 scout 挖到才知）②先立证据
  分级框架（硬证据〔审计/官方文件〕vs 自述 vs 第三方转述），产出里三级分开 ③两面强制：
  支撑面 + 红旗削弱面都要有，只写一面 = 未完成 ④结论 = 方向 + 置信声明；口径冲突标
  "待破"。
- **分派结论**：类型问卡 = 尽调评估（Recommended；兜底归探索性全景）；深度 = 深度；
  scout ×1 + analyst ×2（支撑面/风险面各一）+ critic ×1；topic = 面（资本/运营/竞争）
  + 判决（synthesis）。
- **陷阱**：前提不核（最大坑）；公司自述当硬证据；只写支撑面成宣传稿；给精确估值（数据
  不支撑的精度是伪造）。
- **困惑信号**：评估**用途**不明（投资/采购/合作/盯盘——决定哪些面要挖多深）；时间窗口
  不明。
- **澄清问法**：评估用于什么决策？（推荐：方向性投入判断，不做估值）；时间窗口？
  （推荐：近 18 个月为主）。

## P7 · 方法/方案指导

种子：drt_geometry-coaching（家长陪学几何方案）。

- **识别特征**："怎么做 X / 帮我整理一套可照着执行的方案/流程/话术"；产出 = **方案**
  （步骤 + 资源 + 适配判断），不是事实集。
- **思考路径**：①先钉**执行者画像与约束**（方案给谁执行、ta 的基础、什么硬约束——
  geometry 案例：家长自己不会解题，方案必须不要求家长会几何，这决定一切取舍）②方案的
  验收 = **可照着执行**：步骤化、有分支（顺利怎么走/卡住怎么办）③证据双源：方法论的
  出处（理论/标准）+ 实操经验（社区/一线实践者），只引前者是书斋方案 ④资源推荐带
  适配标注（什么基础用什么资源，不排单一榜）。
- **分派结论**：类型问卡 = 方案指导（Recommended；兜底归探索性全景）；深度 = 标准；
  scout ×1 + analyst ×1 + critic ×1；topic = 方案组成块（难点诊断/流程话术/资源），
  各带 must_answer。
- **陷阱**：用事实研究的方法跑方案题（铺完文献没有方案）；方案脱离执行者能力；资源
  清单无适配标注。
- **困惑信号**：执行者画像不明（必答）；约束条件不明（时间/预算/工具/基础）。
- **澄清问法**：方案给谁执行、ta 的基础是？（必答，无推荐——用户才知道）；有什么硬
  约束？（时间/工具/预算，按题给推荐）。

## P8 · 事态跟踪/时间线

种子：drt_dsh-release-watch 后半问 + 边界题 B2（zod v3→v4 迁移生态）。

- **识别特征**："X 这段时间经历了什么 / 进展到哪了 / 生态稳了吗"；产出 = 时间线 +
  当前状态 + 趋势判断。
- **思考路径**：①时间窗先钉（起点事件或日期，决定搜索边界）②关键节点以**官方变更点**
  为骨（release notes / changelog / 公告），媒体报道为肉 ③"稳了吗/成熟了吗"是第二层
  问题（社区采用度、迁移证据），单列一问别混在时间线里 ④时效标注最重——每个节点带
  日期，"现状"标截至时刻；趋势判断显式标"判断"，与事实分开 ⑤趋势/变化结论锚在
  **指标清单**上（Indicators & Signposts：预先列出可观察信号及其阈值），不锚在
  叙事感觉上。
- **分派结论**：类型问卡 = 事态跟踪（Recommended；兜底归探索性全景）；深度 = 标准；
  scout ×1 + analyst ×1 + critic ×1；topic = 时间线主体 + 现状评估（synthesis）。
- **陷阱**：时间线凭模型记忆拼（不查 changelog——记忆会编）；现状停在旧节点（查了
  历史忘了查今天）；预测混进事实陈述。
- **困惑信号**：起点不明（从哪算起）；「稳/成熟」的判据不明。
- **澄清问法**：从哪个事件/时间算起？（按题给推荐）；「稳」的判据？（推荐：主流生态
  官方支持 + 迁移指南齐备，可改）。

## 增长协议（本库如何生长——防膨胀两道闸；外部范式依据 = drafts/self-growing-pattern-library-research.md）

1. **落痕**（run 内，lead）：立项 journal 行固定携带判型结果——命中：
   `判型命中=P<#>`；未命中：`判型未命中：<题面特征一句话>；兜底=<三分法哪类/怎么派>`。
   两者都是收割原料（未命中 → 新条目候选；命中 → 条目效用计数）。harness 零写入
   （D17）——标记只落 bundle journal，**不写本库**。
2. **离线收割**（归档时，操作侧）：`grep -rn "判型" research-workspace/
   --include=journal.md` → 两张清单：未命中候选 + 各条目命中账。
3. **晋升门槛**：候选成为新条目须满足其一——**跨 run 复现 ≥2 次**；或**单次造成真实
   成本**（HITL1 返工 / §Decisions 方向修正 / 前提级发现推翻问题前提）。一次性未命中
   不进库，留给模型能力（兜底也兜库的整洁）。新条目入库标 `（留察）`，第二次命中才
   转正；条目**只写模型不知道的增量**——每段自问"值不值 token"，常识不进条目。
4. **淘汰**：条目连续 3 次收割零命中 → 移库尾"休眠条目"节（一行理由，不删——保留
   重启证据）；条目困惑信号不灵（命中但澄清没接住）→ 修订其第 5/6 段，同晋升通道。
5. **编典生效**：按六段骨架写/改条目 → 模型可见面变更跑 l4-lite 真模型档 →
   `dev/sync-pack-workspace.mjs` 同步种子 → 随包发布。离线编典由强模型侧执行
   （Letta sleep-time 同构：记忆整理挂强档，在线执行留给任何档）。
6. **升级路径**：条目 >12 或本库 >500 行 → 拆一模式一文件 + 索引（渐进披露——启动
   只预载索引，命中才读条目全文）。
7. **修订记录**：条目新增/修订/休眠在库尾登记一行（日期 + 条目 + 一句话动因）。
