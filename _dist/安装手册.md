这是一个 **DSH 插件包（bundle）**，不是独立应用：角色 preset、方法论 skill、研究驾驶舱、抓取回退、
研究手册与 run 模板都在包内；研究产物（`drt_<slug>/`）、方法库与归档落在你指定的工作区。
产品形态 = **bundle + 自有 `deep-research` profile**：安装与启动全部走 DSH 自己的命令，
**没有 launcher、没有 scaffold、没有自定义安装器**。共 131 个条目。

## 一、前置

- DSH 满足包内 `engines.dsh`；`dsh` 在 PATH；Node 满足包内 `engines.node`。
- 首次装包/团队层需要 pnpm；团队层需要 registry 或预装缓存（完全离线见 §八）。
- 研究 run 需要模型凭据（DeepSeek API key 或账号登录）；安装/首启本身不调用模型。
- 下文用默认 `DSH_HOME`（`~/.dsh`）；自定义 home 时把 `$DSH_HOME` 换成你的路径。

## 二、安装（DSH 原生两步）

```sh
# ① 建产品 profile（仅首次；DSH 的 web 模板；破坏性，只对全新 profile 用）
dsh --profile deep-research --from-default-profile web --dump-default-config

# ② 装 bundle + 团队层（版本 = 运行中的 DSH）
dsh plugin --profile deep-research add dsh-deep-research-pack@0.3.0 \
  @deepseek-ai/dsh-experimental-agent-team-profile@<与 dsh --version 同版本>
# 或离线 tarball：
# dsh plugin --profile deep-research add file:/path/to/dsh-deep-research-pack-0.3.0.tgz
```

- **顺序不能反**：`dsh plugin` 首次初始化未知名 profile 只带 `dsh-base`，没有 Web 应用；必须先
  `--from-default-profile web`。已有 profile 不要重复 `--from-default-profile`（它会重置依赖与用户 patch）。
- **装成功的第三个状态才是功能存在**：pnpm 成功 / dependency 写入 / `dsh.profile.bundles` 含本包。
  用 `dsh --profile deep-research --dump-config` 看到 `preset-lead`、`research-client`、
  `research-content`、`research-startup`、`tool-present`、`ui-agent-team`、`session-query-sqlite`。
- **更新**：在产品内 Plugins 页装新版（跨面，默认）或重复 ②；**重启 profile** 生效。
- 同一个 bundle 也可以装进现有的 `web` profile（互操作）；但产品形态是自有 `deep-research` profile。

## 三、首启

```sh
DEEP_RESEARCH_WORKSPACE="$HOME/projects/acme" dsh --profile deep-research
# 或先不带环境变量：dsh --profile deep-research
```

- DSH 打印带 token 的 URL；浏览器打开即进产品首屏。
- 未指定工作区时，首屏起步卡有「选择项目目录」：选完研究产物写到该目录，
  下次启动会记住（浏览器提示键；换浏览器需重选）。
- 首屏 = Orca 品牌 + 产品化工作区标题（`Deep Research — <目录名>`）+ 起步卡（当前工作区 /
  三步起步 / 凭据提示 / 选择项目目录）；默认 preset = Deep Research Lead；右栏研究状态/研究配置/
  研究图谱/终稿；主界面方法库 tab。

## 四、工作区里有什么

```text
<workspace>/
  drt_<slug>/            一次调研 = 一个 run bundle（问题/证据/审查/终稿/回执）
  archive/               已交付归档
  _abandoned/            未投入但保留的停放位
  method-library.md      本工作区方法库（用户所有；首次保存时创建）
```

**没有**产品内容文件：研究手册由包内 `content/manual.md` 以 runtime context 注入；NODES/判型库是
Lead 的 skills；run 模板在包内 `content/templates/run/`。产品不写 `.gitignore`；工作区是 git 仓库且
缺研究数据忽略规则时只打印建议。

## 五、数据归属

| 事实 | 位置 | 卸载后 |
|---|---|---|
| 插件内容（preset/skill/手册/模板/驾驶舱/启动行） | profile `node_modules/dsh-deep-research-pack/` | 删 |
| 产品 profile + 团队层依赖 | `$DSH_HOME/profiles/deep-research/` | 包可移除；团队层可单删；profile 可显式删 |
| 产品设置（工作区 / 上次会话） | `$DSH_HOME/deep-research/settings.json` | 随目录显式删；无秘密 |
| 工作区提示键 | 浏览器 `localStorage['dsh.deep-research.workspaceId.v1']` | 清站点数据 |
| 方法库 | `<workspace>/method-library.md` | 保留 |
| run bundle / archive / _abandoned | `<workspace>/drt_<slug>/` 等 | 保留 |
| Workspace registration / 会话 / 凭据 | `$DSH_HOME/` | DSH 管理；本包不删 |
| 浏览器侧栏布局 | vendor localStorage | 清站点数据 |

默认共享 `$DSH_HOME`，所以 Web UI 会显示该 home 下其他 Workspace/Session；需要干净环境用
`DSH_HOME=<dir> dsh --profile deep-research`。

## 六、升级 / 回滚

```sh
# 升级（停掉正在跑的 profile 后）
dsh plugin --profile deep-research add dsh-deep-research-pack@<new>
dsh --profile deep-research
```

- 工作区数据不随包升级；方法库不被覆盖；内容（手册/模板）随包版本，新开 Lead 会话生效。
- 回滚 = 装回旧版包；DSH 必须满足旧包 `engines.dsh`，否则宿主拒绝加载。
- 安装/更新走 DSH（Plugins 页或 `dsh plugin`）；不要手写 profile manifest，不要在运行中替换
  `node_modules`。

## 七、卸载

```sh
dsh plugin --profile deep-research remove dsh-deep-research-pack
dsh plugin --profile deep-research remove @deepseek-ai/dsh-experimental-agent-team-profile  # 不需要团队层时
rm -rf "$DSH_HOME/profiles/deep-research" "$DSH_HOME/deep-research"                         # 需要删 profile/设置时
```

工作区产物（`method-library.md`、`drt_*`、`archive/`、`_abandoned/`）保留；`$DSH_HOME` 的会话/凭据是
DSH 的，本包不删。

## 八、离线 / 故障

- **pnpm 缺失**：`dsh plugin` 会 127；先安装 pnpm。
- **团队层 registry/缓存不可用**：首装失败；预装/缓存该层，或先手动
  `dsh plugin --profile deep-research add @deepseek-ai/dsh-experimental-agent-team-profile@<版本>`。
- **`engines.dsh` 不匹配**：宿主拒绝加载；升级/切换 DSH 或换匹配的包版本。
- **端口占用**：`dsh --profile deep-research -- --port <free>`。
- **没有模型 key**：Web 里用 DeepSeek 账号登录也能开始；搜索可用、抓取回退降级为本地。
- **saved Session 打开在别的工作区**：client 首屏会按 `dsh.sessions.current` 与产品提示键判断并切回；
  P1 才做确定性自动选中。
- **`dsh plugin add` 失败**：按输出末尾的 `diagnostics: .../pnpm.log` 看 pnpm 原因；profile 半装时
  先 `dsh plugin --profile deep-research remove dsh-deep-research-pack` 再重试。

## 九、诊断

```sh
"${DSH_HOME:-$HOME/.dsh}/profiles/deep-research/node_modules/.bin/dsh-deep-research-doctor" \
  --profile deep-research --install-only
```

只读检查：pack engines / profile roster（base、web-app、本包、团队层）/ 安装副本版本 / 团队层版本 /
产品设置与工作区 / 模型凭据。`--install-only` 跳过凭据；它不安装、不启动、不写 profile。

## 十、已知限制

- 浏览器提示键是设备/源级的；换浏览器或清站点数据后要重选项目目录（Workspace registration 仍在）。
- 首屏「选择项目目录」走 native chooser；browse-only 部署没有专门的目录浏览 UI（报错可见，不假装成功）。
- Host 建会话是 best-effort（webserver 无 readiness gate）；client 用首选 blank / onboarding 兜底。
- 团队机制层是 N2 experimental：上游可能改 API 或撤能力；版本必须匹配运行中的 DSH。
- 不承诺 Windows / Desktop；正式 npm 发布前 tarball 是主分发形态。
- 一个工作区一条 pack 版本线；run bundle 无自动 GC，删除是用户显式动作。
- 本包不使用 attachments / spill / KB-RAG / storage domain；会话删除与附件 GC 是 DSH 边界。
