# postmortem/ — 事故复盘

> **时态：过去**（事故已发生并复盘）。

> 事故叙事的**唯一合法层**（vendor `docs/postmortem/` 同构）。其他文档一律不写战争故事：
> `docs/` 只写当前合同，`implemented/` Note 只写决定与验证——**现场经过、误判、惊险时刻**
> 属于这里。

## 进门条件

**bug 到达了不该到达的地方**——真实用户、已合并的提交、一次交付（vendor `docs/postmortem/`
判据同款）。值得写的不是那一行修复，而是**为什么我们的流程放它过去了**。

典型：门禁假绿、静默降级、数据/凭据风险、真会话里才暴露的挂载失败、误提交。**探针抓到的
文档漂移不进这里**（那是卫生整治，归 `implemented/`）；未到达"不该到达的地方"的普通 bug
修在 `implemented/` 的"实际跑过的验证"里即可。

## 文件形状

```
notes/postmortem/yyyy-mm-dd-<主题>.md      # 日期 = 主题首提日期，与 notes/ 其余目录同构
```

正文以**三十秒摘要**起手（一到三句：什么坏了、影响了谁、根因一句话），再进五节（顺序即阅读顺序）：

1. **症状**——外部可观察到了什么（谁在什么时候发现）；
2. **为什么没早发现**——防线为什么漏（这一节比时间线重要：它是复盘的产出）；
3. **根因**——机制层的原因，不是"某人忘了"；
4. **修复**——改了什么，带了什么反证（红→还原→绿）；
5. **新增防线**——加了哪条门禁/检查，以及它为什么不会再漏（没有就写"无，理由：…"）。

节名可以按事故性质调整（现存条目用「现象 / 根因 / 修复 / 防复发」），但**第 2 节的信息必须
在场**——它是复盘的产出。

## 与 `docs/evaluation.md` 的关系

复盘产出的防线要落进评估面（L0 门禁或对应面的真检查）才算闭环；本目录记"为什么需要它"，
`evaluation.md` 记"它现在是什么"。引用**外部**复盘（如 company postmortem 0001–0003）不是
本目录的条目——外部材料登记在 [00-index §外部研究材料](../../docs/00-index.md)。

条目即目录树（不建手抄索引）：现存 [2026-09-26-roadmap-graduation-drift](2026-09-26-roadmap-graduation-drift.md)（队列指针指向已完成条目；新增防线 = 门禁 `queue-pointer-live`）、[2026-10-13-llm-stream-malformed-storm](2026-10-13-llm-stream-malformed-storm.md)（上游 CDN 丢头 brotli 撕 LLM 流 + 三小时定位过程；新增防线 = 取证工具留存 + 录制器哨兵收紧）。

未达事故门槛的教训性记录（如 l4-lite 复跑修掉的两个真 bug）留在 `implemented/` 的"实际跑过的
验证"里，不追溯迁移。
