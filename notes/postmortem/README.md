# postmortem/ — 事故复盘

> 事故叙事的**唯一合法层**（vendor `docs/postmortem/` 同构）。其他文档一律不写战争故事：
> `docs/` 只写当前合同，`implemented/` Note 只写决定与验证——**现场经过、误判、惊险时刻**
> 属于这里。

## 进门条件

一次**事故**：预期行为与实际行为偏离，且偏离值得防止复发。典型：门禁假绿、静默降级、
数据/凭据风险、真会话里才暴露的挂载失败、误提交。**探针抓到的文档漂移不进这里**（那是
卫生整治，归 `implemented/`）。

## 文件形状

```
notes/postmortem/0001-<一句话症状>.md      # 四位序号，与 vendor 惯例一致
```

正文至少含五节（顺序即阅读顺序）：

1. **症状**——外部可观察到了什么（谁在什么时候发现）；
2. **为什么没早发现**——防线为什么漏（这一节比时间线重要：它是复盘的产出）；
3. **根因**——机制层的原因，不是"某人忘了"；
4. **修复**——改了什么，带了什么反证（红→还原→绿）；
5. **新增防线**——加了哪条门禁/检查，以及它为什么不会再漏（没有就写"无，理由：…"）。

## 与 `docs/evaluation.md` 的关系

复盘产出的防线要落进评估面（L0 门禁或对应面的真检查）才算闭环；本目录记"为什么需要它"，
`evaluation.md` 记"它现在是什么"。引用**外部**复盘（如 company postmortem 0001–0003）不是
本目录的条目——外部材料登记在 [00-index §外部研究材料](../../docs/00-index.md)。
