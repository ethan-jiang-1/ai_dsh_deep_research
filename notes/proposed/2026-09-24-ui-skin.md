# RFC：UI 皮肤（品牌层：client 面 + slots 品牌）

> 状态：proposed

归宿：roadmap §搁置池「UI 皮肤」（复活条件见 §验收；**与「观察面 GUI 化」（已毕业）边界已辨析**：
品牌皮肤是表现层，观察面是开发工具层，目的不同）。

## 问题

web GUI 目前全用出厂观感；若要对外 demo / 交付给非开发用户，需要品牌化（logo、配色、
`sidebar.brand.name` 一槽）。

## 方案（草图，复活后细化）

client 面品牌包：`sidebar.brand.name` 槽 + `--dsw-*` 平台令牌定制的主题层 + 禁写字面
颜色（company 教义）。观察面 GUI 化的构建链（client-face-bootstrapping）落地后，皮肤
只是同链上的**又一个薄 client 包**，边际成本骤降——这是把它继续押后的另一理由。

## 输掉的方案

- **提前做**（run 前）：已否决——company 到 R5 才做皮肤；核心研究流优先（用户 2026-09-24
  拍板维持）；
- **混进观察面条目一起做**：否决——复活条件不同（demo 需求 vs 观察刚需），混做把
  教义口子开大。

## 验收（= 复活条件现状）

- 复活条件：首个完整 run 通过（**✓ 已满足**，drt_cn-us-cpu-gap）+ 有 demo 需求
  （**✗ 未满足——等用户点名**）；
- 现状更新（2026-09-27）：押后理由之一"构建链落地后复活成本骤降"**已成立**——client-face
  构建链当日多次实际使用（观察面卡片增删与重建），皮肤作为同链薄包的边际成本进一步降低。
  需求条件不变：仍等用户点名，便宜不构成提前做的理由；
- 复活后验收：品牌包 client-load-smoke 绿 + 皮肤零字面颜色（令牌纪律）。
