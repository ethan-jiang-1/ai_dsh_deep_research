# RFC：Note 存量体检——70 篇按三结局分类，由分布决定 class 层

> 状态：proposed

出处 = 推敲卡 [2026-10-08-sdlc-reference-absorption](../../_backlog/_done/_closed_plans/2026-10-08-sdlc-reference-absorption.md)
（§候选与取舍 第二档 C19 + §毕业门 ②"建议先做一次 notes 存量体检"）。判断材料全文住卡。

## Problem

**这是本仓既定触发器要求的动作，不是新提案。** 事实链：

1. `notes/README.md:91` 自述分裂阈值 = "超过约 50 篇"；
2. `notes/implemented/` 实有 **70 篇**——**超阈值 40%**；
3. `notes/implemented/2026-09-24-note-lifecycle-absorption.md:36-37` 已**否决** class 层，
   但**明确写下了重估入口**（"随 dsh-discipline 条目重估"）；
4. 该条目已于 2026-09-24 毕业（= `docs/discipline-map.md`）→ **重估入口已到齐**；
5. **重估本身没做**，且无门禁提醒（70 > 50 无任何机械反馈）。

所以问题不是"要不要引入 class 层"，而是"**本仓自己写的重估义务到期未履行**"。

**为什么必须先体检、不能先定分类轴**：没有 70 篇按三结局的实际分布，"采 class 层"的成本
估算全是猜（搬迁 + 链接重写 + 门禁扩面反证的规模都取决于分布）。更要紧的是，**本仓刚刚
实证过"没有实测支撑的判断依据会静默腐烂"**——本轮 C17 首版就是以猜出来的路径形状冒充
机械断言，被对抗自审打回。先定分类轴再拿 70 篇去套，是同一个错误的重演。

## 方案

分两段，**第一段是纯体检，第二段才是决定**：

**第一段（本 RFC 的实施范围）：存量体检**

按参考卷 `01 §6` 的三结局对 70 篇逐篇分类，产出**分布表**：

| 结局（参考卷 `01 §6`） | 本仓判据 |
|---|---|
| **留活跃**（leave） | 仍在指导未来工作：红证/台账引用/负知识/复活条件在身（校准 = `notes/archived/README.md` 的进门条件，vendor `dsh-archive-agent-notes` 口径：**按未来决策价值判定，不按年龄字数**） |
| **归 archived**（archive） | 不再指导未来工作；带 `> 归档：<日期>` 行 + triplet 等价物 |
| **该合并后删除**（consolidate-then-delete） | 与另一篇覆盖同一决定/机制 → 完整取代时**先吸收全部独有理由再删**（`notes/AGENTS.md` §取代检查） |

产出形态 = **体检报告进 [`_backlog/reference/`](../../_backlog/reference/README.md)**，
**不直接改 notes 树**（推敲卡规矩：卡载思考、Note 载决定；且体检结论未裁定时不得动生产线）。

报告须含：① 70 篇逐篇一行（篇名 / 结局 / 一句话理由）；② 三结局计数分布；
③ **"该合并"组的成对清单**（这是删除路径的输入，本仓 A5 gap 明写"合并后删除无程序"）；
④ 若分布显示应采某分类轴，给出**该轴下的组数与组间边界**。

**第二段（不在本 RFC 范围，由体检分布决定是否另立）**：是否落 class 层或别的分裂轴
（按 D 号 / 按子系统 / 维持）。⚠️ **不得把第二段的结论夹带进本 RFC 的实施记录**——
本仓规矩 `_backlog/README.md` §主干："下游发现的新缺口 → 回本处立新卡——绝不夹带进 Note 或变更里"。

## 输掉的方案

- **直接落 class 层**（不等体检）：阈值已破是事实，但"破了就该按参考卷的六 class 分"是
  **未验证的推断**——参考卷 `01 §2` 的六 class 闭集是为**另一个仓库的形态**设计的；
  本仓 70 篇的分布可能显示"按 D 号"或"按子系统"更贴。先分类再套轴 = 拿猜的判据当真。
- **维持现状、把阈值改高**：这是**改断言迁就实现**——`guides/60 §0` 四条硬边界之②明写
  "改断言迁就实现不是修法"。阈值是当时定的判断，不是需要维护的数字；要改也须由分布证明。
- **体检直接改 notes 树**（边体检边归档/删）：体检结论未经裁定就动生产线 = 越过"无 RFC
  不行为"。且删除路径本身尚无程序（A5 gap），边做边发明程序，会得到一套没被审过的规矩。
- **只做计数不做逐篇判定**：计数已知（70），缺的正是**逐篇的未来决策价值判定**。只数数
  等于没做。
- **顺手把 A5 gap（合并后删除的程序）也在本 RFC 定义掉**：它是体检"该合并"组的下游依赖，
  但性质是**新增程序**（改 `notes/AGENTS.md` + 可能加门禁），须独立立卡。本 RFC 只产出
  "哪些篇该合并"的**输入**。

## 验收判据

| # | 判据 | 检查方式 |
|---|---|---|
| 1 | 70 篇**逐篇**有结局判定 + 一句话理由，无遗漏 | **对账命令**：报告行数 = `ls notes/implemented/*.md \| grep -v README \| wc -l`；逐篇名对账无缺 |
| 2 | 三结局计数之和 = 总数 | **对账命令**：报告内计数相加核对（防漏项静默） |
| 3 | 判定口径**显式写出**且与 `notes/archived/README.md` 进门条件一致（按未来决策价值，非年龄字数） | 人工判据：报告须有"判据"节；抽查 3 篇判定理由能对回该口径 |
| 4 | "该合并"组给出**成对清单**（谁并谁、独有理由是什么） | 人工判据：每对须写明"完整取代还是部分取代"（`notes/AGENTS.md` §取代检查 三选一） |
| 5 | 报告住 `_backlog/reference/`，**notes 树零改动** | **机械门禁**：`git status --short notes/` 为空（体检段；若报告本身引用需要则只读） |
| 6 | 体检**不产生** class 层决定 | 人工判据：报告只给分布与可选轴，不写"因此应采用 X" |

判据 5 是**范围纪律的机械化**：本 RFC 最可能犯的错就是"体检着就把 notes 重构了"。

## 影响面

- 新增：`_backlog/reference/2026-10-08-notes-stocktake.md`（体检报告）
- **不改**：`notes/` 树任何文件、`verify.mjs`、`evaluation.md`、`tests/`
- 后续依赖（**不在本 RFC**）：① class 层或他轴的取舍卡；② A5"合并后删除的程序"卡
- 证据档：L0（`pnpm verify` + `pnpm test`——本 RFC 原则上零代码改动，L0 绿即证未破坏）
