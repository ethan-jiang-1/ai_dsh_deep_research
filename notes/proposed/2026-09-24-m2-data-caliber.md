# RFC：M2 口径纪律——"数据至上"的通用化（analyst/critic/证据契约增补）

> 状态：**proposed（待用户打磨）** · 2026-09-24 · 归宿：roadmap ▶「首个完整研究 run」
> 依据：源头仓亲读实证——真实 run 的 rerun 修订记录反复出现且被用户明示的原则：
> "数据至上（真正用数据证明，不靠纸面规格）"、每条性能数据必带口径标签（模型版本/
> 精度/并发/上下文/卡数/来源 URL）、**单源链要破**（A 档也要同口径第二源）、挖不到的
> 如实写"换渠道再攻未果"并收窄结论、dead holes 显式不投。

## 依赖与落地次序

第 ② 件（落地序见 roadmap 队列行）：与 plan-shape 无相互依赖（不同文件面：本件动
skill ×2 + evidence 模板 + 手册证据契约节），排在其后只为评审连续性。

## 问题

上述纪律在源头是**领域特定的措辞**（芯片性能），但模式通用：**关键事实类结论的质量
= 数据口径完整性 × 来源独立性**。我们的现有载体（A–D 分级、≥2 独立来源交叉验证、
反例必记）盖住了来源独立性的一半，没盖住：

1. **口径完整性**：数字/规格类摘录不带测量条件（版本/配置/时间点/原文限定语），
   "纸面规格冒充实测"无防线；
2. **单源显式性**：交叉验证要求 ≥2，但"只有一个来源、破不了"时的**单源标记**没有约定；
3. **缺口诚实**：反例搜索有"已搜反例，未见"，但一般性"已搜未得（什么渠道）"没有约定。

## 方案（三处小增补，不新建机制）

1. **evidence-entry.md 模板**：`## 原文摘录` 提示语追加——"数字/规格类摘录须带口径
   （测量条件：版本/配置/时间/原文限定语；口径不明就写'口径不明'）"。口径住正文，
   frontmatter 不加字段（最小改）。
2. **analyst `evidence-extraction` skill 增两条纪律**：
   - 关键数字 claim 只有一个来源时，解读节显式标 `单源——待破（试过的第二源渠道：…）`；
   - 搜不到的写 `已搜未得（渠道：…）`——与反例搜索的"已搜反例，未见"同构。
3. **critic `adversarial-review` skill 质量审计线增两个触发点**（不新增审查线）：
   - 关键结论的数字口径缺失（摘录裸数字、无测量条件）→ MAJOR；
   - 单源关键数字未标"单源——待破"→ MAJOR。
4. **手册证据契约节补一句**：口径要求是所有角色可判的最小契约（与 frontmatter 同级）。

## 输掉的方案

- **frontmatter 加 caliber 字段并机械断言**：否——Q6 已登记"floor 机械化缺实测证据"，
  同理：口径机械化先跑实测，第一轮只做纪律文本（教训：margin ≠ threshold，先别上 gate）。
- **critic 新开第四审查线（口径线）**：否——并入质量审计线，避免线膨胀稀释注意力。
- **要求全部摘录带口径**：否——只约束"数字/规格类"（关键事实），叙述性背景不背这包袱。

## 验收判据

- skill ×2 + 模板 ×1 + 手册 ×1 的 diff 落地；映射表 §5 教训 8 行同步（"gate 结果只信
  JSON"的数据版 = 口径纪律）+ **§3 证据身份链节**（口径并入契约描述）+ 20-roles §3
  防线 3"对抗验证"补单源显式性；
- 落地面：L0 + **L1**（skill 是 preset 内容 → preset-smoke 真挂载绿，面选择表 60 §2）+ L3；
- M2 run 实际检验：final.md 里至少出现一次"单源——待破"或"已搜未得"的如实记录
  （有就证明纪律活着；全 run 无一处单源/缺口反而可疑；此项由 run-mechanics 的 run
  汇总核销）。
