# RFC：研究类型覆盖（下一场真实 run 与多类型固化）

> 状态：proposed

归宿：roadmap §队列「研究类型覆盖」（研究/活动，**用户带题驱动**；兼 ▶ 观察面 GUI 化
的 L4 验收载体）。

## 问题

首个完整 run（drt_cn-us-cpu-gap，L4 四判据全闭）只覆盖了一种研究形态；lead persona 的
HITL1 三型（快速事实核查 / 探索性全景 / 主张验证）另两型**未经实战**。且首场的 HITL2 是
代理模拟拍板——**真实用户拍板的全流程**还没跑过。观察面 GUI 化的验收也需要一场活 run。

## 方案（草图）

用户带 1–2 个真实研究问题（建议覆盖另一型，如"主张验证"）→ `bash dev/boot-run.sh` →
**真人 HITL1/HITL2**（这次不代理模拟——观察面横幅/活标题正好承接"等你拍板"）→ run
bundle 落 `drt_<slug>/`。可选组合：观察面 GUI 化交付后同场验收（一石二鸟）；或多跑一
场小型"快速事实核查"验最薄路径。

## 输掉的方案

- **自造题目刷覆盖**：否决——真实问题才有真压力（评估面教义：真模型、真实问题）；
- **等 GUI 全好才跑**：可议——GUI 前 run 也有效（D 路仪表盘已可用），不必串行死等。

## 验收（含延期收口的观察面真人档 + 证据可靠性面）

- 证据可靠性（自 [evidence-reliability RFC](2026-09-25-evidence-reliability.md)）：bundle 含 audit.md 且关键结论佐证结构达标；


- 观察面真人档（自 [observability-gui 毕业记录](../implemented/2026-09-24-observability-gui.md) 延期）：活标题/横幅目验 + 矩阵/review 状态与 run bundle 对账；

（原验收如下）

- ≥1 场真人 HITL 全流程 run，类型 ≠ 首场类型；
- L4 四判据机器断言全绿（报告+来源清单 / 抽查回溯 / 两点纪律 / 中断恢复）；
- 顺手取证两条搁置项的重估证据：lead 综合负载（synthesizer）与质量滑坡有无（floor）。
