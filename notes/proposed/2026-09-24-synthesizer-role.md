# RFC：专职 synthesizer 角色（wave2 综合是否独立成角色）

> 状态：proposed

归宿：roadmap §搁置池「专职 synthesizer 角色」（Q4 已销账：**维持搁置**，证据在案）。

## 问题

综合（synthesis）目前归 Lead（D2：最薄队形）。若 lead 综合负载实测过高，拆出专职
synthesizer（第五角色）。

## 现状证据（2026-09-25 首个完整 run 实测，Q4 销账）

lead 独任综合**无过载**：journal 两次调度决策干净落地，标准报告 4 topic 规模全程无
瓶颈。结论 = 不拆角色，本条维持搁置（出处：
[m2-run-mechanics §实施记录](../implemented/2026-09-24-m2-run-mechanics.md)）。

## 方案（草图，仅复活后适用）

加第五角色 = 推翻 D2（角色数 4），须先登记新 D 号；person = "只综合不派工"，承接
synthesis skill；roster/镜像/门禁/测试随 `adding-a-research-role` 技能全链走。

## 输掉的方案

- **按规模阈值预备拆**（如 topic > N 即拆）：否决——无实测支撑的阈值是拍脑袋；
  维持"run 实测说话"。

## 验收（= 复活条件现状）

- 复活条件：run 实测 lead 综合负载过高（**✗ 单场 run 未见**；多 run / 大 topic 数
  run 后重估——「研究类型覆盖」条目可顺手取证）；
- 复活后验收：L1 真挂载 + L4-lite 新角色响应 + 一场含综合瓶颈场景的 run 证明分工收益。
