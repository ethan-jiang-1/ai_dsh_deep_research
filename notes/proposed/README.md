# proposed/ — 待显式评审的持久决定（将来）

> **本页是目录宪章**：只写稳定条款；条目清单 = 目录树，当前事实 = `docs/`。

## 时态与职责

将来。只放“实现前需要人显式评审”的持久决定提案。它不是一般执行工作的前置，也不是任务队列。

## 只收 / 不收

- 收：范围、真实比较过的备选、验收都能评审的持久决定 RFC。
- 不收：已授权的普通工作、问题卡/查证材料（→ [`_backlog/`](../../_backlog/README.md)）、
  已交付决定（→ [implemented/](../implemented/README.md)）、已否决（→ [rejected/](../rejected/README.md)）。

## 进门与出门

- 进门：决定需要显式评审，且当前已有可评审的范围、备选与验收。
- 出门：批准并交付后，若决定理由需长期维护 → 正文改写为已交付事实体，迁 `implemented/`
  （只改路径不算毕业）；被否决且有防复犯价值 → `rejected/`；两者皆无 → 删。
- 状态行：`> 状态：proposed | approved | superseded`（裸值；不带日期与括号）。

## 阅读契约

未批准 = 不指导实现；`approved` 仍不替代用户授权；`superseded` = 已被新提案取代——
读新篇，不按旧篇行动。

## 维护

一个决定一个 owner；新增或修订同 diff 做取代检查（[notes/README](../README.md)
§决定覆盖与取代检查）。空目录合法：没有需要评审的决定，就不建 RFC。
