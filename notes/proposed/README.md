# proposed/ — RFC 停机坪（将来时：已开工的设计）

> **时态：将来**（设计稿，尚未交付）。放**队列条目的全文 RFC**（一文件一条目：问题/方案/
> 输掉的方案/验收判据）。队列行（roadmap §队列）只有排序与指针，发现与状态分家。

## 空目录是常态，不是"没活干"

本目录只在**队列条目开工时**才有文件。**空 = 当前没有在飞的设计稿**——接下来做什么永远看
[roadmap.md §队列 ▶](../../roadmap.md)（全仓唯一"当前"指针），不是看这里。想一眼看清三个
时态各住哪里，见 [notes/README](../README.md) 的时态表。

## 规则

1. 进门条件：roadmap §队列有对应条目（verify 门禁 `proposal-scheduled` 强制）；
2. 毕业：条目收尾时 RFC 迁 `notes/implemented/`（日期+主题命名），队列行删除——**毕业 =
   正文改写**（计划体 → 已交付事实体，见 [guides/60 §4](../../docs/guides/60-dev-loop.md)）；
3. 状态行写在 RFC 自己头部，**裸值**（`> 状态：proposed` / `approved` / `superseded`，不带日期括号——
   其余 provenance 落正文），不写进 roadmap；
4. 落地次序住队列行：多条 RFC 服务同一队列条目时，次序登记在该队列行——本目录按
   文件管理，文件名不携带次序（从名字看不出先后，以队列行为准）；
5. 用户直派的任务**不必**先进这里：决定已作出并随当前变更交付 → 直接进 `implemented/`。
