# RFC：交付自审高风险扫描从 4 条扩到 11 条（治"质量不知道在哪里"的语义盲区）

> 状态：proposed

出处 = 推敲卡 [2026-10-08-sdlc-reference-absorption](../../_backlog/_done/_closed_plans/2026-10-08-sdlc-reference-absorption.md)
（§候选与取舍 第二档 C10；本 RFC 是该卡"部分采纳"毕业后的逐项立卡，判断材料全文住卡）。

## Problem

本仓对"**写出来的程序质量不知道在哪里**"的体感，机械面已有 37 道门禁把守，但**语义面**——
即"这个改动有没有引入某类经典缺陷"——只有一个薄层：开发技能 `reviewing-a-delivery`
的高风险扫描清单，**现为 4 条**。

参考卷 `06 §4` 给出 11 条。差额 7 条里，**有若干条本仓从未在任何地方检查过**——这不是
"少查了"，是**盲区**（对照推敲卡 §逐面 gap 表症状③ 的实测：`design/30` 映射表每行换成
`| x | y |` 后 `pnpm verify` 全绿 + 252 测试全过，即机械面对语义层零覆盖）。

盲区的实际代价已经出现过：本轮 C17 首版**自造了一条"看着在场、永不为真实失效而响"的断言**
（对抗自审实证：造 `src/lib/session-v5.ts` 时门禁照旧全绿）。这条缺陷机械面抓不到，
**是语义扫描该抓的**——而当时的 4 条清单里没有对应条目。

## 方案

把 `reviewing-a-delivery` 技能的高风险扫描清单从 4 条扩到 11 条，逐条对齐参考卷 `06 §4`。
新增的 7 条按参考卷原文逐条落，每条给出**本仓语境的判据句 + 一个本仓实例**（技能文本
若只抄条款名称，读者无法判断何时适用——这是技能写作的既有纪律，同族写法见
[writing-a-gate](../../.agents/skills/writing-a-gate/SKILL.md) §1"判据句 + 反例"）。

已识别的 7 条方向（落笔时按参考卷逐条核对，不凭记忆）：

| 方向 | 本仓语境 |
|---|---|
| **disposal / 资源释放** | 子进程、临时目录、端口、浏览器上下文；`scripts/AGENTS.md` 已有"释放到静默"纪律，但语义扫描未列 |
| **race** | 并发写同一 bundle / 同一 session log；watch-run 与 run 的读写交叠 |
| **denial 双路径** | 拒绝既能从策略来也能从上游来时，两条路径都要有出口（参考卷"双路径"原文） |
| **byte limit** | 输出/输入的字节上限而非字符上限（CJK 下字符数与字节数不等——本仓 CJK 语境高发） |
| **shipped entry path** | 交付件走的是**真入口路径**而非测试专用旁路（本仓已有该纪律，语义扫描未列） |
| **derived state 权威点** | 派生状态的唯一权威在哪；防止两处各自推导同一事实 |
| **静默降级 / 空集** | 扫描型逻辑扫到 0 个对象时是 fail-loud 还是静默通过（`scripts/AGENTS.md` §防空语料 的语义侧对应物） |

**范围界定**：只改技能文本（`.agents/skills/reviewing-a-delivery/SKILL.md`），不动门禁、
不动 tests。这是**刻意选择**——参考卷 `00-index.md:9-13` 第二立场明写"不宣称全部语义规则
都可自动验证"；把这 11 条包装成门禁会造出一批假牙齿。

## 输掉的方案

- **把 11 条包装成机械门禁**：语义判断无法由固定条件判真假——按
  [writing-a-gate](../../.agents/skills/writing-a-gate/SKILL.md) §1 的判据，这类规则
  "需要读语境、权衡设计" → 归属 owner 文档或技能，**别造一条会漂移的假门禁**。
  硬做会重现推敲卡 §症状③ 已实证的失败形态（门禁全绿而内容已被替换成 `| x | y |`）。
- **只在推敲卡里记着、不落技能**：卡会毕业归档，技能是**任务匹配即加载**的程序化工作记忆
  ——清单住技能才会在每次交付自审时在场。这正是"每类事实有唯一 owner"的应用：自审清单
  的 owner 是技能，不是卡。
- **一次 11 条全抄参考卷原文**：参考卷 `06 §4` 的条款句写在其自有语境（GitHub PR 流程、
  上游仓库形态）下；直抄会得到读者不知道何时适用的清单。逐条落"本仓判据句 + 实例"。
- **同时补 C11（recorded-session 义务机械化）**：C11 有独立的前置（假阳率标定，见
  [C11 RFC](2026-10-08-recorded-session-obligation.md)），且性质不同（动机械面）。
  不夹带。

## 验收判据

| # | 判据 | 检查方式 |
|---|---|---|
| 1 | 技能的高风险扫描清单实有 11 条，且逐条能对回参考卷 `06 §4` 的某一条款 | **对账命令**：`grep -c` 清单条目数 + 人工逐条比对参考卷（记录比对表） |
| 2 | 每条含**本仓判据句**（何时适用）与**至少一个本仓实例** | 人工判据：逐条走查，无实例的条目打回 |
| 3 | 不改门禁、不改 tests、不新增门禁 | **机械门禁**：`git diff --stat` 仅限技能文件（`pnpm verify` 全绿即证未破坏既有面） |
| 4 | 技能改动后仍满足技能格式门禁 | **机械门禁**：`dev-skill-format` 全绿 |
| 5 | 新增条目真的能抓到本轮已发生的实例（回放检验） | 人工判据：拿 C17 首版"装饰性断言"缺陷与 D3"否定式标题"缺陷回放，确认至少一条新扫描项会指向它们；写进实施记录 |

判据 5 是本 RFC 的**自证条款**：参考卷的立场是"agent 是一等参与者"，一份抓不到真实
已发生缺陷的清单，与 C17 首版那条"永不为真实失效而响"的断言是同一个病。

## 影响面

- 改动：`.agents/skills/reviewing-a-delivery/SKILL.md`（技能文本）
- 同步：推敲卡 §落地记录 记方向指针（卡已毕业归档，只加指针不重写正文）
- **不涉及**：`verify.mjs`、`evaluation.md`、`tests/`、pack 面、model-visible 面
  → 按 [guides/60 §2](../../docs/guides/60-dev-loop.md) 路由表，证据档 = L0（verify + tests）
