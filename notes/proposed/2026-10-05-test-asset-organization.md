# 测试资产组织收拢——词汇对照与落家序

> 状态：approved

来源推敲卡：[2026-10-05-test-asset-organization](../../_backlog/_done/_closed_plans/2026-10-05-test-asset-organization.md)（深想轮两实验与六点裁决随卡归档）。用户 2026-10-05 点名优先、ongoing goal 全程自主推进。小条目：纯文档 + 契约测试扩展。

## 问题

测试资产的组织有套路（三轴：档位 / 验收面 / 命名即层）但缺两块单一入口：传统 unit / integration / e2e 词汇与本仓形态无对照桥（[project-map](../../docs/project-map.md) 只说"不是金字塔"不给翻译，新人带金字塔脑子对不上号）；"新检查住哪"的决策规则散在四份文档，且六步序经三例回放实锤缺一步（一次性检查无家）。

## 方案

- project-map §测试怎么选 增两小节：**测试词汇对照**（金字塔词汇 ↔ 本仓形态表 + 反金字塔理由：标签回答不了"要什么前置"——本仓三轴各回答什么）与**新检查落家序**（七步修正版：契约测试 / 一次性检查 / 分级冒烟 / 真模型档 / verify 门禁 / run 门 / fixtures，各步挂登记义务与子程序指针）；
- 成本只成文一句原则（穷举矩阵不是目标，能咬中本次回归的红灯才是）；覆盖面账与真模型档经济学判**维持判断制**（触发条件登记）；
- 负知识四条（覆盖账不做 / mutation·property-based 刻意不做 / 目录即 interface 分层不现在建 / 全量照搬姊妹仓 testing.md 不做）+ 姊妹仓三条可借证据纪律（互补案例规则 / 仪器对准目标 / 新形态先入词汇表）→ 小 implemented Note（决定与负知识的家）；
- D23：契约测试先立红——扩展 [tests/navigability-contract.test.mjs](../../tests/navigability-contract.test.mjs) 断言两新节在场、词汇覆盖、链接可解析。

## 输掉的方案

### 全量照搬姊妹仓 docs/testing.md

他们有独立 testing.md 与 interface 子目录是包结构与测试量级使然；本仓 19 个回归文件、路由表已在 [guides/60 §2](../../docs/guides/60-dev-loop.md)，复制 = 双家 + 大 churn。

### 覆盖面账 / 成本曲线成文

无数值数据先成文 = 假牙齿（floor 教训同源）；清单必腐（count-free 门禁存在理由同源）。

### tests/ 内分 unit / contract 两套词表或子目录

一词一义；glob 层无差别对待是设计（都 keyless 秒级、同一条 `pnpm test`）。

## 验收

判据可检验化（D23）：能机械的先立红，实现到绿，证据进实施记录。

1. **词汇门**：project-map §测试词汇对照为唯一家，覆盖 单元 / 契约 / 集成 / 端到端 / 生产审计 五词 + 反金字塔理由。检查 = 契约测试断言（词汇在场 + 链接解析）。
2. **落家门**：七步序收拢同节，每步链 owner 文档。检查 = 契约测试断言（步骤关键词在场 + 链接解析）+ 人工过目（义务链正确性，走查记录）。
3. **成本门**：一句原则在场；经济学"维持判断制 + 触发条件"进 Note。检查 = Note 在场（note-format 门禁）。
4. **负知识门**：四条刻意不做带触发条件进 Note 输掉的方案。检查 = spot 检查。
