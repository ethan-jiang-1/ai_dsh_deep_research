# RFC：真人档验收（需要用户在场的一次 run）

> 状态：proposed

> **2026-09-27 用户指令：本条目延迟到最后**——期间由代理模拟代行"看"的职责；卡片可用性
> 审计 / 观察面走查 / 深度规模验证 run 由 ongoing goal 推进，结论记为**代理评估**，不冒充
> 真人档闭合——真人变量仍在，等用户有空时以最小成本接手。

归宿：roadmap §队列「真人档验收」（研究/活动，**等人**——必须真人拍板与目验，静默期做不了）。
承接：[研究类型覆盖](../implemented/2026-09-25-research-type-coverage.md) 毕业时转出的两项——
真人 HITL 与"要眼睛看"的界面验收。

## 问题

机器可判的部分已经在两场代理模拟 run 里闭掉（类型覆盖 / L4 四判据 / 证据可靠性 run 级），剩下的
两项**本质上需要人在场**：

1. **真人 HITL 全流程**：两场 run 的 HITL1/HITL2 都是代理模拟（用户不在场，已在两个 bundle 的
   `question.md` §Decisions 与 `journal.md` 显式标注）——"真实用户拍板的全流程"仍未跑过；
   交互卡片对**人**是否好用（选项措辞、推荐位是否被理解、自由输入是否顺手）只有真人能给结论。
2. **观察面目验**：活标题「研究状态 · ⏳ 等你拍板」与 HITL 横幅是否真的让人一眼看懂、
   矩阵/review 状态与 bundle 对账是否可信——机械断言只证"渲染在场"，证不了"看得懂"。

## 方案（草图）

用户在场，带一个真实研究问题 → `bash dev/boot-run.sh` → **真人**走完 HITL1（三问选项卡）与
HITL2（交付审阅）→ 当场记录体验（哪一问措辞含糊、推荐位是否被采纳、横幅是否及时、矩阵对不对得上）
→ bundle 落 `drt_<slug>/`。类型上三型已全部实战（快速事实核查已于第六/八场代理模拟 run 各跑
一场），真人档要验的只剩**真人这个变量**：同样的卡、同样的流程，真人来答是什么手感。

## 输掉的方案

- **把"代理模拟 + 机械断言"当作真人档闭掉**：否决——那正是本条目存在的原因；机械证据只证管道通，
  证不了"人是否用得下去"。
- **等界面再打磨一轮才请人**：可议——界面已能承接两个交互点（两场 run 已跑通选项卡的推荐位、
  分页、提交与横幅渲染），先请人跑一场拿真实反馈，比继续盲改更省。

## 验收

一次在场会话同时闭：

1. **真人 HITL**：HITL1 三问与 HITL2 审阅由**真人**作答（非代理模拟）——bundle 的
   `question.md` §Decisions 记真人选择且**不标**"代理模拟"；
2. **卡片可用性结论**：三问选项卡与 HITL2 选项对真人可用，并给出至少一条改进项或明确的
   "无需改"结论（只写"跑通了"不算——那是机械断言已经证过的）；
3. **观察面目验**：活标题/横幅在等待期确实可见且可理解；矩阵/review 状态与 run bundle 对账无误；
4. **run 本体照旧**：L4 四判据全绿 + bundle 含 `audit.md`（CRITICAL 0）。
