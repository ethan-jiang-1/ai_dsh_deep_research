### 一、证据契约收紧（判据正本 = 研究手册 §证据文件契约，analyst skill 同步）

四条全收，依据两场旧契约 run 的审计实测（16 张卡 `source_url` 未真抓、约四分之一摘录非逐字，
成因是契约没写清"摘录行里能放什么"）：

1. 引文行只放原文（标签/URL/`（同上…）`/`旁证｜…`/`说明：…` 不进 `>` 行）；

手册「机械强度诚实记账」节同步改为与工具实现一致（抓取强度 + web-only 语料覆盖率分档），

L4-lite 真模型 ALL PASS（模型可见文本变更的面选择表三道全过）。

### 三、新契约首个执行场的合规检验（本条目的核心目的）

三场对照（同一条审计、同一套判据，唯一变量 = 契约）：

| 指标 | run 1 claim_verification<br>（旧契约） | run 2 exploratory_map<br>（旧契约） | **run 3 quick_factual<br>（新契约）** |
|---|---|---|---|
| `source_url` 未真抓取 | **5** | **11** | **0** |

| final 溯源链 | 118/118 | 128/128 | 45/45 |

格式合规抽查（抽 `t1-deepseek-api-docs-pricing-zh`）：表格**逐格引**（"模型 / deepseek-flash(1) /
deepseek-v4-pro / 模型版本 …"每格一行）——第 3 条被遵守；引文行内标注（`（同上…）`/`旁证｜`/
`说明：`）**零残留**——第 1 条被遵守；`[…]` 标记 0 处使用（卡片以"每片段独立一行"实现逐段逐字，
未触发省略场景）。残留：2 条转写不符均为页内交叉引用行（覆盖率 0.00 / 0.50），15 条复合多为
带链接的表格格——量级上从"系统性"降为"零星"。

**结论：契约收紧对 agent 行为有直接、可测量的改善**——未抓取 source_url 清零、非逐字率从约
25% 降到 1.4%。且这些改善是行为性的（agent 照新契约写卡），不是工具放宽造成的。

## 第四场 run：两个新行为的执行验证（用户验收前的自验，2026-09-26）

用户要求"先帮我验收、打磨得差不多了再体验"。两处拍板改动（轻量 critic / scout 检索器对账）当时
**零执行记录**，故先各做一次行为验证，绿了才递给用户。

**(a) scout 检索器对账——定向真模型探针：通过。** 一个 scout 会话的小型方向侦察（4 条 lead）：
每条 lead 都带 `- **检索器**:` 行；`单检索器——待破` 用了 3 次且每次带精确理由（"这条 lead 的

**(b) 轻量 critic——第四场 quick_factual run（`drt_qwen-dashscope-pricing`）：通过且超预期。**

**(c) 验证中暴露并当场修掉的三处**：
1. **critic 修复轮与摘录契约打架**（真发现）：critic 要求卡片补"读法说明"，analyst 把说明写进了
   `>` 引文行——一次引入十余条契约违规（第 1 条）。已在 critic skill 轻量模式里写明"你要求卡片
   补充的说明，落点必须写明：解读节或引文块外，不进 `>` 行"（含教训原文）。
2. **audit 的 normalize 不剥 markdown 转义**：卡片把 `<` 转义成 `\<`（防被当 HTML 标签）而来源页
   无转义 → 33+ 条逐字摘录整条失配。normalize 现剥反斜杠（run 4 摘录 197/266 → 215/266）。
3. run 4 残留 30 条"不符"的构成如实记档：约半数是上述 (c1) 的注解进引文（已修 skill，下一场生效）；
