# rejected/ — 否决理由（防复犯）

> **时态：过去**（否决已发生）。本目录的读者是"差点又要做这件事的人"。

> 放**被否决的方案**，且**只保留仍能阻止一次诱人重犯的**。这不是"垃圾桶"也不是归档层——
> 它是防复犯资产：读到它的人应该是"差点又要做这件事的人"。

## 进门条件（两条都满足）

1. 方案被**否决**（用户拍板否决，或复现证据否决）；
2. 否决理由**对未来的某个决定仍有指导价值**——即：不了解它的人很可能再提一次同样的方案。

只满足第 1 条、理由已无价值的 → **不进门，直接不留**（"凑数归档"是本仓卫生铁律禁止的
净增噪声；处置序 删 > 并 > 修 > 记，见 guides/60 §4）。

## 与 `proposed/` 和搁置池的关系

一个 RFC 被否决后**不能留在 `proposed/`**（2026-09-27 起该目录只收在飞队列条目）：

- `proposed/` 的进门条件被 verify 门禁 `proposal-scheduled` 机械强制——每个文件必须在
  `queue.md` 有名，留在 `proposed/` 等于把它变成活队列条目（语义错误）；
- 搁置池（queue.md §搁置池）= **"决定不做"清单**，其条目全文就住本目录、带重启条件，
  池行直接链过来——搁置与否决同层，差别只在重启条件的强度；
- `implemented/` 语义为假（没实现）。

故设本目录。**单个决定内部的"输掉的方案"小节仍写在它所属的 Note 里**
（那是决定的组成部分）；本目录只收**独立成篇、且值得被检索到**的否决/搁置方案。

## 文件形状

```
notes/rejected/yyyy-mm-dd-<主题>.md
```

头部状态行：`> 状态：rejected—— <一句话理由>`（**裸值**：不带日期与括号，日期在文件名里），
正文至少含：

- **原方案**：当时想做什么（写到不需要上下文就能读懂）；
- **否决理由**：为什么不做（用户拍板原话要点 / 复现证据）；
- **复活条件**：什么新证据出现时应该重提（纯否决、无重启价值就写"无复活条件"）。

条目可见性：queue.md §搁置池行为带重启条件者立行（扫 queue.md 即可见）；纯否决、无重启
条件者只住本目录（目录树即清单）。
