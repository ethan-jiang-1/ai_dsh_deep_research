# rejected/ — 否决理由（防复犯）

> **本页是目录宪章**：只写稳定条款；条目清单 = 目录树。

## 时态与职责

过去。放“被否决、且理由仍能阻止一次诱人重犯”的方案。它不是垃圾桶、不是搁置池、也不是归档层；
读者是“差点又要做这件事的人”。

## 进门条件（全部满足）

1. 方案被**明确否决**（用户拍板，或复现证据否决）；
2. 不了解它的人很可能再提一次同样的方案。

只满足第 1 条 = 不留（处置序 删 > 并 > 修 > 记）。

## 只收 / 不收

- 收：独立成篇、值得被检索的否决方案（原方案 / 否决理由 / 复活条件）。
- 不收：单个决定内部的“输掉的方案”（留在该 Note）、已落地或被完整取代的否决
  （按 [notes/README](../README.md) §主动清理吸收后删除）、普通待办。

## 状态与形状

`> 状态：rejected`（裸值；一行理由可附在 `——` 后）。正文写原方案、否决理由、复活条件；
复活条件被满足并落地后，本条目不再是否决——把独有理由吸收进新 owner，然后删除。

## 阅读契约

先读复活条件：条件未出现就不要重提；条件已满足则读新 owner，不按本条行动。
