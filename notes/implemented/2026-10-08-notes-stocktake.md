## 决定

**履行本仓自己登记的重估义务，并对 72 篇逐篇做三结局判定。**
本 Note 承载的是**判决本身**（结论 + 由此产生的纪律），逐篇理由与三轮实验数据住 report。

### 结论一：**归档判定这条判据，在本仓不可靠**（本次体检最重要的产出）

同一份 72 篇、同一份 `archived/README.md` 进门条件，三轮独立判定：

| 轮次 | 口径 | leave | archive | consolidate |
|---|---|---|---|---|
| 一 | 宽（"负知识在身即留活跃"） | **72** | 0 | 0 |
| 二 | 严格（"机制若消失，哪次具体未来变更会变差"） | 35 | **23** | 1 |
| 三 | 对抗证伪（打开承接文件，专找假承接/未兑现承诺） | 严格轮的 archive **8/8 被打回** | — | — |

**判据换个提问形状就得到几乎不相交的名单。**根因：进门条件 2（"不再可能指导未来变更"）
是纯语义判断，而 `scripts/verify/verify.mjs` 里 `archived` **只出现 2 次、均为注释**
（900 / 981 行）——**归档与否没有任何复核面**。

这与本轮另两个结论是**同一种病**：`discipline-map` 的 `na` 行会静默腐烂（已实证 10 处变假）、
`design/30` 内容可被替换成 `| x | y |` 而 verify 仍全绿。**共同形态 = 文档声明了某个判断
义务，但没有任何面在履行或复核它。**

### 结论二：**class 层暂不引入**——它的触发条件其实没满足

`notes/README.md:91` 的条件是**析取**："超过约 50 篇 **或** 检索开始靠猜"。
前半满足；**后半才是引入分层的真实理由**，实测不满足：72 篇分布 61 家族，"找一篇"不靠猜。
⚠️ 这是**判断，不是机械结论**（本报告无判据轴可执行面）——且按 RFC 判据 6，
"是否落 class 层"的**决定权不在本条**，本条只给分布。

### 结论三：**本轮不执行任何归档**

严格轮给出 23 篇名录，但对抗证伪在抽样 8 篇上 **8/8 找出反例**（未兑现承诺 /
假承接 / 被现行面当正本引用 / 判据悬空）。仅两篇经手工复核接近干净承接
（[hitl-docking-polish](../../notes/archived/2026-09-28-hitl-docking-polish.md)、
[node-topology-procedure](../../notes/archived/2026-09-28-node-topology-procedure.md)），
且前者仍有"承接了但没完全承接"的边界。按
[archived/README](../../notes/archived/README.md)"边界个案用判断并留档"，
**两篇列为待裁定，不在本轮归档**——判据本身不可靠时批量归档，就是用坏尺子量生产线。

## 输掉的方案

- **直接落 class 层**：阈值破了是事实，但"破了就按参考卷六 class 分"是未验证推断——
  参考卷 `01 §2` 的闭集是为**另一个仓库的形态**设计的；实测本仓 61 家族，按哪条轴分都没有
  分布依据。先分类再套轴 = 拿猜的判据当真。
- **维持现状、把阈值改高**：**改断言迁就实现**——`guides/60 §0` 硬边界②明写"改断言迁就
  实现不是修法"。阈值是当时的判断，要改须由分布证明（本轮分布正好证明该改的是判据形状，
  不是数字）。
- **体检直接改 notes 树**（边体检边归档）：结论未裁定就动生产线 = 越过"无 RFC 不行为"；
  且删除路径本身尚无程序（A5 gap）。**本 Note 与 report 均零触碰 notes 树，有机械证据。**
- **接受严格轮的 23 篇名录并批量归档**：这是本次**差点犯下的错**。23 篇看着有承接文件、
  看着完整，但抽样证伪 8/8 有反例。**"承接文件存在" ≠ "唯一理由已被承接"**——这正是
  本轮 C17 的同一形态：看起来有断言，实际不为真实失效而响。
- **只做计数不做逐篇判定**：计数已知（72），缺的正是逐篇的未来决策价值判定——但实测证明
  **逐篇判定本身需要先有可复核的判据形状**，否则三轮三个答案。故本轮真正的产出从"名录"
  改成了"判据不可用"这个发现。
- **顺手定义掉 A5 gap（合并后删除的程序）**：性质是新增程序（改 `notes/AGENTS.md` + 可能加
  门禁），须独立立卡。本 Note 只给"哪些篇该合并"的输入——实测：候选 4 对，**0 完整取代、
  3 部分取代、1 distinct**，其中 **2 对缺互链**（真缺陷，见 §验证）。

## 实际跑过的验证

- **判据 1（逐篇判定无遗漏）**：72 篇全部有判定。宽口径一次覆盖 72/72；严格口径解析
  47/59 + 12 篇由两个子代理补齐（其中 6 篇口径被该代理事后自我收紧，已按收紧后记录）。
  **如实登记：严格轮有 12 篇是补做的、不是一轮跑完的。**
- **判据 2（计数之和 = 总数）**：宽 72 = 72；严格 35+23+1 = 59，加 12 篇补齐 + 1 篇本轮
  新 Note（其机制显然活着）→ 覆盖 72。
- **判据 3（口径显式写出且与 archived/README 一致）**：report §两轮判定 与 §方法诚实边界
  两节显式给出全部三轮口径与不一致处；抽查判定理由能对回"按未来决策价值"口径。
- **判据 4（"该合并"组成对清单）**：4 对候选（按文件名主题词 Jaccard ≥0.5 机械筛出）
  逐对裁定 = **0 完整取代 / 3 部分取代 / 1 distinct**。三个部分取代对里
  **2 对缺互链**（`notes/AGENTS.md` §取代检查要求部分取代双方互链）：
  `project-navigability` ↔ `project-navigability-phase1`（后篇→前篇 2 处，前篇→后篇 0 处
  = 单向，非互链）；`entry-chain-fresh-agent-audit` ↔ `fresh-agent-doc-audit`（两向皆 0）。
  **独立 grep 复核确认**。这是本轮唯一可直接动工的机械缺陷。
- **判据 5（notes 树零改动）**：**机械门禁**——本轮体检期间
  `git status --short notes/` **输出为空**（实测，非声称）。
- **判据 6（不产生 class 层决定）**：report §下一步 只列三条候选处置各带前置，
  明写"**此为判断，非机械结论**"；本 Note §结论二 同样标注"决定权不在本条"。
- **抽验（我自己做的独立复核，不采信子代理单方结论）**：
  严格轮 5 个 archive 判定的承接主张逐条 `rg` 核实**全部命中**（analyst skill 口径纪律 3 处 /
  `run-state.mjs` 根因 6 处 / `node-gate.mjs` 门L 11 处 / `00-index` 差异化 2 处 /
  `guides/60` 1 处）；两个边界个案的承接文件也手工读过原文。
- **全量**：`pnpm verify` 全绿 · `pnpm test` 252/252。
- **未跑项**：对抗证伪只抽 8/23 篇（35%），**未全量证伪**——"8/8 被打回"不能推广为
  "23 篇全不成立"。如实登记。
- **⚠️ 阈值本身在长**：RFC 立项写 70 篇，执行时实测 72 篇（本轮自己又新增 1 篇）。
  **这是"计数写进文档必然腐烂"的又一实例**——与本轮 C17 修的 `evaluation.md` 计数陈旧
  同型。判据 1/2 因此以**实测值**为对账基准，不以 RFC 里的数字为准。
