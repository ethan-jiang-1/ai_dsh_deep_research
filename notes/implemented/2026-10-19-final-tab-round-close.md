# 终稿页签与交付判据：一轮被真实 run 纠正的决定

> 状态：implemented

卡 = [2026-10-19-final-tab-in-sidebar](../../_backlog/_archived/settled_issues/2026-10-19-final-tab-in-sidebar.md)；
构成正本 = [docs/design/40-research-cockpit.md](../../docs/design/40-research-cockpit.md)。

## 决定

### 1. 终稿是"交付那一刻出现的一页"，不是常驻空页签

页签类型接管 `drt_<slug>/final.md` 的**文件地址**（`priority: extension` + `canOpen` 收窄到
根 / `archive/` / `_abandoned/` 三位置）。于是交付卡片、结句内联引用、Files 树点到同一份文件，
落的都是同一个页签——**地址即视图**，不另造"文件预览 vs 终稿"两个同名面。

出现时机 = 交付本身：在屏会话 journal 的**现场** `deliverables/presented` → `openResource` 一次。
回放快照刻意不触发（否则每次重载都弹）。空态就是"不存在"：右栏在交付前不占任何页签位，
承诺写在状态页签⑤（"终稿将在交付后自动出现在右栏"），兑现由那一页自己完成。

### 2. 交付判据收口到 `present`；`final.md` 在场只算"可审"

综合步（wave2）就写 run 根 `final.md`，所以"文件在场"在审查与 HITL2 之前就成立——拿它点灯就是
把未审草案当终稿。交付的机械判据是 `present`（node-gate 门②）；状态页签⑤ 的 `✅ 已交付`
与 `brief-fold` 的 `delivered` 输入都改由它见证，未交付只显示承诺行。

### 3. 自动打开的"让路"判据是**有没有草稿**，不是焦点在不在输入框

DSH 打开会话即把焦点放进 composer。把"焦点在输入框"当成"正在写"，会让自动打开在**几乎每次**
交付时被自己的保护逻辑吃掉（真 run 实测 `decision=false focused=true`）。判据改为
`draftInProgress`：输入框/文本域里有非空草稿、或 contenteditable 里有内容才让路。

### 4. 长 review.md 必须翻页读，定窗会读到中间轮次的旧判定

状态页签原先固定读 review.md 前 600 行。一版归档 run 的 review.md 有 1448 行，终局
`readiness: PASS` 在 1442 行，而第 571 行还留着当轮的 `FAIL`——UI 因此在业务摘要里把**已交付**
的 run 报成「审查修复中」。修法 = `readPage` 翻页读到 eof（40 页上限），判据仍是
`terminalReadiness`（取末位行首判定）。这是 BUG-036 的同族回归：判定在文末的文件不能吃默认窗口。

### 5. 静音条不替交付背书

`final/vN.md` **不是**交付凭证：真 run 里 v1 在 HITL2 拍板**之前**就落盘（门③ 禁的正是这个，
但模型会先写）。静音条只讲读得到的事实——`审查未过` / `vN` / `当前版`；"已交付"只由⑤ 说。
页签体读面是一张定表（`final.md` / `review.md` / `final/`），路径按三位置回退
（`finalCandidates`：`present` 记录的是交付当时的位置，bundle 归档后即失效——首个端到端断言
就撞上这个）。

## 输掉的方案

- **交付前占位的空页签**：提前许愿 + 每会话占一个页签位，且必须写一段"还没到交付"来解释自己；
- **独立页签种类（slug 参数）**：同一份终稿会有两个视图，地址身份也不再唯一；
- **塞进「研究状态」作为末尾区块**：结果面继承工具的噪音，违背"中间过程也没有"；
- **只做门、不自动开**：静默期结束时没有任何东西"到达"，把发现成本推回用户；
- **用 `final.md` 在场当交付信号**：审查前就点灯；
- **用 `final/` 版本目录当交付信号**：见决定 4，实测会被模型提前写；
- **guide 胶囊**：常驻胶囊在还没交付时是空手承诺。

## 实际跑过的验证

- **keyless**：`tests/run/final-target.test.mjs` 11 条（认领范围 / 交付折叠 / 读面定表 / 三位置回退 /
  自动打开判据 / 草稿让路）；反证三次实跑（放宽 `canOpen` → 范围红；去掉焦点保护 → 判据红；
  把"空输入框"当草稿 → 新用例红），还原后绿。
- **真浏览器**：`client-load-smoke` ALL PASS——终稿端到端（打开已交付冷会话 → ⑤ 交付门 → 页签
  标题「终稿」→ 正文与盘侧首标题对账 → 静音条元素 → 不泄漏中间过程负例）；静音条断言读**元素**
  而不是整页文本（整页会被聊天里的"当前版报告"误命中）。
- **真 run**（`drt_deepseek-r1-license`，quick_factual）：现场 `present`（turn 6）到达后，收起状态
  的右栏自动展开并出现 `Chat / Trajectory / 终稿`，静音条 `v1`。失败-修复链如实留在卡上：
  第一二次没弹（观察页未跟随该会话）→ 第三次 `decision=false focused=true`（焦点保护误伤）→
  修 `draftInProgress` 后第四次弹面成功。
- **同轮修掉验收集自身的三类缺陷**（真 run 把它们全照出来了）：整页文本匹配静音条文案会被聊天
  污染；按标题点会话会撞同名；期望侧按全量日志折、UI 按窗口折。三处都改成"读元素 + 按行键 +
  同窗口"，冒烟随后 ALL PASS。
- **L0**：`pnpm verify` 全绿 + `pnpm test` 全绿。
