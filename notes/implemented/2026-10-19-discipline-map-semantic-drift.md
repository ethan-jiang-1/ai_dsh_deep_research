# discipline-map 语义漂移：9 行裁决 + 三态值域机检 + 两笔遗留的归宿

> 状态：implemented

归宿：`docs/discipline-map.md` 全表语义重校（9 行）→ 新增 L0 门禁 `discipline-state-vocab`；
两笔遗留（`owns` 截断、语料基线漂移）各有明确归宿。卡 = [_backlog/_archived/settled_issues/2026-10-19-discipline-map-semantic-drift.md](../../_backlog/_archived/settled_issues/2026-10-19-discipline-map-semantic-drift.md)。

## 决定

### 1. 9 行失真：只有一条值得补门禁，但不是卡上猜的那条

卡上问「哪几条值得补门禁（源 3 #3 禁 commit id、源 3 #4 slop 审计）」。按 `writing-a-gate` §1
「能不能由一个固定条件判真假」逐条过，结论：

- **源 3 #3（禁 commit id 引用）不补门禁**。它**能**判定（正则扫 tracked md 的十六进制串），但
  §2 代价评估通不过：本仓 `notes/` 里合法出现哈希的地方是**历史记述**（"commit 0d9be24 修了 X"），
  这是 Note 体裁的正常写法，禁掉会误伤整类记忆。上游禁的是把**指针**写成 commit（"详见 abc1234"），
  不是禁一切哈希——而"这句是引用还是记述"要读语境。**记引入条件**（出现"详见 <hash>"式指针漂移时补）。
- **源 3 #4（slop 审计）不补门禁**。`count-free` / `doc-now-only` **已经是门禁**，台账却写"未机械化"
  ——这是事实错误，改准即可；再造一个 slop 审计 = 把已机械化的换个名字重造。
- 其余 7 行改归类 / 改措辞。

### 2. 真正该补的是「三态值域机检」（`discipline-state-vocab`）

核实过程中发现卡上遗漏的一类：表头明写「每行三态」，值域 = 照搬 / 带证据适配 / 不适用，但实测状态列
出现值域外写法（`已具备`、`前两件已具备`）。

**这不是措辞洁癖**：`已具备`（"本来就有"）与 `带证据适配`（"改造过、带证据"）维护语义不同——前者
暗示无需重校，后者要求每次换 pin 重验。把后者写成前者 = 悄悄给该行签免检，而本表价值恰恰是
"换 pin 后逐行重校"。`discipline-na-trigger` 只管「不适用」行的触发条件，管不到值域越界。

判据：**按表头定位状态列**（表头含「状态」的那列），逐数据行验首词属于闭集。不按固定列序判——
本文档并存 10 张三列状态表与 2 张两列处置表（`| vendor 文件/目录 | 本仓处置 |`），后者第二列出现
"已具备"属正常记述，按列序判会误红。

### 3. `owns` 截断：改存引用锚点，不放宽长度

46/108 条（卡上记 47，实测 46）被硬截断在 139–140 字符，末尾常是**半截词**（`thr`、`linkin`、
`heading`）。完整原文仓内不存在第二份。

**裁：不改字段长度**。放宽只保今后，救不回已丢的；而自由文本无论如何都会漂（上游改了这边不跟）。
处置 = 46 条加 `ownsTruncated: true` 标记 + 顶部 `_ownsTruncation` 说明"措辞一律读 `vendor/dsh/<source>`
原文"。**已丢的原文随此不可逆，如实登记不假装补回**。

### 4. 语料基线漂移：登记待更新 + 重议条件，本轮不重跑

`_digested/test-strategy/` 自报 `639ed01539`（v0.2.0-rc.2），本仓 pin 已 `687f282e86`（0.2.1-rc.2）。
`00-index.md` 原写"语料自报基线 = 本仓 vendor pin 同 commit"——**这句话现在是假的**，已改为如实登记。

**裁：不重跑**。`_digested/` 重跑是独立工作量（需重读两个 commit 之间的 upstream 差异），不属于本卡
"语义修正"范围。重议条件入 `triggers.md`：① 下次 pin bump 时必须重跑；② 出现「语料结论与本仓现状
冲突」的实例时立即重跑。

## 输掉的方案

- **给源 3 #3 补"禁 commit id"门禁**：会误伤 Note 里合法的历史记述（"commit abc123 修了 X"），
  而窄化到"只禁指针式引用"需要判语境——假门禁不如无门禁。
- **`owns` 字段放宽长度上限**：只保今后、救不回已丢的 46 条，且自由文本必然随上游漂。
- **本轮重跑 `_digested/`**：工作量独立于本卡，混进来会让这次 diff 的审阅面失控。
- **按固定列序（第 3 列）判状态列**：首版即如此，会把两列处置表误红。

### 教训：案例绿 ≠ 案例有效

防空语料案例首版（改表头）在门禁**部分破损时仍然绿**，因为两道守卫同时成立，案例无法归因。
发现方式不是看它绿，而是**主动把门禁改坏看它会不会咬人**。这条已写进 `gates-cases.mjs` 该函数的
注释，防止后人重新踩。
