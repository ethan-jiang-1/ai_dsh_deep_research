## 决定

**盘点结论**：原料五处——roadmap 搁置池（5 条，条件全未满足）、notes/proposed（6 RFC = 5 搁置
+ 1 队列条目真人档【等人】）、notes/research（5 篇考古全"已完成"且有落点）、包 README 延后工作
（2 条）、design/30 方法映射（无未移植行，唯一自建残留 = 证据身份链属有意保留）。

**处置（四阶段）**：

1. **A1 搜索韧性（借鉴成熟插件首战）→ seam 阻塞，记档防复踩**：dsh-web-search-pro（70★）的
   多引擎路由无法在 pack 层复刻——vendor web seam 是**单 provider 语义、明文拒绝隐藏优先级链**
   （配置 provider 不可用 → 结构化错误，不自动换；`available()` 判凭据不判健康）。vendor 现成
   exa/perplexity 两个 provider 的换源路径留给用户（需新凭据）。全文见
   [search-fallback-seam](2026-09-27-search-fallback-seam.md)。
2. **B 观察面 team_task 卡 → 前提被实测推翻，已回退**：实现 4 张卡后用 run 7 历史（29 次调用）
   重放验证 → 0 渲染；深挖发现**协调类工具根本不进对话流**（wait_agent/list_agents/send_message/
   team_task_* 在渲染流里 0 出现；研究类正常——web_fetch 56 / read 252 / edit 140），团队任务的
   观察由 ui-agent-team 任务板 + To-dos 折叠承担。回退死代码，包 README 延后行改写为实测事实
   （"team_task_* 卡留后续"永久销账）。
3. **A2 claim-evidence ledger 对比 → 维持现状**：dsh-scholar 的 claim 一等实体 + 两段式 intake +
   gate 治理与我们证据链**同构但不同架构**（Research Kernel 类型化状态 vs 文件契约）；逐项对照
   后无一值得吸收，且我们独有机械溯源审计、反例纪律、口径纪律（scholar README 均无）。吸收记录
   已入 [生态调研笔记](../research/2026-09-25-dsh-plugin-ecosystem.md)。
4. **C run 7 情报回灌 → 零新增 roadmap 条目**（逐条判定防自嗨）：报告 §9 三类缺口里——A1①
   "引用是否真支持所引句子"我们的 critic **每场都在做**（"文件存在但不支撑结论 → CRITICAL"）；
   A1② 链接腐烂我们的**摘录式设计天然免疫**（引文住在卡片里）；B 类取证阻断是研究内容的 rerun
   决策（用户拍板，非 harness 工作）；C 类是世界事实。报告的环节级结论（引用可溯国产侧更细、
   可干预性差异）反而印证了两点交互与 [来源:] 链的设计选择。

## 输掉的方案

- **复活搁置池条目凑工作量**：否决——五条复活条件全部未满足（皮肤等用户点名、synthesizer/floor
  已重估维持、keyless 快照无需求、license 等分发计划），违反自己的进池纪律。
- **把"借鉴成熟插件"当必做清单**：否决——两个钩子一阻塞（搜索路由）一维持现状（ledger），
  借鉴的价值在"遇到问题时先看别人"，不在为借鉴而借鉴。
- **从 run 7 报告硬造 roadmap 条目**：否决——逐条判定后零条成立；报告的缺口要么我们已覆盖、
  要么属 rerun 决策，硬造就是自嗨。
- **给 lead 加 bash 工具以跑审计脚本**：否决——lead 是协调者不是 shell 用户；扩工具面是设计
  决策且改变角色边界，非打磨（另：第八场实测子代理也无 shell，"派子代理跑脚本"同样不成立）。
