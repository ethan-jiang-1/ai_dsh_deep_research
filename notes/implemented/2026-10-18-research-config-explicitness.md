## 决定

1. **面板主职责 = 「看与改」**（R8）：卡片点击进详情（看它怎么干活／改它），「选」只留明确入口
   （⋯ 菜单与详情底部的「用于本次研究」、无 run 时置顶区的指路）。理由：用户原始质疑是
   「这条具体怎么干活／改了生效没有」，而按 D25「选」最终要变成一条发给 Lead 的指令，是低频动作。
2. **四区结构**：① 本次研究（本次采用 ＋ 来源 ＋ 换一条）② 内置打法（一句话 ＋ 什么时候用它 ＋
   标本位）③ 我的偏好库（写明作用域：本工作区、换工作区不带）④ 底线条（六条共同底线 ＋ 两个
   定制入口 ＋ 刷新）＋ 就地回执。详情弹窗补：执行面表（谁读它／在哪生效／管不到什么）、底线块、
   标本骨架、推荐规则说明位。
3. **判不了就说判不了**：本次研究区读 `question.md` 研究方法节，五态如实——无 run／文件缺／
   未记录（旧 run 的合法形态，**不回填**）／无法判定／已记录；**绝不回落成默认打法名**。
   读方法节须显式传足额 limit（方法节在模板第 32–40 行，默认 40 行恰好卡边界，BUG-026 同族）。
4. **回执三态各有独立信号源**：已发送 = `session/prompt` ok；Lead 已回话 = **本面板发出的那条指令
   之后**的 assistant 事件（只盯自己发的，不做整面板实时化）；已落盘 = 回读 `method-library.md`
   对账出 diff（`把「找来源」从 A 改成 B`）。**对账读不出变化就退到已回话，不冒充落地**（发现 4）。
5. **U16 落点 = research-brief skill §方法预设的「判型 → 打法映射」表**（单一正本，模型面）；
   面板的「什么时候用它」与「推荐规则说明位」是它的投影。P8 → 时间线与信号（修自家规则链的
   语义错位）；P6 本轮仍推方案比较。
6. **显示标签统一方向 = 向库格式/指令载荷靠**（找来源／怎么核实／报告怎么写／不承诺）：
   库文件与指令载荷是模型面正本，反向统一要动 skill 格式并让存量条目读不出来。
7. **领域示范独立成位，不占「内置打法」条数**：厚条目演示的是**领域包**（轴 C）该写多细，
   不是按判型推荐的方法（轴 B）——故不进方法预设表、不进内置清单；面板单列只读示范位。
   因此本轮内置打法 **5 条**（4 ＋ 时间线与信号），与 D-1「本次落地 5 条」一致。
8. **同钉面扩张**（发现 13/14/15 ＋ critic 审查行）：显示标签（client `SECTIONS` ↔ lib
   `SECTION_LABELS`）、判型→打法映射、六条共同底线、两个入口指令逐字、领域示范四字段、
   critic 的方法审查行（新增内置打法须同 diff 补一行）；冒烟的内置名单**从 skill 表解析派生**
   （删掉第四份手写副本）。

## 输掉的方案

- **面板"选为主"**（卡片常驻「用这条」）：把面板变成一次性动作面，看/改更难找（R8 的另一侧）；
- **库格式向面板靠**（改 skill 的库格式与 lib 解析前缀）：存量库条目读不出来，要迁移且伤数据；
- **把领域示范当第 6 条内置打法**：会把领域包（轴 C）伪装成方法（轴 B），还得凭空给它编一条
  判型映射；
- **只加「Lead 已回话」一态、不做落盘对账**：用户问的是"生效没有"，唯一证据是回读对账；
- **把偏好库列表改 follow 流实时**：成本明显更大；先保留手动刷新 ＋ 发送后自动重载（发现 12
  只记现象，不预设解法）；
- **冒烟内置名单继续手写字面量**：条数一变就有第四份副本。**口径订正**：它是子集检查，加内置
  并不会打红（总卡发现 14 原说法不准确）——真风险是静默走味，故改派生；
- **详情显式化块不设内滚**：实测弹窗 1129px / 视口 720px，头部关闭钮被顶到视口外点不到
  （真缺陷）——正文加 `maxHeight: 52vh` 内滚；
- **P6「证伪优先」本轮进内置**：四字段是未经模型验证的 prompt 文本，且 P5/P6/P7 共享同一条
  override——留 run 级覆写 ＋ A/B 后再定（其逐字文案留在子卡②）。

  `receipt-fold` 7 例、显示名一致性、推荐映射/六条底线/两入口同钉、领域示范同钉）；
