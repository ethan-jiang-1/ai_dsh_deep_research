# 交付自审高风险扫描 4 → 11 条（语义自审面补盲）

> 状态：implemented

出处 = SDLC Reference 全量对表推敲卡
[2026-10-08-sdlc-reference-absorption](../../_backlog/_done/_closed_plans/2026-10-08-sdlc-reference-absorption.md)
§候选与取舍 第二档 C10（治症状③"质量不知道在哪里"）。计划体全文见该卡，本 Note = 已交付事实。

## 决定

把 [`.agents/skills/reviewing-a-delivery`](../../.agents/skills/reviewing-a-delivery/SKILL.md)
的高风险语义扫描从 **4 条扩到 13 条**：参考卷 `06 §4` 的 **11 条逐条落地**（1–11），
另保留本仓特有的 2 条（生成物链 / live 文档，参考卷无直接对应）。

改动实质不是"条数变多"，是**判据形状变了**：原 4 条只有面名（"模型可见面：金标准只许重写
不许放宽"），读者无法判断**何时适用**。新 11 条每条三件套：

1. **参考卷原条款**（逐条对齐，不凭记忆）；
2. **本仓判据句**——这个面在本仓具体长什么样、查什么；
3. **本仓实例**——真实落点或既有纪律的正本链接。

分组承载可读性：接口与并发（1–2）· 边界与授权（3–4）· 模型可见面与拒绝路径（5–6）·
状态与计量（7–8）· 入口与证据（9–11）。并显式写明**这不是 checklist**：按 diff 涉及面选查，
但"涉及该面却跳过"要在报告里写明没查（承技能原有的"报告只列实际查过的面"边界）。

**为什么现在做**：机械面已有 37 道门禁，语义面只有一个薄层，而差额里若干条
（disposal / race / denial 双路径 / byte limit / derived state 权威点 / shipped entry path）
**本仓从未在任何地方检查过**——不是"少查了"，是盲区。实证代价已经出现过：本轮 C17 首版
**自造了一条"看着在场、永不为真实失效而响"的断言**，机械面抓不到，而那正是语义扫描该抓的
——当时的 4 条清单里没有对应条目。

## 输掉的方案

- **把 11 条包装成机械门禁**：语义判断无法由固定条件判真假——按
  [writing-a-gate](../../.agents/skills/writing-a-gate/SKILL.md) 的判据，这类规则需要读语境、
  权衡设计，归属 owner 文档或技能。硬做会重现推敲卡已实证的失败形态（把 `design/30`
  映射表每行换成 `| x | y |` 后 `pnpm verify` 仍全绿）。
- **只留推敲卡、不落技能**：卡已毕业归档，而技能是**任务匹配即加载**的程序化工作记忆——
  清单住技能才会在每次交付自审时在场。每类事实的唯一 owner：自审清单的 owner 是技能。
- **照抄参考卷 11 条原文**：参考卷条款写在其自有语境（GitHub PR 流程、上游仓库形态）下；
  直抄会得到读者不知道何时适用的清单，等于回到原 4 条的毛病。
- **删掉本仓特有的 2 条去凑"正好 11"**：生成物链（pack 源→overlay→镜像→种子）与
  live 文档（计数/时变状态）是本仓形态特有的高发面，参考卷没有对应条款不代表本仓不需要。
  **11 是参考卷的数，不是本仓的数**。
- **同时补 C11（recorded-session 义务机械化）**：C11 性质不同（动机械面）且有独立前置
  （假阳率标定），另立 [RFC](../proposed/2026-10-08-recorded-session-obligation.md)。不夹带。

## 实际跑过的验证

- **`dev-skill-format` 全绿**（技能格式门禁——SKILL.md 结构与 frontmatter 完整）；
- **`pnpm verify` 全绿**（37 门禁；本改动只碰技能文本，`git diff --stat` 仅一个文件，
  即证未触碰 `verify.mjs` / `tests/` / pack 面）；
- **验收判据 1（条数 + 逐条对回参考卷）**：对账命令产出——参考卷 `06 §4` 实有 11 个
  条款行（脚本枚举逐条打印核对），新清单 1–11 逐条对应，无遗漏无自造；
- **验收判据 2（每条含判据句 + 实例）**：逐条走查，11 条均含"本仓实例"且实例可解析
  （链接过 `md-links`）；
- **验收判据 5（回放检验——本 RFC 的自证条款）**：拿本轮**已实际发生**的五处缺陷回放，
  确认新清单能指向它们：

  | 本轮真实缺陷 | 被新清单哪条指向 |
  |---|---|
  | C17 首版装饰性断言（永不为真实失效而响） | 10（断言有效性 / negative control） |
  | D1 用猜的路径形状冒充机械断言（广告不存在的覆盖） | 4 + 10 + live 文档条 |
  | D3 否定式标题通过（"明说没证据"满足"要有证据节"） | 10 + 4 |
  | D2 分支零覆盖（新手写的正则路由从未被行使） | 10 + 2（race/reentry 之外的覆盖缺口） |
  | D6 计数陈旧（evaluation 声称未跑过的形态数） | live 文档条 + 7（权威点） |

  ⚠️ **这条判据是人工判据，不是机械断言**——上表映射是我读清单后的判断，没有任何门禁在跑它。
  如实登记，不假装它比实际更强。
- **未跑项**：无。本改动不触及 L1 挂载 / L2 安装 / L4 run 面，按
  [guides/60 §2](../../docs/guides/60-dev-loop.md) 路由表证据档 = L0，L0 已全绿。
