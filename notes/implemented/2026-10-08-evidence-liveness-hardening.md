# 依据层的活性硬化——`na` 理由会腐烂，证据节原来没人看

> 状态：implemented

出处 = 推敲卡 [2026-10-08-sdlc-reference-absorption](../../_backlog/_archived/settled_issues/2026-10-08-sdlc-reference-absorption.md)
（SDLC reference 全量对表 + 二轮复核）。用户 2026-10-08 指令「能修的修，能补的补」，
判断材料全文住卡（§二轮复核 + §落地记录）。

## 决定

**根因判断**：`不适用 + 一个当时为真的理由` = 永久免检区。`align-ledger` 原实现自认
"只判存在性，不判语义对错"，于是登记行一旦写下即无人再看——**依据静默腐烂比任何单条
gap 都危险**，因为它是"什么该做、什么不该做"的判断依据本身。实测 101 条源面里 **10 条
理由已变假**（archived 层已启用、snapshot 录制夹具已在场、cordis 插件代码已自写、
client UI/样式面已存在、capability seam 已自建），门禁全绿。

四项落地（均为"能机械判就机械判"，不留给记性）：

1. **`na` 活性依据——如实分两层，不假装统一机械覆盖**（`align-ledger`）：
   - `liveness` **机械缺席断言**（`absent` 路径 / `globAbsent` glob）——断言对象一旦出现
     即红；**仅限"目录/文件树缺席本身就是信号"的形态**（如 `website/`、`.github/`、
     `packages/client/`）。**11 条**。
   - `reReviewOn` **声明式人工重估触发条件**——能力面缺席（"本仓无 X 子系统/实现面"）
     写清"X 以什么形态出现时回来重估"。**13 条**。
   - **两者皆无即红**（防新增 `na` 行重新变成免检区）。
   **这一分层是被对抗自审打回来的结果，教训必须留住**：首版要求每条 `na` 都给机械断言，
   我把"免检区"**换了个写法**而非关掉——断言写的是**猜出来的路径形状**，而 reason 声称
   缺席的是**一个能力**，两者只是碰巧相关。实证：造 `src/lib/session-v5.ts`（session-format
   行的自然落点）或 `src/lib/lifecycle.ts`（agent-lifecycle 行的自然落点），首版门禁照旧
   全绿。一条 glob 无法表达"没有模块实现能力 X"——能力级腐烂仍是**语义判断**，归
   §维护规则 的三类触发事件与人工重估，不归机械面。**宁可如实说"这层是声明"，也不要
   广告一层不存在的机械覆盖。**
   同轮另防**"装饰性断言"**：断言对象不得是 vendor 源路径本身（那种断言永远成立、永不为
   真实失效而响）——门禁对 `absent === src` 或互为路径后缀的形态判"断言空转"红（自查
   抓获 7 处）。
2. **维护规则认本仓自身演进**（`discipline-map` §维护规则）：原规则只认 vendor 换 tag，
   而"本仓落点"列描述的是**我们自己**的现状 —— 这正是 10 处陈旧的结构原因。增设三类
   触发事件（新增/退役自写代码面 · 激活/清空 notes 层 · 新增对接面/生成物/夹具族）+ 一条
   "`不适用` 是当时不适用、不是豁免"的显式条款。
3. **implemented 证据节机械化**（`note-format`）：`## 实际跑过的验证` 原为
   `notes/README.md` 与 `evaluation.md` 共同宣称的骨架四节之一，却零机械把守（文档声明
   严于门禁 = 缺口）。现有断言；判定 = **恰好 h2**（`^##(?!#)`——`^##` 在 /m 下也会匹配
   `###`，二轮自审抓获的潜伏面）且标题含证据词族（验证/检查/验收/实录/记录/实证/探针/
   全绿/复验/证据），容忍历史命名变体；**否定式标题判红**——`## 未验证的猜测` / `## 无验证`
   / `## 待验证` 原先因"验证"二字在场而通过，即"明说没有证据"反而满足"要有证据节"，
   语义倒置（二轮自审抓获，已加 `VERIFY_NEGATED` 与对应 smoke 案例）。
   `## 环境状态` 仍只由 guides/60 §4 声明、无门禁（已如实登记进 notes/README 差异表）。
   **已知边界（如实登记，不假装更强）**：这是**标题在场检查**，不是**内容检查**——
   `## 验证计划（未执行）` 这类空洞标题仍会通过。机械面在此只能保证"作者被逼到必须为此
   开一节"；**证据是否真实充分仍是语义判断**，归交付自审与 L4 人工判据。收紧到须含
   "跑/测/通过"等执行动词会引入另一类假阳（合法历史命名被误杀），收益不抵代价。
4. **单页自足性终检**（`docs/AGENTS.md` §slop 清单）：等价 `dsh-trim-cot-leakage` 的
   一问——**只有 HEAD**、拿不到会话记录/PR 讨论/未提交草稿/变更史的读者，能否解析本页
   每一个引用、核实每一条主张？答不上来即 CoT 泄漏。

**同时修正的 10 处失真登记**（`alignment-ledger` + `discipline-map`）：五族 `na` 转为
`adopted`/`adapted` 或改写落点，其中 `discipline-map` 源 4 那行**在同文件内自相矛盾**
（源 2 已记 snapshot-replay 三层判据为"带证据适配"，源 9 却仍写"无 session 快照测试面"）。

## 输掉的方案

- **`na` 理由不做活性断言，改挂季度人工复审**：人被记性打败是这 10 处陈旧的成因本身，
  再加一条"记得定期看"等于把同一个失败模式再复制一遍。机械判据能覆盖的 24 条全部机械判。
- **`na` 理由用自然语言语义比对（LLM 判）**：不确定、不可复现、且把"依据是否新鲜"变成
  又一次需要信任的判断。取 `absent`/`globAbsent` 的**结构断言**——粗糙但可复现，且正好
  覆盖实际腐烂形态（"本仓无 X" 里 X 出现了）。
- **证据节强求统一命名 `## 实际跑过的验证`**：实测 70 篇里绝大多数把证据写在
  `## 验收判据` `## 阶段一实录` `## 构建打通 + 双通道全绿` 等自造标题下，且内容有效。
  逼统一命名 = 格式洁癖式假红 + 25 篇无意义重命名。改判**语义族**，只咬"根本没有证据节"。
- **`## 环境状态` 一并机械化**：44/70 篇有该节，余者多为"无环境状态可记"的纯文档变更
  （如本仓纪律表调整）——强制它会逼出填充式空话，与 slop 清单的"状态会腐烂"条款相抵。
  维持文档声明、明确登记"无门禁"，不假装它被把守。
- **`docs/AGENTS.md` 超预算时升顶**（88 > 85）：处置序是 下放 > 压缩 > 升顶，而这是新增
  一条 slop 判据、不是预算 bug —— 压缩到 85 行内解决。
- **顺手把 C19（class 层重估）也做了**：它已满足自身触发条件（70 > 50），但**重估需要
  先有一份"70 篇按三结局分类"的存量体检做输入**，否则成本估算全是猜。留给卡上 §毕业门
  裁定，不夹带。

## 实际跑过的验证

**第二轮（对抗自审后的修正）——首版有真缺陷，实证如下：**

- **D1 复现（首版最严重的缺陷，我自己的）**：`touch packages/deep-research-pack/src/lib/lifecycle.ts`
  与 `src/lib/session-v5.ts`——这两个正是 `agent-lifecycle` 行与 `session-format-status` 行
  声称缺席的**能力的自然落点**——首版门禁**照旧全绿**。结论：首版把免检区换了个写法。
  修正后这两行改用 `reReviewOn` 声明（不再声称机械覆盖），并加"两者皆无即红"把守。
- **否定式标题复现**：`## 未验证的猜测` / `## 无验证` / `## 待验证` 在首版**全部通过**
  ——"验证"二字在场即算证据节，语义倒置。加 `VERIFY_NEGATED` 后判红，且六个真实历史命名
  （`## 验收判据` / `## 阶段一实录` / `## 构建打通 + 双通道全绿` 等）仍绿。
- **`###` 潜伏面**：`^##` 在 /m 下也匹配 `### 验证`——`^##(?!#)` 收紧后 `###` 不再命中。
- **`globAbsent` 分支零覆盖**：首版三个 `align-ledger` 案例全走 `absent`，而 `matchSimpleGlob`
  是新手写的正则路由——本分支完全未被行使。补 `align-ledger-na-liveness-glob` 案例。
- **`?` 静默错配**：`matchSimpleGlob` 的转义类漏了 `?`，`a?b` 会变成正则量词（匹配 `ab`、
  反不匹配 `axb`）。已转义；**本匹配器不支持 `?` 单字符语义**，按字面量处理（刻意的保守
  选择：宁可少匹配也不静默错配），已在注释写明。
- **判据行锚定**：`gates-smoke` 原用裸 `includes('PASS  <gate>')` 判基线——若某天
  `PASS`/`FAIL` 同行名并存会读成"基线 PASS"从而**禁止**案例需要的 `expect`。改带换行边界
  的精确形态（实测 verify 每门禁恰打一行）。
- **`polish-to-plateau` 二次修正**：我新建的证据节里第三条**重述**了正文 §输掉的方案 第 4 条
  与另一条事实（两处同规 = 违反"一个事实一个家"）。改为指回 §输掉的方案 第 4 条。

**第一轮（原始落地）：**

- **`na` 活性六形态注入 → 红 → 还原 → 绿**（`align-ledger`，`gates-smoke` 案例为证）：
  ① 造 `website/AGENTS.md` 咬路径型 → `na 理由已失效——"website" 现在存在`；
  ② 造 `docs/architecture.zh.md` 咬 **glob 型** → `glob "docs/**/*.zh.md" 命中 …`；
  ③ 删 `website/AGENTS.md` 的 `liveness` → `verdict=na 必须给 liveness`；
  ④ **装饰性断言型**：把 `docs/api-gateway.md` 的断言改回它自己 → `liveness 断言空转`；
  ⑤ **能力面两依据皆缺型**：删 `session-format-status` 的 `reReviewOn` 且不给 `liveness` → 红；
  ⑥ 存量补齐后 `pnpm verify` 全绿。六者均已还原（`git diff` 确认无残留）。
- **自查抓获的自造缺陷（7 处装饰性断言）**：首版给 7 条 `na`（`agent-lifecycle` / `api-gateway` /
  `config-catalog` / `graph-atlas` / `module-graph` / `persistence-catalog` / `tool-catalog`）
  写的断言就是**那份 vendor 文档自身**——永远成立，真实失效形态不会触发。前六条已按 D1
  改入声明层。**教训：活性断言的价值全在"它会不会为真实失效而响"，不是"它是否在场"。**
- **证据节断言注入 → 红 → 还原 → 绿**：把某篇的验证节标题改为中性词 `## 附注` → 点名红。
  **首版注入只改首个匹配标题时门禁照绿**（该文另有 `## 证据` 节）——案例因此改为一次改
  全部证据词标题；这是"注入不彻底 ⇒ 案例空转"的实测教训。
- **`gates-smoke`**：`CASES` 增 6 案例，**14 案例全绿**。新增 `expect` 机制把守基线非 PASS
  时的假绿风险——`align-ledger` 因 vendor submodule 不拷入副本而基线本就非 PASS，只查
  `FAIL <gate>` 会被**别的**报因蒙混；主流程强制"基线非 PASS 的 gate 必须给 expect"，
  并**反向禁止**基线 PASS 的 gate 给多余 expect（本轮该规则再次抓到我一次多余 expect）。
- **真阳性 1 处**：`2026-09-27-polish-to-plateau` —— 机械绿证据（L0 全绿/tests 58/58/
  L1·L4-lite ALL PASS）原误置 `## 环境状态`（= `## Consequences`），而 `notes/AGENTS.md`
  的章节映射明写 验证 ↔ `## Verification`/`## Testing`。已归位新建的 `## 实际跑过的验证`。
- **首版词表 bug（自查抓获）**：`验证\b` 的 `\b` 在 CJK 后无边界可依、恒不匹配——40 篇误红
  （其中 39 篇其实有 `## 验证`）。去掉后收敛到 3 篇，再按实测标题族加宽后收敛到
  **1 篇真阳性**。同类：`gates-smoke` 注入器漏了 `m` 标志（`^##` 需 multiline）导致找不到
  目标 Note、以 exit 2 拒跑——已修。
- **全量**：`pnpm verify` 全绿（37 门禁）· `pnpm test` **252/252** · `gates-smoke` **14/14**。
- 反证与登记同步：`docs/evaluation.md` §L0 的 `note-format` 与 `align-ledger` 两行已写入
